- `webRecencyKeyOf(addedAt: Long, lastReadAt: Long): RecencyKey`

## 仕様（この振る舞いをテストで固定する）

`RecencyKey(tier: Int, value: Long)` は `Comparable` で、**比較は tier が value に優先する**（tier が違えば value を見ない）。

**`recencyKeyOf`** — 蔵書の二層キー。
- `lastReadAt > 0` のとき `RecencyKey(tier = 0, value = lastReadAt)`
- `lastReadAt == 0` のとき `RecencyKey(tier = 1, value = addedAt)`（未読が上層）

**`webRecencyKeyOf`** — Web 由来カードのキー。**tier 特権なし＝常に tier 0**。
- `lastReadAt > 0` のとき value は `lastReadAt`
- `lastReadAt == 0` のとき value は `addedAt`

**`importedNcodeKeys`** — 取込済み ncode の保存キー集合。
- 各 `BookEntity.ncode` を `Ncode(it).storageKey` へ写像する（**trim して大文字化**した形）
- `ncode` が null の本は除外する
- 結果は `Set` なので、同じ保存キーになる本が複数あれば1つに潰れる

## 必須テストケース（全部書くこと）

1. `recencyKeyOf`: `lastReadAt = 0` → tier 1 で value が `addedAt`
2. `recencyKeyOf`: `lastReadAt > 0` → tier 0 で value が `lastReadAt`
3. `webRecencyKeyOf`: `lastReadAt = 0` → tier 0 で value が `addedAt`
4. `webRecencyKeyOf`: `lastReadAt > 0` → tier 0 で value が `lastReadAt`
5. `RecencyKey` の比較: tier が異なるとき、value の大小に関わらず tier が勝つ
6. `importedNcodeKeys`: `ncode` が null の本は結果に現れない
7. `importedNcodeKeys`: 前後に空白のある ncode と小文字の ncode が、trim+大文字の保存キーへ正規化される
8. `importedNcodeKeys`: 同じ保存キーへ写像される本が2冊あるとき、結果は1要素

## 完了の定義

`./gradlew testDebugUnitTest` が緑で、上記8ケースすべてがテストとして存在すること。
