案A「はじめに」初回起動オーバーレイ型

初回起動の直後に全画面で 3 枚。もっとも作りやすく、もっとも読み飛ばされる古典型。

ADR 0032 が置いた最優先は「デフォルトUI が一目で分かること」。チュートリアルは、そこを埋め合わせる逃げ道になってはいけない。 T3・T4 を仕分けると次のようになった。

項目仕分け理由
没入中にメニューへ戻る手段が画面から消える（T4） UI で伝える
＝案D		 教示では原理的に解けない。「一度教えて覚えてもらう」設計は、時間が経てば必ず劣化する（それを観測するのが T4 の時間差テストそのもの）。 教示の回数を増やしても真因（手がかりが画面から消えること）は残る。
いまどの操作言語の面にいるか（T3 の半分） UI で伝える
＝案E		 記憶に頼らせる限り、2 週間後にまた同じ混乱が起きる。「思い出す」を要求しないのが唯一の恒久策。
横スワイプが面ごとに違う意味を持つこと（T3 の本体） どちらでもない
＝割り当ての問題		 これを説明で処理してはいけない。案C-2 の 2 列がその証拠で、説明を丁寧にするほど「面倒なアプリ」に近づく。 直すべきは文章ではなく割り当て。教示は暫定の当て木にしかならない。
「なろうで読む」は外部サイトのページそのものである 教示が要る
＝案B-3 / C-2 節5		 アプリの画面と地続きに見えるが実体が違う、という事実は絵で伝わらない（規約上ページを改変しない設計判断の帰結）。 ここは教示が正当。
縦書きの切替が［表示設定］の中にあること 教示が要る
＝案C-2 節4		 所在の教示。UI で示すなら読書クロームに縦書きトグルを常設することになるが、それはクロームの情報量を増やす別の裁定。 現状のままなら教示側で持つのが妥当。

案D と T3 の関係（比較表の補足）：D は操作言語の食い違いそのものは解かないが、実害には迂回路を与える—— メニューさえ出せれば下バーの［次章］が横書き・縦書きのどちらでも同じように効く。 つまり T4 を解くと T3 の「次の話へ行けない」だけは緩む（逆は成り立たない）。 T3 の残りは「読み進める向きが分からない」で、そちらは E か割り当ての再設計。

裁定してほしいのは 3 点
1. 没入中に取っ手（案D-1 の細い一本）を常設してよいか ─ 没入の純度をこの一本ぶん諦めるかどうかの意匠判断。
2. 案C-2 の「横書き／縦書き」2 列が、親切に見えるか面倒に見えるか ─ 面倒に見えるなら、直すのは説明ではなく操作の割り当て。
3. 案E の名札（「縦書き ←」）の矢印が、読み進める向きだと初見で伝わるか ─ 伝わらなければ名札は装飾になる。
