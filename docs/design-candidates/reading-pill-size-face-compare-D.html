案A ／ 正本へ寄せる（11px ゴシック）— 波及

Compose 側: NativeReadingScreen.kt の3箇所（復帰ヒント／続きに戻る／最上部へ）で fontSize = FontSubTitle → FontLabel(11.sp)、fontFamily = MinchoFamily → GothicFamily へ**参照するトークンを差し替えるだけ**。
他要素への波及＝ゼロ: FontSubTitle の値（13.sp）は動かさないので、同トークンを使う他の 15 箇所（本棚・作品詳細・検索・取込・目次・K スキン等）は 1px も変わらない。トークンの値を書き換える案ではないことが要点。
正本の改訂: 不要（reading-D .hint・reading-backtotop-D .toppill がいずれも 11px ゴシックで、実装がそこへ戻るだけ）。 ただし tutorial-onboarding-K.html の .pillhint（13px 明朝＝実装の逆同期記録）は 11px ゴシックへ直す必要がある。
副作用: GothicFamily は現在どの描画からも参照されていない（Typography.kt が「裁定が下りたときの器」として先に置いたもの）。 本案はその初めての実使用になる。
緊張点: タップ可能な2ピルが最小になる（高さ 33.6dp）。

案B ／ 実装へ寄せる＝正本を改訂（13px 明朝）— 波及

Compose 側: 変更なし（現行がこれ）。
正本の改訂が6ファイル: reading-D.html .hint ／ reading-vertical-scroll-D.html .hint ／ reading-gear-alt-D.html .hint-bottom ／ skins/reading-J.html .hint ／ skins/reading-M.html .hint ／ reading-backtotop-D.html .toppill。 いずれも現在 11px ゴシック（M は 11px・J/D 系も 11px）で、これを 13px 明朝へ書き換えることになる。
スキン横断の緊張: C は .float .hint 10px、P は .puck .hint 9px ピクセル体と、 各スキンが独自の字面を持つ。D だけ 13px 明朝へ上げると、「ヒントは小さいゴシック」というスキン横断の共通語彙が D で切れる。
原則との衝突: 視覚言語 D の署名は「本文＝明朝／ラベル＝ゴシック」（ADR 0005・0014、Typography.kt 冒頭）。 ピルは機能ラベルなので、明朝を正本化するのはこの署名を D 全体で緩めることを意味する。ここは人間の裁定が要る一番大きな点。
整合が取れる先: tutorial-onboarding-K.html .pillhint（13px 明朝）は改訂不要になる。

案C ／ 中間（12px ゴシック）— 波及と、そもそもの根拠

根拠: 書体は正本（ゴシック）が勝ち、寸法だけ実装寄りに 1px 上げる。 書体と寸法を別の軸として扱うのが本案の主張＝「D の署名（ラベル＝ゴシック）は譲らないが、 タップ可能な2ピル（続きに戻る／最上部へ）は純表示の復帰ヒントと違って指で押す標的なので、 11px は正本が『純表示のヒント』として較正した値であってタップ標的の較正ではない」という分離。
Compose 側: 3箇所を FontCaption(12.sp) ＋ GothicFamily へ。既存トークンなので新設不要。
正本の改訂: 案B と同じ6ファイルを 11px → 12px（書体は据え置き）。案B より改訂の中身は小さい（書体を触らない）。
緊張点: 3案の中で唯一「正本にも実装にも今は無い値」を新たに置く＝逆同期の手間が確実に発生する。 1px の差に見合うかは人間の判断。

3案に共通してぶら下がる論点（本件の裁定とは別に、決めるなら今）

① タップ標的の最小寸法: ピル高は案A 33.6 / 案C 35.2 / 案B 36.8 dp で、3案とも Material の最小タップ標的 48dp に届かない。 48dp が要るなら、字面をいくら動かしても届かないので器に最小高を持たせる（Modifier.heightIn(min = 48.dp) か 不可視の当たり判定拡張）別作業になる。復帰ヒントは純表示なので対象外。
② 字色の乖離: 実装は3ピルとも topBarIcon #4A4F58。正本は .toppill が --ink #1C1F26、 .hint が --soft #7C808B で、正本自身が2つの色を使い分けているのに実装は1色に潰している。
③ 器そのもの: 参考R のとおり、復帰ヒントの丸ピルは正本のどの読書モックにも存在しない （D・J・M・vertical-scroll・gear-alt の全てが「器なしの素テキスト」）。丸ピルの根拠は reading-backtotop-D の散文「復帰ヒント・続きに戻ると同型」と、実装を逆同期した tutorial-onboarding-K .pillhint だけ。
④ 位置: 復帰ヒントの下端は実装 96dp（Insets.ChromeHintBottom）／正本 .hint は 26px。 本比較では実装値 96 に揃えてあるが、これも未決の乖離。
⑤ 「続きに戻る」をクローム表示側に描いていない理由: 実装の位置指定は Alignment.TopCenter ＋ statusBarsIgnoringVisibility ＋ top = 8dp で、 これは上端バーが占める帯と同じ場所を指す（コード上の読み取り。実機での重なり方は未確認）。 本件は寸法・書体の裁定なので、重なりという別問題で目を曇らせないよう、チップは没入側（バーが無い状態）に置いた。
