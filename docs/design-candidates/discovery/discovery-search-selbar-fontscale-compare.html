選択中キーワード帯：見出しが fontScale 2.0 で折れる件 — 案比較

対象＝さがす→検索（DiscoverySearchScreen）で選択キーワードが1件以上のとき下部に出る帯の見出し行。
再現条件は fontScale 2.0。1.0 では折れない（golden DiscoverySearchScreen_drafted_*_2.0 に写っている症状）。
このシートの模型＝正本 .sel-bar 系の CSS を素で複製し、フォントサイズにだけ倍率 --fs を掛けた（余白・チップ内 padding は dp 相当＝非スケール）。 端末幅は正本と同じ 372px・左右 24px 余白＝可用幅 324px。「すべて解除」に padding:0 12px を足してあるのは Compose の TextButton 既定 contentPadding 12dp の再現で、案ではなく比較の前提。
正本 discovery-search-D.html が .sel-bar-ttl について規定していること（全文）:
.sel-bar-head { display: flex; align-items: center; justify-content: space-between; }
.sel-bar-ttl { font-size: 10.5px; letter-spacing: .08em; color: var(--ink-soft); }
.sel-bar-clear { font-size: 11.5px; color: var(--ai); font-weight: 500; cursor: pointer; }
マークアップは <span class="sel-bar-ttl">（＝flex アイテム）。
→ 正本は見出しに伸長指定を与えていない（flex 既定＝0 1 auto＝内容幅）。 Compose 側の Modifier.weight(1f)（＝flex:1 1 0）は正本に無い加筆で、これが「残り幅で折る」挙動の直因。
→ 折返しの許可は帯の中で .sel-chips にだけ与えられている（flex-wrap: wrap）。 .sel-bar-head は flex-wrap 未指定＝nowrap が正本の既定＝見出し行は1行構図。
→ ただし正本は fontScale 2.0 を規定していない（1.0 の1枚しか無い）。可用幅 324px に対し 2.0 では見出し＋解除が入りきらないため、 「正本どおり flex:0 1 auto に戻す」だけでは両者が縮んで解除ラベルまで潰れる＝正本は単独では答えを持ちきらない。以下は正本の1行構図をどう守るか／どこで折るかの選択。

現状Compose 現行（見出しに weight(1f)・行は縦センター）

見出しが残り幅で2行に折れ、縦センターの「すべて解除」が2行の谷間に落ちてどちらの行にも属さなく見える。
fontScale 1.0
選択中のキーワード 3件すべて解除
ほのぼの×スローライフ×悪役令嬢×
fontScale 2.0
選択中のキーワード 3件すべて解除
ほのぼの×スローライフ×悪役令嬢×
直因
Modifier.weight(1f)＝正本に無い伸長指定。折返しは行箱でなく幅で決まる（2026-09-02 の lineHeight 便は右の「すべて解除」しか触っていない＝無関係）。

案A1行を維持して末尾を省略（縮めて収める系）

weight は残したまま maxLines=1＋末尾省略。見出しの器を残り幅に閉じ込め、「すべて解除」は必ず1行目の右端に居る。
fontScale 1.0
選択中のキーワード 3件すべて解除
ほのぼの×スローライフ×悪役令嬢×
fontScale 2.0
選択中のキーワード 3件すべて解除
ほのぼの×スローライフ×悪役令嬢×
正本上の根拠
.sel-bar-head が flex-wrap 未指定＝1行構図。折返しは .sel-chips にだけ許可されている。省略記号「…」は正本の語彙内（.kw-cat-preview の「IF戦記・史実・時代小説…」）。
1.0 での退行
無し。1.0 は可用幅に収まるので省略が発動せず、レンダリング結果は現状と1px も変わらない（golden 1.0 も無変化の見込み）。
代償
2.0 で「◯件」が消える——大きい文字を要求している人ほど情報が削られる。件数はチップを数えれば分かる、で許容できるかが裁定点。
サブ案A′＝見出しを「選択中のキーワード」＋「3件」の2つに割り、前半だけ省略・件数は固定で残す（実装は Text 2本）。可読は落ちるが件数は守れる。
実装
Text に maxLines=1, overflow=TextOverflow.Ellipsis を足すだけ（1行）。

案B1入らなければ縦積み・解除は次行の左（倒す系）

見出しは自分の内容幅を主張（＝正本どおり伸長しない）。1行に収まらないときだけ「すべて解除」が次行へ落ちる。谷間は原理的に発生しない。
fontScale 1.0
選択中のキーワード 3件すべて解除
ほのぼの×スローライフ×悪役令嬢×
fontScale 2.0
選択中のキーワード 3件すべて解除
ほのぼの×スローライフ×悪役令嬢×
正本上の根拠
①見出しに伸長を与えないのは正本 .sel-bar-ttl の既定 flex:0 1 auto そのもの＝weight(1f) という加筆の撤回。②「入らなければ折り返す」は同じ帯の .sel-chips（flex-wrap: wrap）が既に持つ流儀＝新規意匠ではない。
1.0 での退行
無し。1.0 は 1行に収まるので space-between のまま＝正本の見た目と同一。折返しは 2.0 でしか発動しない。
代償
2.0 で解除ボタンが左端に来る（右端＝破棄操作の定位置、という慣習からは外れる）。
これは FlowRow(horizontalArrangement = SpaceBetween) という最も素直な実装がそのまま出す絵（2行目に1個だけ載ると SpaceBetween は左寄せ）。文字が左余白から 12px 内側に入って見えるのは TextButton の contentPadding で、Modifier.offset(x = (-12).dp) で余白に揃えることは可能（要・追加の一手）。
実装
見出しから weight を外し、Row を FlowRow(horizontalArrangement = Arrangement.SpaceBetween, verticalArrangement = spacedBy(S4)) へ。

案B2入らなければ縦積み・解除は常に右端（倒す系）

B1 と同じ挙動で、次行へ落ちた「すべて解除」を右端に置く。1.0 の見え方は B1・正本と同一。
fontScale 1.0
選択中のキーワード 3件すべて解除
ほのぼの×スローライフ×悪役令嬢×
fontScale 2.0
選択中のキーワード 3件すべて解除
ほのぼの×スローライフ×悪役令嬢×
正本上の根拠
B1 と同じ。加えて「解除は行の右端」という justify-content: space-between の含意を、折返し後も保つ読み。
1.0 での退行
無し（B1 と同一の描画）。
代償
実装が B1 より重い。FlowRow の arrangement は行ごとに切り替えられないので、末行だけ右寄せにするには 見出しの onTextLayout で溢れを検知して Row↔Column を切り替えるか、SubcomposeLayout で測る必要がある（＝状態を1つ持つ）。
なお「fontScale >= 1.5 なら Column」という閾値分岐でも同じ絵にはなるが、幅・文言・翻訳で条件が変わると破れる（折返しは幅で決まるため）。
