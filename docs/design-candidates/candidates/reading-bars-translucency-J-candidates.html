ヘアラインは触っていない（＝この頁で振っていない軸）

「境界が読めない」には ヘアラインを濃くするという別解もあるが、D/K の裁定でそれは 次の別裁定として意図的に外してある（同時に2軸動かすと効いた方が分からない）。J でも同じ規律を守り、 --bar-line（ライト #E7ECE4／セピア #E0D3B0／ダーク #22301F）は全案で現行のまま。

ナビ／ステータス帯は不透明（要件・図は D/K の裁定頁に在る）

実装形は containerColor に α を掛ける形ではなく、面＝半透明／システム帯＝不透明の2段塗り （Modifier.readingChromeBarSurface）。この器は D/K の裁定で既に結線済みでスキン非依存なので、 J は SkinJ.readingBarSurfaceAlpha の override 1行だけで乗る。J 固有の実装は増えない。

バーラベルの可読は J では制約にならない（実装はラベルも --ink）

正本の .bottombar .bl は --soft だが、実装（ReadingChrome.kt の BottomBarButton）はアイコンとラベルで tint を共有＝ラベルも topBarIcon（=--ink）。 案B の最悪面（本文が真下を通った箇所）でのコントラストは ライト 13.9:1 ／ セピア 9.5:1 ／ ダーク 12.0:1、 金の「表示設定」ラベルでも 6.4 / 5.7 / 9.0:1 で、いずれも 4.5:1 を大きく上回る。 D/K の裁定で「9.5px のラベルが本文の影を踏む」を案C 却下の根拠にしたが、J ではその軸が効かない （このモックの --soft 表示は実装より厳しい側＝差の是非は本件の裁定対象外）。

この裁定が触らないもの

「最上部へ」ピルは地が --bar×α.78 で、バーの上ではなく本文の上に浮く別の器 （2026-09-04 裁定・reading-backtotop-D 案D）＝本件で値は動かない。 遊び心J2『敷居光』は z-index がバーより上＝バーの α に関わらず同じに見える。 没入中は上下バーごと退避＝本件は「クローム表示中の定常の地」だけに効く（J は没入が既定）。 出没はスライド（translationY × collapsedFraction）のままで、定常の透過を入れても フェードへ戻す話ではない。

C・M・P は対象外（なぜ J だけを別に裁定するのか）

C は上下バー面を素地と別面に取る思想＝同値問題がそもそも起きない。 M/P は navBackground が焼き込み済み不透明トークン（M は rgba(14,21,48,.82)、 P は plastic 面を焼き込み）＝使用側でさらに α を掛けると二重に薄まる。 だから SkinTokens.readingBarSurfaceAlpha の既定は 1f のままで、裁定の付いたスキンだけが override する。
