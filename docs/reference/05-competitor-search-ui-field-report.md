# 05 競合5アプリの「作品検索UI」実機目視レポート

> 実施: 2026-07-07 / 実機 PGEM10（1440x3168, Android）に5アプリを導入し、adb経由で実際に検索を操作・撮影して確認。
> ユーザー実施の実機調査をリポジトリへ収蔵したもの（2026-07-07）。本文中の `_screenshots/`・`_recon/` は
> 調査時のローカル作業ディレクトリでありリポジトリには含まれない（画像・デコンパイル成果物は非収蔵）。
> 検索ワードは全アプリ共通で「転生」。静的解析（デコンパイル）による事前分類は `04-competitor-app-features.md` 系の調査を参照。
> 本書はその**実機裏取り＋静的解析では見えなかった部分の確定**が目的。

## TL;DR

1. **静的解析で復元不可だった「なろう公式」の検索UIが実機で全容判明**（本書の最大の成果）。モーダル1枚のフォーム型で、**ジャンル絞り込みが無い**という意外な割り切り。表示順はなろうAPIの order とほぼ1:1の13種。
2. **カクヨムの検索は確かにWebView委譲**（uiautomator でWebView 1ノードを確認）だが、中身のWebがアプリライクに完成されており、**5アプリ中もっともリッチな検索UX**（5軸タブ・キュレーションタグ・保存検索的履歴）。「Web委譲=手抜き」ではなかった。
3. 検索フォームの実質標準は「**ワード＋除外ワード＋種別＋並び順**」。4アプリ全てで**除外ワードが一等地**にある。
4. 結果画面の定石は「**件数表示＋結果画面に常駐するソート切替**」（公式=下部フローティングバー、なろうブック=上部ドロップダウン）。
5. 検索履歴を持つアプリは**ワードではなく条件セット丸ごと**を保存する（なろうリーダ=ピン留め付き、カクヨム=新着バッジ付き=実質の保存検索）。

## A. なろう公式（com.syosetu.android 1.6.5）— 静的解析不可→実機で確定

難読化＋pairip＋Composeで静的解析では「検索」リテラル0件だったが、実機では明快なフォーム型検索を持つ。

**エントリ**: 下タブは「ホーム/ランキング/ブックマーク」の3枚で検索はタブに置かず、上部バーの虫眼鏡から**モーダル「作品検索」**を開く（`syosetu_01_home.png` / `syosetu_02_search.png`）。

**フォーム構成**（`syosetu_02_search.png`）:
- 検索ワード / 除外ワード（テキスト2欄）
- 作品種別: 「短編」「連載」チェック＋（全て/連載中/完結）ラジオ
- 表示順: Spinner＋昇順/降順の2ドロップダウン
- 大きな「検索する」ボタン。**ジャンル・タグ・文字数などの絞り込みは一切無い**

**表示順は13種**（`syosetu_03/04_order_dropdown*.png`）: 最新掲載日 / 初回掲載日 / 週間ユニークアクセス数 / ブックマーク登録数 / レビュー数 / 評価者数 / 総合・日間・週間・月間・四半期・年間ポイント数 / 文字数。なろうAPIの `order=` パラメータとほぼ1:1で、**公式アプリも公開APIと同じ語彙で作られている**ことが分かる。

**結果画面**（`syosetu_06_results.png`）:
- ヘッダ下に条件要約「「転生」を含む作品」＋「条件を変更」リンク、**「1〜50件を表示（全119,899件）」**
- カード: タイトル/作者・連載状態/話数・文字数・**読了目安時間**（例: 55,519文字→2時間19分）/ジャンル・総合pt/更新日/あらすじ4行/**タグchips折り返し表示**
- **画面下部にフローティングのソートバー**（最新掲載日⇅/降順⇅）— 結果を見ながらその場で並べ替え
- ×で閉じるとフォームに戻る（条件変更→再検索のループが1タップ）

**検索履歴は無い**。上部バーの時計アイコンは「閲覧履歴」（ブックマーク済み/非ブックマーク済みの2タブ、`syosetu_09_history.png`）。予備マトリクスの「検索＋履歴」は閲覧履歴の誤認だったと確定。

**ランキング画面**（`syosetu_10_ranking.png`）も同じ設計言語: ジャンル横スクロールタブ＋下部フローティングバー（日間/すべて/**表示多め**=表示密度切替）。ジャンル絞り込みは検索ではなくランキング側に置く、という役割分担。

## B. カクヨム公式（jp.kadokawa.el.kakuyomu 6.12.0）— WebView委譲の実物

静的解析どおり `FindWorksFragment` はネイティブのツールバー（←＋タイトル）だけ持ち、本体は kakuyomu.jp のWebページ1枚（uiautomator dump で WebView ノード1個を確認）。ただし中身は5アプリ中最もリッチ。

**「小説を探す」トップ**（`kakuyomu_02_search.png`）:
- スコープ切替（「小説⌄」）付き検索ボックス、プレースホルダ「小説名・紹介文・タグ」
- 「探す」カード5枚: **ジャンル / キャラ / ストーリー / その他 / 詳細条件**
- 「最近の検索」: 日付グループ＋条件の組（例「サポーター限定 / 週間ランキング」）＋**「新着10件以上」バッジ**＋個別削除

**絞り込みはボトムシート**（`kakuyomu_03_advanced.png`〜`kakuyomu_05_chara.png`）。上記5軸がタブになっており:
- **詳細条件**: アコーディオン8項目（除外ワード/連載状態/★の数/小説の長さ/除外条件/抽出条件/公開日/更新日）
- **ジャンル**: 複数選択チェックリスト（異世界F/現代F/SF/恋愛/ラブコメ/現代ドラマ/ホラー/ミステリー/エッセイ・NF/歴史・時代・伝奇…）
- **キャラ**: **キュレーション済みタグの＋chip**を「地位・称号」（冒険者/公女/奴隷/勇者/魔王/聖女/悪役令嬢/騎士…）「職業」（警察/軍人/商人/探偵/家庭教師…）などカテゴリ別に提示。タグを知らなくても検索条件が組める
- シート下部に常に「< 検索する >」（左右矢印でタブ移動）

**結果画面**（`kakuyomu_07_results.png`）:
- 「検索/検索履歴」タブ、「1〜20件を表示 全43,010件」
- **適用中条件のchips**（「転生 ×」＋「＋」で条件追加）＋「条件を変更」ボタン
- カードは**読者レビューの引用文**を先頭に出す独特の構成
- 下部フローティング「⇅週間ランキング / 表示多め」— **デフォルトの並びが関連度でなく人気順**
- **検索履歴タブ**（`kakuyomu_08_history.png`）: 時刻付き条件セット＋新着バッジ＋編集 — 実質「保存した検索条件に新着を知らせる」保存検索機能

## C. なろうリーダ（com.tscsoft.naroureader 1.36.17）— 静的解析と1:1で一致

`dialog_novel_search.xml`＋`SearchCondition.java` の静的解析結果が実機でそのまま確認できた。「検索=ライブラリへ取り込む手段」という思想が一番明確。

- **エントリ**: 空状態オンボーディングに「ランキングからインポート / **検索してインポート** / 小説を読もう！からインポート」の3導線（`tscsoft_02_main.png`）
- **「検索条件」ダイアログ**（`tscsoft_03_search_form.png`）: サイト切替（小説を読もう！⌄ = R18サイト対応）/検索ワード/除外ワード/**適用対象4チェック（タイトル・あらすじ・キーワード・作者）**/ジャンル（単一Spinner、`tscsoft_04_genre.png` — なろうAPI genre準拠の〔大ジャンル〕付き表記）/小説タイプ/並び替え順序。再表示時は前回条件を保持
- **検索履歴**（`tscsoft_07/08_history*.png`）: ダイアログ右上の時計→**条件一式のセット**として一覧表示、⋮メニューに**ピン留め/削除**
- **結果画面**（`tscsoft_05_results.png`）: 番号付き高密度リスト。各行に**チェックボックス**があり、複数選択して一括インポートする前提。タイトル/作者/あらすじ2行/ジャンル/pt/連載中・全N部/更新日時

## D. なろうブック（com.zyunto.naroreader 4.10.0）— 検索を第一級タブに置く最小構成

- **下タブ「ブックマーク/検索/ランキング」**で、5アプリ中唯一検索を常設タブにしている（`zyunto_01_home.png`）
- **検索タブ**（`zyunto_02_search.png`）: 検索ワード（**「URL可」**= ncode/URL直貼りで作品直行）/除外ワード/小説タイプ⌄/ジャンル選択（**複数選択チェックダイアログ**、`zyunto_03_genre.png`）/「この条件で検索」— 並び順はフォームに置かない
- **結果画面**（`zyunto_05_results.png`, `zyunto_06_sort.png`): 上部に常設ソートドロップダウン12種（新着更新順/新着投稿順/ブックマーク数/総合〜年間pt/週間ユニークユーザ/**更新が古い順**=昇降トグルの代わりに項目化）。カードの左に**ブックマーク直登録アイコン**（結果から1タップで登録）。タグはchipsでなくテキスト羅列
- ブックマークタブ側にもローカル絞り込み（タイトル・作者名）＋並び替えがあり、「オンライン検索」と「手元の絞り込み」を別画面で分けている

## E. Web小説リーダー（com.sampleb3.novel 2.638）— 検索UIを持たない

初回起動の「ご案内」と＋ボタンのダイアログで実機確定（`sampleb3_01_home.png`, `sampleb3_04_plus3.png`）: 作品登録は「①ブラウザの共有機能で連携 ②目次ページURLを直接入力」の2方式のみ。作品を探す行為はブラウザ（サイト側の検索）に完全委譲。静的解析の分類どおり検索UIの参考外。

## 自作 novel-reader への示唆（検索UI設計の要点）

前提: なろうAPIはメタデータ専用（`03`参照）。ここでの「検索」はディスカバリUIの話。

1. **全体形はフォーム型が本命、モダンにするならカクヨム型**。なろうAPIはパラメータ検索なので「フォーム→結果」の2画面構成（公式/tscsoft/zyunto）が素直。1画面に収めたければカクヨムの「検索ボックス＋軸別タブのボトムシート」が最良の手本（ただしあれはWeb実装なので、Composeで作るなら ModalBottomSheet＋タブ）。
2. **最低ライン**: ワード / **除外ワード** / 種別（短編・連載・完結）/ 並び順。除外ワードは4アプリ全てが一等地に置く「なろう検索の常識」— 省略しない。
3. **並び順はAPIの order をそのまま日本語化**（公式が13種で実証）。UIは「Spinner＋昇降」（公式）か「昇降を項目に畳む」（zyunto）の2流派。
4. **結果画面に (a) 全件数＋ページ位置、(b) 常駐ソート切替、(c) 条件変更への1タップ復帰**の3点セット。公式の下部フローティングバーが最も洗練。
5. **ジャンルは複数選択**（zyunto/カクヨム方式）。なろうAPIは genre のハイフン連結指定が可能なので、単一Spinner（tscsoft）にする理由はない。適用対象4チェック（tscsoft）も `of` ではなく検索対象フィールド指定として API がサポート（title/ex/keyword/wname）するので実装可能。
6. **履歴は「条件セット」単位で保存**し、＋αを1つ選ぶ: tscsoft流「ピン留め」か、カクヨム流「新着バッジ」（保存検索化。定期チェックと組めば更新通知の入口にもなる）。ワード履歴だけの実装は競合に無い。
7. **カクヨムのキュレーションタグ**（キャラ/ストーリー軸のchip提示）は「何と検索すればいいか分からない」への回答で、なろうのキーワード検索にもそのまま適用できる差別化候補。
8. **小ネタ**: 公式の「読了目安時間」は文字数から計算するだけで実装でき、PDF読書アプリの文脈とも相性がよい。zyuntoの「URL/ncode直貼り」も取込型アプリなら実用度が高い。
9. **tscsoftの「検索結果を複数選択→一括インポート」**は、「検索=自分のライブラリに取り込む手段」という自作アプリの目的に最も近い操作モデル。結果カードの直接ブックマーク（zyunto）と合わせて、「結果画面から次のアクションまでを1タップにする」ことを設計原則にするとよい。

## 付録: 実機確認の再現メモ

- 5アプリのうち zyunto のみ未インストールだったため `apks/com.zyunto.naroreader/` の原本から `adb install-multiple`（base＋arm64＋ja＋xxhdpi）で導入。
- 日本語入力は端末内の ADBKeyboard（`com.android.adbkeyboard/.AdbIME`）へ `ime set` で切替え、`am broadcast -a ADB_INPUT_B64 --es msg <base64(UTF-8)>` で送信。終了後 Gboard に復元済み。
- WebView判定は `uiautomator dump` のノードクラスで確認（カクヨムのみWebView）。
- なろう公式は事前にユーザーがログイン済みの状態で確認。
