# read-only 委譲の digest 契約（Phase 1）

ADR 0031 決定4 の Phase 1＝「agy には読み取り専用の調査をさせ、digest だけ持ち帰る」を成立させるための返り値契約。
**監督が機械照合できない digest は受け取らない**、が唯一の主旨。

## なぜ形式を縛るか（2026-08-10 実測）

agy の Read 精度は**ファイルサイズと問いの形で非対称**だった。

| 条件 | 結果 |
|---|---|
| 22KB のファイルから全数列挙 | 正解 |
| 39KB のファイルで計数 | 正解 |
| **111KB のファイルから自由列挙** | **実在9個に加え、存在しない2個を捏造**（適合率 82%） |
| 名指しした対象の存在確認 | 正答 |

つまり**自由列挙は大ファイルで壊れ、名指し確認は任せられる**。
能力検査で唯一機能した検証形も「規約の指定節を行番号つきで逐語引用させ、grep で照合する」だった（完全一致）。
契約はこの2つの実測から逆算して作る。

## 契約

### 1. 行番号のない主張は無効

各事実は1行1件で、末尾に出典を付ける。

```
<主張> — <path>:<line>
<主張> — <path>:<start>-<end>
```

監督は全行から `path:line` を抜き、実際にその行を読んで突き合わせる。
**出典のない行は照合できない＝読まずに捨てる**（議論しない。捨てるだけ）。

### 2. 引用は逐語。要約した引用は規約違反

要約は grep に掛からない＝照合不能。原文が長いなら行範囲だけ示し、本文は引かない。

### 3. 自由列挙は 40KB 未満のファイルにだけ許す

それ以上のファイルでは、監督が候補を名指しし、agy は**各候補の有無だけ**を答える形へ分解する
（実測で壊れたのは前者、通ったのは後者）。「他にもあるか」を大ファイルへ投げると捏造が返る。

### 4. 「無い」の主張には再現可能な検索式を添える

```
X は実装されていない — `grep -rn 'X' src/` が0件
```

不在は行番号で示せないので、検索式そのものを出典として扱う。監督は同じ式を回して0件を確認する。

### 5. 捏造が1件でも混じったら digest 全体を破棄する

部分採用はしない。捏造は「材料が足りず埋めに行った」信号であり、
**同じ機序で生成された他の主張も同じ確率で汚染されている**と考えるべきだから。
一致率で按分すると、汚染された digest を「82% は正しい」と言って通してしまう。

### 6. 本文はファイルへ、digest にはパスと要点だけ

生出力の貼り戻しと、agy が触ったファイルの再読み込みは禁止（ADR 0031 決定2-c）。
これを破ると監督のコンテキストが再膨張し、委譲した意味が消える——
コスト主体は生成ではなく `cache_read` なので、**digest が太った時点で節約は消える**（判断材料6）。

## 監督側の受け入れ手順

1. digest から `path:line` を全数抽出する
2. 各行を読み、主張と一致するか確認する
3. 1件でも外れたら**全体を破棄**し、問いを「名指し確認」形式へ分解して投げ直す
4. 通ったものだけを事実として扱う
