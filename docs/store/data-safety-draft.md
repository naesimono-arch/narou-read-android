## 0. 前提整理（フォームの用語定義と本アプリの事実）

公式ヘルプの定義（2026-07-29 確認）:

- **「収集」＝アプリがユーザーのデバイス外へデータを送信すること**。端末内でのみ処理されるデータは収集に当たらない。
- **エフェメラル処理の除外**: 「メモリにのみ保存され、特定のリクエストにリアルタイムで対応するために必要な間だけ保持され、他の目的には使用されない」データは収集として開示不要。
- **WebView**: アプリが WebView から収集するデータは申告対象。ただし**ユーザーが WebView でオープンウェブを閲覧すること自体は申告不要**。

本アプリの事実（コード裏取り 2026-07-29・詳細はプライバシーポリシー下書き §2-3）:

| 通信 | 内容 | フォーム上の整理 |
|---|---|---|
| なろう公式 API（検索・ランキング・新着チェック） | 検索条件・Nコードを送り作品情報を受ける。開発者側での保存先なし（自前サーバー不存在） | ユーザー要求の即時処理＝エフェメラル。収集に該当せず |
| なろう公式サイト表示（WebView / 外部ブラウザ） | 読書用 WebView は無加工・JS注入ゼロ（ADR 0012）。PDF 取込画面のみ、DL 完了のため当該 URL の Cookie/UA を**同一サイトへの DL 要求へその場で転送**（他送信先なし・保存なし＝`PdfImportViewModel`） | オープンウェブ閲覧＝申告不要（ヘルプ明記）。Cookie 転送は同一サイト・即時処理＝エフェメラル。アプリは WebView からデータを収集しない |
| カクヨム・暁の作品取得（ユーザー明示操作）／**同サイトへの新着話チェック**（有効時のみ1日1回） | 作品ページ取得→本文は端末内保存のみ（ADR 0024）。新着チェックは取り込み元の作品ページの目次を照会する（`NewEpisodeCheckWorker`）＝**なろうAPIだけではない** | 取得はエフェメラル・保存は端末内＝収集に該当せず |
| Auto Backup（メタデータ層のみ・ADR 0015） | OS 機能が読書記録・設定を Google サーバーへ | **要確認**（下記 §1 Q1 の注記） |
| 診断情報（`diagnostics/`） | 端末内のみ・外部送信ゼロ・書き出しUIなし | 端末内処理＝収集に該当せず |
| **In-App Review**（`com.google.android.play:review-ktx` 2.0.2） | 初回読了時に Play の評価シートの表示を要求するだけ。評価内容はアプリに返らない（`review/ReviewPrompter.kt` に結果を受け取る経路が無い＝API 仕様どおり） | ✅ **2026-08-25 に決着＝Q1「いいえ」に含めてよい**（§5 の3）。Play SDK Index を実際に引いたところ**この SDK は掲載自体が無い**＝参照すべき提供元ガイダンスが存在しない。ヘルプの「ライブラリや SDK による送信も対象」という原則は変わらないが、**アプリが受け取るデータが無い**ため申告対象が生じない |

## 1. フォーム回答案（設問順）

### Q1. アプリは、必須のユーザーデータの種類を収集または共有しますか？

**回答案: いいえ**

- 根拠: ①開発者がデータを受け取るサーバーが存在しない ②分析・広告 SDK ゼロ ③外部通信はすべて「ユーザー要求の即時処理」でエフェメラル除外に該当 ④端末内保存データは定義上「収集」でない。
- **「いいえ」を選ぶと以降の設問（暗号化・削除リクエスト・データ種類の明細）はすべてスキップされる**＝フォーム作業はここで完了。
- ⚠️ **要確認（Auto Backup）**: 公式ヘルプに Auto Backup 経由の転送を収集と扱うかの明示記述は見当たらなかった（2026-07-29 確認）。推奨は「いいえ」のまま＝転送の主体は Android OS のバックアップ機構であり、宛先は開発者でなくユーザー自身の Google アカウント・開発者は内容にアクセス不能、という整理。同型アプリ（競合「リーダ」等）も収集なし基調で通している。審査で指摘された場合のみ、「収集あり（バックアップ目的・暗号化・削除手段あり）」への切替を検討する。

### Q2 以降（Q1 が「いいえ」の場合は表示されない）— 保険としての控え

Q1 を「はい」に切り替える判断をした場合の最小申告例（Auto Backup を収集と整理する場合）:

- データの種類: 「アプリのアクティビティ」（読書位置等）＋「アプリの情報とパフォーマンス」ではなく——バックアップ対象は読書記録・設定のみ＝「アプリのアクティビティ > その他のアプリ内アクティビティ」1 項目で足りる想定（**要確認**: 転記時にフォームの選択肢名と突合）。
- 収集: あり／共有: なし／処理の一時性: なし（保存される）／必須か任意か: 任意（端末設定でオフ可）／目的: 「アカウント管理」ではなく「アプリの機能」（バックアップと復元）。
- 送信中の暗号化: あり（Google のバックアップ転送は暗号化される）。
- 削除リクエスト: あり（端末設定・Google アカウントのバックアップ管理から削除可能）。

## 2. ストア掲載ページに表示される想定（Q1「いいえ」の場合）

- 「データは収集されません」「第三者と共有されるデータはありません」
- 競合実例（実査 B-4）: 「リーダ」＝第三者共有なしと表示（ただし一部収集あり申告）／「ライブラ」＝広告 SDK 由来で第三者共有ありと表示。**広告 SDK の有無が申告を分ける**＝本アプリは広告ゼロなので最もクリーンな表示になる。

3. **In-App Review を Q1「いいえ」に含めてよいか**（2026-08-21 に判明した未評価 SDK＝§0 末尾）。
   **一次ソース2点で分かったこと**: ①公式ヘルプ answer/10787469 は「ライブラリや SDK によってアプリからデバイス外に送信されるユーザーデータも対象。
   デベロッパーとサードパーティのサーバーのどちらに送信されるかにかかわらず該当」と明記し、**Play 提供 SDK の除外規定は置いていない**。
   ②In-App Reviews API の公式ガイド（developer.android.com/guide/playcore/in-app-review）は、データセーフティの回答は**デベロッパーの責任**で、
   SDK 提供元が公開しているデータセーフティ情報（Google Play SDK Index）を参照せよ、という立て付け。
   **＝「Play の SDK だから申告不要」と書いた一次ソースは見つからなかった**（"見当たらない" のであって "不要でない" とは限らない）。
   **本アプリ側の事実**（申告の材料）: 評価シートは Play ストアが描画し、**アプリは評価の有無すら受け取らない**＝アプリが収集するデータは無い。
   送るのは表示要求だけで、蔵書・読書位置・識別子は一切渡していない。
   ✅ **2026-08-25 に Chrome で SDK Index を実際に引いて決着**（JS 描画のため実ブラウザで操作した）:
   - `com.google.android.play:review` も `com.google.android.play` も **SDK Index に掲載が無い**
     （Maven ID・"review" で検索して 0 件。ヒットする Google 製は Play Billing・GMA・Maps・GIS・Google Pay など別物だけ）。
   - 掲載条件を定めた公式ヘルプ（support.google.com/googleplay/android-developer/answer/12034434）によれば、
     Index は **「Maven で配布される商用 SDK」で、かつ 100 アプリ以上・インストール1億件以上**という規模基準を満たすものだけを載せる。
     さらに**データセーフティのガイダンス URL は提供元にとって「省略可能」**と明記されている。
   **＝参照すべき提供元ガイダンスは存在しない**（"まだ見ていない" ではなく "無い" ことが確認できた）。
   **確定＝Q1「いいえ」のまま出す**。根拠はアプリ側の事実（評価シートは Play が描画し、アプリは評価の有無すら受け取らない＝収集するデータが無い）。
   ⚠️ 残る不確実性は「Google が将来この SDK を Index に載せてガイダンスを出す」場合だけ＝**提出時に1分で引き直せる**（検索して 0 件なら現状維持）。
