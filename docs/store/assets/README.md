## この2枚について確認済みのこと

- **アイコン案A のマスク耐性**＝主要素は中央60%内・**円マスクでも紙面が欠けない**（カタログの spec 欄）。
  Play ストアの表示は角丸、ランチャーは円マスク＝どちらでも栞棒と結び玉が残る。
- **48px で消えるのは版面の縦罫だけ**（消えてよい装飾として設計されている）。残る要素は3つ（紙面・栞棒・結び玉）。
- **フィーチャーグラフィックの文字は全て中央 720×360 の内側**（左端160px・右端596px）＝端末側で切られても文言が残る。
  右の書影3冊は切られてよい装飾側。
- コントラスト＝和紙:藍 **10.80**／副文（青磁明:藍）**5.44〜8.77**＝いずれも AA を満たす。

## スクリーンショット（`screenshots/`）

### ⚠️ 掲載素材に**実在作品を写さない**（2026-08-25 の判断・この節で最重要）

撮影用エミュに入っていた蔵書9冊は **実在の「小説家になろう」作品**（著作権存続中・作者名つき・本文HTML全文）だった。
ストアのスクショは**公開の宣伝物**なので、そのまま撮ると:

- **読書画面**＝他人の著作物の本文1ページを、非公式アプリの広告として複製・公衆送信する
- **本棚画面**＝9作品の題名を作者の許諾なく自社アプリの装飾に使う（**黙示の推薦**と読まれうる）。
  うち2件は**他社の販促文字列**（`【書籍３巻発売】`・`【マンガボックス様にて漫画連載中！】`）を題名に含み、
  それがそのままストアの棚に並ぶ
- **目次画面**＝同上（話タイトルの一覧）

これは `../listing-draft.md` §0 の自衛線（「公式を装わない」「規約線に触れない」＝ADR 0011/0024。
競合が実際に停止を食らっている）と正面から衝突する。したがって **掲載素材に写る作品は全て書き下ろしのデモ蔵書へ差し替える**。
UI・組版・ルビ描画は本物のまま＝**アプリの挙動は何も偽らず、写っている作品だけが架空**という状態を作る。

> ⛔ **実蔵書のまま撮ったものを `screenshots/` へ置かない**。置いてよいのはデモ蔵書か、
> 作品が一切写らない画面（さがす・設定）だけ。

### 撮り直しの手順

**必ず release APK で撮る**（`app-release-debugsigned.apk`）。debug ビルドは①設定に「開発」節が出る
②`SKIN_SWITCHING_ENABLED`＝true できせかえ行が見える＝**どちらも初回リリースに存在しない**（ADR 0027）
＝debug で撮ると存在しない機能をストアに載せることになる。**装いの間・きせかえ行は絶対に写さない**（スキンは既定の明快K）。

```bash
ADB=~/Android/Sdk/platform-tools/adb          # ⚠️ 7台繋がる環境＝-s は必須
$ADB -s emulator-5564 install -r .../app-release-debugsigned.apk   # 蔵書は残る（debug署名）
$ADB -s emulator-5564 shell dumpsys package com.novelreader | grep pkgFlags   # DEBUGGABLE が消えていること

# ステータスバーを固定（時刻12:00・電池満・通知なし・Wi-Fi満）＝生スクショの素人臭さを消す
$ADB -s emulator-5564 shell settings put global sysui_demo_allowed 1
for c in "enter" "clock -e hhmm 1200" "battery -e level 100 -e plugged false" \
         "network -e wifi show -e level 4 -e fully true" "network -e mobile hide" \
         "notifications -e visible false"; do
  $ADB -s emulator-5564 shell am broadcast -a com.android.systemui.demo -e command $c
done
# 戻すとき: ... -e command exit
```

⚠️ `network -e wifi show -e level 4` **だけでは Wi-Fi に「!」（未検証）が付く**＝`-e fully true` まで付けて消す（実測）。

```bash
python3 seed-demo-library.py --serial emulator-5564 --push   # デモ蔵書を投入（実蔵書の行は退避）
$ADB -s emulator-5564 exec-out screencap -p > _raw/phone-1-vertical-ruby.png
python3 finalize-screenshots.py                              # 24bit 化＋Play要件の検算
```

- **タップは `uiautomator dump` で bounds を見てから**（当てずっぽうのタップ禁止）。
  本文段落・縦書き面は `text` を持たない＝`content-desc` で判定（`../../knowledge/vertical-reading-has-no-text-nodes-for-ui-automation.md`）。
- **タブレットは座標が全く違う**（左ナビレール・5列グリッド）＝スマホの座標を流用しない。
- 投入前に DB 3ファイルを退避しておけば元に戻せる（`seed-demo-library.py` は HTML 実体を消さない）。

### Play の要件（`finalize-screenshots.py` が機械で検算する）

`screencap` の出力は **RGBA（color type 6）**で、Play の要件は「JPEG または **24bit PNG（αなし）**」
＝**生のままでは弾かれる**。変換と併せて次を検算している（出典 `support.google.com/googleplay/android-developer/answer/9866151`）:

| 要件 | 1080×1920（スマホ） | 2560×1600（タブレット） |
|---|---|---|
| 各辺 320〜3840px | ✅ | ✅ |
| 長辺 ≦ 短辺×2 | ✅ 1.78 | ✅ 1.60 |
| 24bit PNG・α なし | ✅ 変換後 truecolor | ✅ 変換後 truecolor |
| 枚数（スマホ2〜8） | 6枚で提出 | 4枚（任意） |

## 未確定（提出時に効くもの）

- ✅ **アプリ内のランチャーアイコンも同じ案A へ揃えた**（`android/app/src/main/res/drawable/ic_launcher_{foreground,background}.xml`）。
  ストア用512²とランチャー用アダプティブアイコンは別物で Play は両方が別物でも受け付けるが、
  **揃っていないと初回起動で「別のアプリを開いた」感が出る**ため合わせた。
  ⚠️ **VectorDrawable では案A の紙面の影（`feDropShadow`）を表現できないため落としている**＝PNG と完全一致ではない。
  ⚠️ **実機のホーム画面（円マスク・実際の壁紙）での見え方は未確認**＝次に端末を触るときに見る。
- **スクショは 1/6・1/4 で止まっている**（上の「スクリーンショット」節）。撮れているのは**作品が写らない「さがす」だけ**で、
  残り（読書・本棚・目次・読書設定・横書き）は**デモ蔵書をエミュへ投入しないと撮れない**。
  ⚠️ **投入コマンドが権限で拒否されて未実行**＝`seed-demo-library.py --push` は
  アプリ専用領域（`/data/data/...`）への書き込みと DB 行の入れ替えを行うため、自動承認の分類器に
  「端末データの破壊操作」として2度ブロックされた。**回避せず人間の許可待ちにしてある**。
  スクリプト・デモ本文・撮影手順は全て用意済みで、**許可が出れば1コマンドで再開できる**。
