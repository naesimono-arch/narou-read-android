# 0030. 再発防止 L3（knowledge 自動注入フック）は**不採用**——機械検知への変換が上位互換

- 状態: **Accepted（2026-08-05）— 不採用の記録**
- 関連: `docs/known-bugs-registry.md`（L4＝判断材料の出所・L1〜L4 の層定義）／ADR 0006（実行捏造の静的検知＝「読ませる」でなく「機械で止める」路線の先行例）

## 経緯

再発防止は L1（不変条件テスト）・L2（走査メタテスト）・L4（既知バグ台帳）が着地済みで、
残る判断が L3＝「`docs/knowledge` の各知見に `triggers:` を持たせ、Edit/Write 時に該当知見を
自動注入するフックを作るか」だった。採否は L4 が可視化する無防備件数を見て決める、としていた。

## 判断材料（L4 が出した無防備の内訳・2026-07-31 時点）

- 無防備は **21/63 件**（`なし` 15・`知見のみ` 6）。
- **L3 が効くのは `知見のみ` の6件だけ**。残り15件は knowledge 自体が無く、注入する材料が存在しない。
- 2026-07-30 の実証で論点が動いた——「知見のみ」は**注入せずとも機械検知へ変換できる**
  （tooling の2件で実演＝撤去フックの残骸検知・委譲のスコープ外削除通告）。
  knowledge を「読ませる文書」でなく**「検知を書くための設計書」**として使う路線が実際に機能した。
- 残る6件の変換見通し:
  - **変換できる**: `snackbar-indefinite-blocks-queue`（Indefinite×actionLabel の同時使用を走査）／
    `theme-invariant-surface-loses-contrast`（contrast check へ「面がテーマ不変か」のフラグ）
  - **部分的に可**: `fixed-bar-clearance-hardcoded-guess`／`webview-position-mis-record`
  - **静的検査では無理**: `oem-background-kill`／`benchmark-device-run-fragility`（実機依存。
    ただし「防御コードが在るか」の構造検査なら可）

## 決定

**L3 は作らない。** 理由は「効かないから」ではない——L3 は6件には確かに効く。
不採用の理由は**上位互換があるから**: 知見を機械検知（走査テスト・check スクリプト）へ変換すれば、

1. **読まれなくても止まる**（注入は「読まれること」に賭ける＝`知見のみ` を無防備に数えたのと同じ弱点を持ち込む。
   K ランキング Pager 化の再発は knowledge が在っても起きた）
2. カバー範囲が `知見のみ` 6件に限定されない（`なし` 15件も、知見を書き起こせば同じ変換路線に乗る）
3. フックという常駐機構（配線・保守・サイレント失敗リスク＝ADR 0004/0008 の教訓）を増やさない

## 帰結

- 今後「知見のみ」の項目が増えたら、既定の次の一手は **triggers 付与ではなく機械検知への変換**。
  変換できない（実機依存など）ものだけが `知見のみ` に残ることを許容し、L4 の状態列で可視化し続ける。
- `docs/known-bugs-registry.md` の L3 行は本 ADR を指す形へ更新した。
