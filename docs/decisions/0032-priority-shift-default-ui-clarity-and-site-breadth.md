# 0032. 優先度の転換＝「デフォルトUIの明快さ」と「対応サイトの広さ」を豪奢スキンより上に置く

- 状態: 採用（2026-07-20 ユーザー裁定）／**2026-08-14 に handover から ADR へ移設**（転換の理由は
  やることでなく判断＝台帳に置くと残タスクが消えても背景だけが居座る）
- 関連: ADR 0024（汎用スクレイピング基盤＝最優先Bの実装形）／ADR 0027（初回公開スコープ＝スキンを隠す）／
  `/visual-language`「優先順位」節／`.claude/plans/default-ui-clarity-K-2026-07-23.md`（最優先Aの設計一次情報）

## 背景

それまでの開発は「豪奢なスキン（M 星図／P カセット／J ポータル）の作り込み」と「なろう専用の取込・閲覧」を
主軸に進んでいた。**第三者にアプリを触らせた結果、その手前で2つの本質課題が露出した**:

1. **デフォルトUI（当時＝和モダンD）が一目で分からない**。初見の利用者が、どこに何があるか・
   今どの画面に居るかを掴めない。スキンの意匠がどれだけ良くても、既定で開く画面が読み解けなければ届かない。
2. **なろう限定では求心力が足りない**。読みたい作品が別サイトにある利用者にとって、アプリを入れる理由が無い。

どちらも「作り込みの不足」ではなく**優先順位の誤り**による症状で、追加の磨き込みでは解消しない。

## 決定

**次の2つを最優先とし、豪奢スキンとリッチ化はその下に置く。**

- **最優先A＝デフォルトUI を「一目でわかる・迷わせない」設計へ。**
  大原則は `/visual-language`「優先順位」節＝**デフォルトUIは「一目でわかる」が最優先・
  豪奢さは opt-in の付加価値**。回答として新デフォルトUIスキン「明快K」を起こした（構造の現在値＝`STATUS.md` §0）。
- **最優先B＝幅広いサイト対応＝汎用オフラインDL基盤**（検索→DL→アプリ内で読む）。
  なろう限定を脱し、サイトごとに抽出器を分離できる汎用の取得/抽出基盤へ。オフラインDL＝手元の**蔵書コレクション**の位置づけ。
  - **利用規約で禁止のサイトは除外・別対応**（一律スクレイピングはしない＝ユーザー裁定）。
    なろうは公式API＝安全で優先。**公式サイト直行の逃げ道**も併設する。
  - スクレイピングは**サイトのHTML変更で壊れやすい**前提で設計する（脆さは織り込み・公式直行の逃げ道がその保険）。
  - 実装形と規約線の裁定は ADR 0024 が正本。

**豪奢スキン（M/P/J・星図リッチ化＝ui/refine 系）は否定しない＝温存する。**
既存のスキン／リッチ化 backlog は消さずそのまま保持し、優先度だけを A/B の下に置く。
（その後 ADR 0027 で、初回公開スコープからは機能ごと隠す＋保守も凍結、と具体化された。）

## 着手順序

**まず最優先Aの明快さ・バグを一掃**して「他者が困らない」状態を数日で作る。
**最優先Bの中核設計は並行で下ごしらえ**する（設計は A の作業を妨げないため）。

## なぜ「温存」であって「破棄」でないか

豪奢スキンは**課金アップデートの目玉**という位置づけが最初から与えられており（ADR 0027）、
価値が否定されたわけではない。ここで下げたのは**着手順序**だけである。
破棄すると、初回公開後に売るものが無くなる——「今やらない」と「要らない」を混同しない。
