## 背景 — 同じ論点が3度反転している（だから ADR に落とす）

読書フロー（本棚/作品詳細 → 目次 → 本文）の戻り規則は、これで**4つ目の決定**になる:

| 時期 | 規則 | 破綻した点 |
|---|---|---|
| 2026-07-12 | ← も Back も「一つ上の階層」 | 07/15 の `ReadingBackStack` 再設計が Back だけを変えて崩れた |
| 2026-07-15 | Back＝実経路の逆再生（直行入場なら1発で本棚）・← は据え置き | **← と Back の行き先が同じ画面で割れた**（実測表 §①A の ✗ 2行） |
| 2026-07-19 | ← も Back も「必ず一つ上の階層へ」（Back を ← 側へ寄せる） | 読書の親を本棚に固定していたため、入場元が2つになった時点で破綻 |
| **2026-09-07（本 ADR）** | **← も Back も「前画面へ1段戻る」** | — |

コミットメッセージは「何をしたか」の正本だが、**採らなかった案と前提は記録しない**。3度も反転した論点で
「次に誰かが4度目を提案したとき」の判断材料を残すのが本 ADR の目的である。

## 決定

**読書フローの戻りは「前画面へ1段戻る」の一規則とし、4つの入口（システム Back／章の左上 ←／目次の左上 ←／
没入時 a11y アクション「戻る」）が `performBack` ただ1つを叩く。** 内部スタックを使い切ったとき（`back()==null`）
だけ読書フローを出て、**脱出先は `upFromReading` が NavController のバックスタックから決める**。

### 入場元2種 × 操作2種（直行入場＝続きが章のとき。本裁定の中核）

| 入場元 | 操作 | 行き先 | 実装 |
|---|---|---|---|
| 本棚（続きから／通知 deep link） | システム Back | 本棚タブ | `popToTab(BOOKSHELF)`（Pager スナップ込み） |
| 本棚（同上） | 左上 ← | **同じ**＝本棚タブ | 同上（同一の `performBack` 経由） |
| 作品詳細の「アプリで読む」 | システム Back | **その作品詳細** | 素の 1 pop |
| 作品詳細（同上） | 左上 ← | **同じ**＝その作品詳細 | 同上 |

判定は「直下がタブ層（`TAB_HOST_ROUTE`）か」の1点だけ。素の pop に一本化しないのは、deep link 入場では
Pager が他タブに居ることがあり pop だけだと着地が「さがす/設定」に化けるため（`popToTab` の KDoc）。
⚠️ **入場元を nav 引数で持ち回さないこと**——バックスタックが既に唯一の正本で、引数へ写すと状態が2つになる。

### 内部スタックごとの行き先（← と Back で共通）

| 内部スタック | 行き先 |
|---|---|
| `[章]`（直行入場） | 読書フロー脱出＝入場元へ（1発。目次は経由しない） |
| `[目次]`（目次入場） | 同上 |
| `[目次, 章]` | 目次 |
| `[目次, 章B]`（話送り後＝置き換えで深さ不変） | 目次（読んできた章列を逆走しない） |
| `[章, 目次]`（直行入場から目次を開いた） | **章**（本棚へは落ちない＝07/19 で唯一残っていた割れの解消） |
| `[章, 目次, 覗章]`（参照覗き） | 目次 |

- **目次への導線は下端「目次」ボタンが単独で担う**（既存・全スキン共通）。章の ← はもう目次を開かない。
- 章の ← の `contentDescription` は「目次に戻る」→「**戻る**」へ改めた（行き先が入場形で変わるため、
  行き先を名乗らず操作名にする）。没入時 a11y も「戻る」＝`onBack`／「目次を開く」＝目次ボタンと同じに分けた。
- 「続きに戻る」チップ・`jumpOrigin`（参照モード）の挙動は不変。

## なぜ 07/19 を覆せたのか（目的と手段の分離）

**07/19 裁定の目的は〈同じ画面で操作によって行き先が割れる〉の解消であり、「一つ上の階層へ」はその手段にすぎない。**
一致は「← と Back が**同じ関数を叩く**」ことで保たれるので、手段を前画面遷移へ替えても目的は満たされる。

07/19 が併せて求めた**「横移動（話送り・参照覗き）を Back で逆走させない」も `back()` の定義ではなく、
前進側の2規則が担っている**——①既出画面への移動はそこまで巻き戻す（重複を積まない）②章⇄章の話送り・
続き復帰は置き換え（深さを増やさない）。この2規則は本改訂でも一切触っていないため、`back()` が末尾を
1枚 pop するようになっても「何話読み進めても下段は入場時の1枚のまま」＝逆走は起きない。
`ReadingBackStackTest` の話送り50連・覗き50連のテストがこの性質を固定している。

## 成立しなくなった前提（＝反転の理由は好みの変更ではない）

階層モデルは **「読書画面の親＝本棚」を固定前提**に置いていた。この前提は 2026-09-04 に作品詳細の
「アプリで読む」（`onOpenImportedBook`）が**2つ目の入場元**になった時点で崩れた——詳細から入場しても
終端が `popToTab(BOOKSHELF)` 固定で、呼び出し元を飛び越えて本棚へ落ちていた。
親が文脈依存になった以上、親を固定するモデルでは正しい戻り先を表現できない。

**⚠️ ここが4度目を安易に起こさせないための線である**: 本改訂は「前画面遷移の方が好み」だから覆したのではなく、
**前提（親が1つ）が失効した**から覆した。よって次に規則を動かす提案は、〈嗜好〉ではなく
**〈どの前提が失効したか〉**を示すこと。示せないなら本 ADR が有効である。

副次的な効き目として、発見サブツリーの up（ADR 0026＝1 pop・直下がタブ層なら `popToTab`）と**同じモデル**になり、
アプリ内に2つのナビゲーションモデルが同居する状態も解消した（`upFromReading` と `upFromDiscoveryDetail` は
同型。着地タブが違い契約テストも別なので、1関数へ束ねるなら両契約を同時に動かすこと）。

## 却下した代替案

- **案②: Back だけ前画面・← は目次のまま**（＝07/15 の状態へ戻す。「指のスワイプ＝来た道／← ＝上へ」の役割分担）。
  却下理由は2つ。①**07/19 が真因と名指した割れ**（同じ画面で操作により行き先が違う）をそのまま復活させる。
  ②目次の ← が本棚固定のままなので、**作品詳細から入場したとき ← が詳細を飛ばす**＝今回の動機（終端が入場元を
  知らない）を半分しか解けない。役割分担の説明は成り立つが、3度反転した論点で「説明可能な二本立て」へ戻すのは、
  4度目の反転を約束するのと同じである。
- **07/19 の階層 up を維持し、終端だけ入場元依存にする**。目次 ← が入場元へ帰るようになる一方、直行入場の
  Back/← が「目次を経て脱出」の2段のままで、`[章, 目次]` の割れ（Back→章／←→脱出）も残る。
  前提が失効した本体（親の固定）に触れないため、同じ問題が別の形で再発する。
- **`ReadingBackStack` に入場元を持たせる**。同じ状態がバックスタックと構造体の2箇所に住み、
  「詳細から入場した後に別経路で pop した」ときにズレる。判定はバックスタック側の1箇所に閉じた。

## 据え置いたもの

**`ReadingErrorScreen` の `onNavigateToBookshelf` は本棚へ直行のまま**（章パース失敗時のエラー画面の
「本棚に戻る」ボタン、および書籍が見つからないときのルート側エラー画面）。**ボタン文言と行き先を一致させる**
ためで、戻りの終端（`onExitReading`）とは別物として `ChapterNav`／`ReadingScreen` の KDoc に明記した。
＝読書フローには「入場元へ帰る終端」と「文言どおり本棚へ落ちる袋小路の脱出」の2つが意図的に併存する。

## 実装上の落とし穴

**`BackHandler` は末尾ラムダ形で書くこと**＝`BackHandler(enabled = true) { performBack() }`。
`BackHandler(enabled = true, onBack = performBack)` と名前付き第2引数にすると、`HazardousPatternScanTest`
（型5 backhandler-enabled-flip-loses-os-registration）が丸括弧内を丸ごと「enabled の駆動式」として読むため
定数 `true` と見なされず違反で落ちる。実装中に実際に赤になった（走査側の識別力を守るための形＝スキャナは正しい）。

## 検証

- `ReadingBackStackTest`（新契約へ全面改訂・16件）: back は必ず末尾1枚 pop で現在地の種類（章/目次）に依存しない／
  終端までの回数が入場形で決まる（直行1回・目次経由の本文2回）／覗き・話送りで段が増えない／`listSaver` 契約。
- `ReadingEscapeNavigationTest`（8件）: 上表の**4通りを1テスト1通りで全数**＋内部スタックが残る間は読書ルートを
  出ないこと。本物の `upFromReading` を叩く配線ミラー（ViewModel を要求する `ReadingScreen` 実体は JVM で組めない
  ため、`DiscoveryUpNavigationTest` と同じ手法）。
- `NativeReadingScreenA11yTest`（8件）: 上端 ← と a11y「戻る」が `onBack` を叩き `onNavigateTo("index.html")` を
  叩かないこと（← が目次固定へ退行したら落ちる）。
- ゲート実測: `testDebugUnitTest --rerun` で 1800 tests / failures 0 / errors 0 / skipped 5、
  `:app:assembleDebugAndroidTest` 成功。実機目視は未実施（監督の関門）。

## 残課題

**`[章, 目次]` からの戻り（目次→章）が push 向きのモーションで描かれる**——本文が右から入り目次が左へ抜ける
＝「戻るのに進む向き」に見える。`AnimatedContent` の `transitionSpec` は遷移前後のファイル名だけから向きを
導いており（`toToc`/`fromToc`）、**push か pop かを知る手段を現構造が持たない**ため、方向ヒントを配線するまで
直せない。直行入場で目次を開いてから戻った場合にだけ現れる（07/15 期も同じ挙動だった）。
モーションは意匠層＝`/visual-language`（HTML モック正本）の管轄で別便の所有のため、本便では手を付けていない。

**正本モックの追従**: `docs/design-candidates/reading-backtotop-D.html` の ← は `aria-label="目次に戻る"` のままで、
実装（「戻る」）と乖離している。モックは正本かつ別便の所有物のため本便では変更していない。
