# 0016. 本棚既定ソートの二層化（読書中=lastReadAt 降順を上層・未読=addedAt 降順を下層）

- 状態: 採用（2026-07-12・`ui/polish`＝UX/Design 全層監査 ia Major の消化）
- 関連: 実装 `viewmodel/ShelfItems.kt`（`RecencyKey`）・`data/BookDao.kt`（ORDER BY 同一規則）／監査一次情報 `.claude/plans/ux-design-full-audit-2026-07-12.md` §B [ia] 15-§B／目録モックの持ち越しメモ「①ソートの既定（最近読んだ順/追加順/五十音）」に対する裁定

## 背景

- 旧既定は追加順（addedAt 降順）系で、**未読の新刊を取り込むたびに「読みかけの本」が下へ押し下げられた**。
- UX KB 15-§B: 本棚の支配的タスクは「続きから読む」＝既定ソートは支配的タスクに奉仕すべき。読みかけへの最短路が数冊の取込で壊れるのは、最頻タスクの動線を最新の操作（取込）が破壊する構造。

## 決定

**二層キー `RecencyKey(tier, value)` で並べる。**

- **tier1（上層）= 読書中**（`lastReadAt > 0`）: `lastReadAt` 降順＝最近読んだ本ほど上。
- **tier0（下層）= 未読**: `addedAt` 降順＝最近入れた本ほど上（未読同士では「入れたばかり」が発見しやすい）。
- Web 由来カード（未取込）は tier0 扱い（読書中の実蔵書を押し下げない）。
- DAO の ORDER BY と `mergeShelfItems` の比較を**同一規則**にし、DB とメモリで並びが食い違わないようにする。

## トレードオフ（自覚して受け入れたもの）

- **数ヶ月前に1回だけ開いた本**が tier1 に居続け、入れたての未読新刊より常に上に出る（放置本の decay は入れていない）。
- Web/未取込カードは従来の純粋時系列インターリーブから tier0 へ降格。
- これらが実使用で不快なら、decay（一定期間未読で tier0 へ）・お気に入りピン留め等の追加裁定を別 ADR で。

## 却下した代替案

- **純 lastReadAt 単キー**: 未読本（lastReadAt=0）が全て最下層で固定順になり、「入れたばかりの本を選びに行く」第2タスクが壊れる。却下。
- **現状維持（追加順）**: 支配的タスク（続きから読む）が従属タスク（取込）に負ける構造そのもの。却下。
- **ユーザー選択式ソート UI の先行追加**: 既定の質から逃げる解（UX/19: 最良の設定は開かれない）。まず既定を正し、選択肢は要望が出てから。
