# 0016. 本棚既定ソートの二層化（層反転済み: 未読=addedAt 降順を上層・触った本=lastReadAt 降順を下層）

- 状態: 改訂（2026-07-16・実使用フィードバックによる層反転。旧決定=読書中が上を棄却）／初版採用は 2026-07-12（`ui/polish`＝UX/Design 全層監査 ia Major の消化）
- 関連: 実装 `viewmodel/ShelfItems.kt`（`RecencyKey`）・`data/BookDao.kt`（ORDER BY 同一規則）／監査一次情報 `.claude/plans/ux-design-full-audit-2026-07-12.md` §B [ia] 15-§B／目録モックの持ち越しメモ「①ソートの既定（最近読んだ順/追加順/五十音）」に対する裁定

## 背景

- 旧既定は追加順（addedAt 降順）系で、**未読の新刊を取り込むたびに「読みかけの本」が下へ押し下げられた**。
- UX KB 15-§B: 本棚の支配的タスクは「続きから読む」＝既定ソートは支配的タスクに奉仕すべき。読みかけへの最短路が数冊の取込で壊れるのは、最頻タスクの動線を最新の操作（取込）が破壊する構造。

## 決定

**二層キー `RecencyKey(tier, value)` で並べる。**

- **tier1（上層）= 読書中**（`lastReadAt > 0`）: `lastReadAt` 降順＝最近読んだ本ほど上。
- **tier0（下層）= 未読**: `addedAt` 降順＝最近入れた本ほど上（未読同士では「入れたばかり」が発見しやすい）。
- Web 由来カード（未取込）は tier0 扱い（読書中の実蔵書を押し下げない）。
- DAO の ORDER BY と `mergeShelfItems` の比較を**同一規則**にし、DB とメモリで並びが食い違わないようにする。

## トレードオフ（自覚して受け入れたもの）

- **数ヶ月前に1回だけ開いた本**が tier1 に居続け、入れたての未読新刊より常に上に出る（放置本の decay は入れていない）。
- Web/未取込カードは従来の純粋時系列インターリーブから tier0 へ降格。
- これらが実使用で不快なら、decay（一定期間未読で tier0 へ）・お気に入りピン留め等の追加裁定を別 ADR で。

## 却下した代替案

- **純 lastReadAt 単キー**: 未読本（lastReadAt=0）が全て最下層で固定順になり、「入れたばかりの本を選びに行く」第2タスクが壊れる。却下。
- **現状維持（追加順）**: 支配的タスク（続きから読む）が従属タスク（取込）に負ける構造そのもの。却下。
- **ユーザー選択式ソート UI の先行追加**: 既定の質から逃げる解（UX/19: 最良の設定は開かれない）。まず既定を正し、選択肢は要望が出てから。

## 改訂（2026-07-16・実使用フィードバックによる層反転）

初版（上記「決定」＝読書中を上層）を実使用したユーザーから、**「取り込んだばかりの未読が、読みかけの本の下に埋もれて見つけにくい」**という不満が出た。ユーザー裁定により、二層の**上下を反転**する。

### 新決定（層を反転する）

- **tier1（上層）＝未読/未接触**（`lastReadAt = 0`）: `addedAt` 降順＝最近取り込んだ本ほど上。「取り込んだ本はまだ読んでいないゆえ最上位」。
- **tier0（下層）＝触った本**（`lastReadAt > 0`）: `lastReadAt` 降順＝最後に触った本ほど上。
- Web 由来カード（未取込）も同一規則へ写像: web 読書進捗で「触った」記録があるものは下層（その最終接触時刻＝web の `lastReadAt` で並べる）・未接触は上層（`addedAt` 降順）。
- DAO の ORDER BY と `mergeShelfItems` の比較を**同一規則**にする原則（初版）はそのまま維持し、`tier` の割当だけを入れ替える。

### 旧決定を棄却した経緯

初版は監査公理「続きから読むが支配的タスク」から「読書中を常に上」を導いた。しかし実使用では、取込直後に「今入れた本を開く」動線（第2タスク）の方が高頻度で、未読新刊が下層に沈むと**取り込んだ本を探しにいく操作が壊れる**方が体感の痛みとして勝った。初版の「却下した代替案」で退けた懸念（未読が最下層に固定される）が、実際には上層で解消されるべき問題だった。

### 新トレードオフ（自覚して受け入れたもの）

- **読みかけの本が、入れたての未読新刊より下へ下がる**（初版と逆の痛み）。数冊取り込むと「続きから読む」対象が下層へ移る。
- 初版のトレードオフ（半年前に一度読んで放置した本が未読新刊の上に居座る）は、逆に解消される。
- **どちらの痛みを取るかはユーザーが実使用の上で明示的に選好した**（未読を上）。将来また不快が出れば、decay・お気に入りピン留め・ユーザー選択式ソートを別 ADR で検討する（初版の却下案は「まず既定を正す」段階を一巡した今、再評価の余地がある）。

## 追記（2026-07-26）: Web 未取込カードの tier1 特権を廃止（裁定変更）

実機使用でユーザーが後退を報告: 未取込・未接触の Web カードが実棚で唯一の tier1 住人となり**恒久先頭に居座る**
（蔵書は全て「触った本」の棚では、直近に取り込んだ/読んだ作品が何をしても上回れない）。ユーザー裁定＝
「別作品を取り込んだ・読んだ直後は**その作品**が最上位に来るべき」。

- **決定**: Web 由来カードの列だけ二層写像から外し**常に tier0**（触った web＝最終接触時刻・未接触＝`addedAt` を
  そのまま tier0 のキーに使う）＝`webRecencyKeyOf` を分離新設。**初版「Web 由来カードは tier0 扱い」への部分回帰**。
- **不変**: 蔵書の二層（未読 tier1 上層＝取込直後の本が最上位・触った本 tier0 下層）・DAO ORDER BY・
  「DAO と merge の同一規則」原則はそのまま（改訂 2026-07-16 の主決定は蔵書について維持）。
- **なぜ Web だけ戻すか**: 上の改訂の動機「取り込んだ本を探しにいく操作が壊れる」は**取込済みの蔵書**の話で、
  未取込 Web カードは「まだ入れていない予定表」＝取込直後動線の主役ではない。tier 特権を与えると
  蔵書側の直近操作を恒久的に覆い隠し、改訂の意図と逆の痛みを生んだ（実測＝本追記の発端）。
- テスト固定: `ShelfItemsTest` 裁定変更①〜③＋「tier1 特権は蔵書のみ」ピン（2026-07-26）。
