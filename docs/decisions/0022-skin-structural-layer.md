# 0022. スキン第二層＝画面構造の切替（M星図・Pカートリッジ・Jポータル実装の前提裁定）

- 状態: 採用（2026-07-17・`ui/skin-framework`。ADR 0021 追記2「二層拡張が必要」の設計裁定）
- 関連: ADR 0021（トークン束スキン＝第一層）・ADR 0014（原則5箇条・静謐則・ヘアライン家系裁定）・
  プラン `.claude/plans/skin-compose-implementation-2026-07-17.md`／モック正本 `docs/design-candidates/skins/{bookshelf,reading,toc,settings,discovery}-{M,P,J}.html`

## 背景

M/P/J は本棚〜各画面の構造ごと別物の**構造スキン**であり、SkinTokens（トークン束）だけでは表現できない
（ADR 0021 追記2 で「二層化が必要」とだけ裁定し、設計は本 ADR へ送られた）。
モック全数読解（2026-07-17・5画面×3スキン）で判明した、プラン前提と食い違う事実2点も本 ADR で裁定する:
①P モックにテーマ変種の実体が無い（settings-P の3択はスウォッチ見本のみ・モック自身が「変種数は裁定事項」と明記）
②J の3テーマは読書画面のみ（本棚/目次/発見/設定は固定ダーク森面）。

## 決定

### 1. 二層化＝「画面入口の薄いルーター」で分岐（早すぎる抽象化の禁止）

- **画面丸ごと分岐**（`when(skin)` で SkinX 専用 Composable へ委譲・分岐先は `com.novelreader.ui.skins.m/.p/.j` に1画面=1ファイル）:
  **本棚・目次・発見ホーム・発見結果一覧**。既存 D/C 実装は default 分岐として無改変温存。
- **共通骨格＋スキン別部品**（画面を複製しない）:
  - **読書**: 本文エンジン（組版・ページング・章送り・キャッシュ・タップトグル・状態機械）は単一のまま。
    スキンで替わるのはクローム部品のみ（進捗表示・章扉・上下バー・没入ヒント）＝部品単位の when(skin)。
    **本文組版の規格層（明朝・行間・ルビ 1/2・和文 letterSpacing 0）は全スキン不可侵**（モック3種とも明記済み）。
  - **設定シート**: ロジック（テーマ択・スライダー・永続化）は共有、シート意匠（面・つまみ・値表示）のみスキン分岐。
- **モックの無い画面は構造を発明しない**: 発見の検索/ジャンル/詳細等は Material トークン追従のみ
  （ADR 0021「D 構造へトークン写像」の原則は未モック画面に対して存続）。
- **共通化の抽出は3スキン実装後**（分岐先が2つ以下の抽象を先に作らない＝ADR 0021 却下案の原則踏襲）。

### 2. supportedThemes（変種軸の裁定・モック実態準拠）

| スキン | supportedThemes | 根拠 |
|---|---|---|
| M 星図 | `[DARK]`（夜の相・固定1変種） | settings-M がテーマ固定表示（C と同型）を明示 |
| J ポータル | `[DARK, LIGHT, SEPIA]`（既定=DARK） | reading-J に `.t-dark/.t-light/.t-sepia` の13変数一式。**変種が作用するのは読書系トークンのみ**＝material/shelf は theme 非依存の固定ダーク森面（モック実態。設定チップの扉プレビューは reading 値と連動） |
| P カートリッジ | **`[LIGHT]` で開始**→追補モック承認後に3テーマ化 | モックに変種の実体なし。プラン前提「P=3面」は事実誤認と確定。無根拠のセピア/ダーク値をコードへ発明せず、reading-P へテーマ変種を**追補モック**として起こし人間承認を経てから追加（ユーザーは追加モック作成を許可済み・2026-07-17） |

### 3. モーション裁定（ADR 0014 原則5・静謐則との突合）

- **「現在地の脈動」類型を承認**: M 本棚の hero 結線先端星（sin 周期・reduce で固定輝度静止）・M 目次の現在章ドット
  （CSS pulse 2.8s・reduce で animation なし）・M 目次 canvas 先端星。これらは装飾ループではなく
  **「ここから続く」という現在地のフィードバック**＝原則5の許容目的（読了印・進行類型に続く第3の正当化例外）。
  制約: ①脈動は正本モックにある箇所のみ・新設禁止 ②**reduce-motion で完全静止（モック規定の固定値）を必須**
  ③振幅・周期はモック値を正とする。**読書画面 M はモーションゼロ**（モックの意図＝読書の静けさ）を守る。
- **P/J はモックにモーションが存在しない**（keyframes/transition/JS ゼロ）＝**静止で実装開始**。
  スワイプ・遷移・シート等の機能モーションは既存 `Motion.kt` スロットを流用し、スキン固有の演出新設は
  実機後詰め層（ADR 0005 §B）へ送る。ProcessingBanner 等の既存フィードバックは共通機構のまま。

### 4. トークン正規化（モック間の同名変数食い違いの扱い）

- **画面家系で値が分かれるものは家系トークンへ分離**（ADR 0014 ヘアライン裁定と同型）:
  例 J `--page` #0C0E0B（本棚/発見）と #0F1712（読書/目次/設定）は「回廊の外殻」と「森の内側」の2トークン。
  P `--line` 3値は shelf/reading 系・シート・発見系のスロットへ各々振る。
- **同一役割の知覚下微差は多数値へ正規化**し、正規化の事実を Color.kt の該当 val コメントに記録
  （例 M `--line` α .20/.22 → .20 へ、J `--soft` α .62/.60 → 家系ごとに1値）。個別の採否は C1 の1:1対応表が正本。

### 5. 識別色・ambient パレットは SkinTokens にスロットを切らない

M の学名ドット `--id` 4色・P のラベル/ジャンル色 w1-w4/g1-g6・J の ambient グラデ群は、
**スキン専用の構造画面だけが使うデータ駆動パレット**＝トークン束（全画面共有の窓口）に載せず、
当該スキンの構造画面が `Color.kt` の系統別 val を直接参照する（ADR 0021「栞型軸はスロットを切らず必要時に足す」と同じ倹約則。
直書き禁止は Color.kt 命名 val 経由で担保）。

### 6. enum 値名

`SEIZU_M`（星図）・`CARTRIDGE_P`（カートリッジ）・`PORTAL_J`（ポータル）。追加は SkinX.kt 実装と同一コミット
（ADR 0021 規約）。displayName/tagline は装いの間カードの表示文言＝コミット時に人間検収。

## 却下した代替案

- **SkinTokens へ画面ファクトリ（Composable スロット）を足す**: 束 interface が画面実装へ肥大し、
  トークン層（値）と構造層（描画）の役割分離が崩れる。ルーターの when は画面側に置く方が薄い。
- **読書画面の丸ごと複製（ReadingScreenM 等)**: 本文エンジン（ページング・章キャッシュ・位置永続化）の
  三重複製＝回帰の温床。クロームだけがスキンの署名でありエンジンは共有できる。
- **P を最初から3テーマで実装**: モックに変種値が存在せず「翻訳」でなく「発明」になる（/visual-language
  の自己判断禁止に抵触）。追補モック→人間承認→実装の順を守る。
- **食い違い値の機械的な単一値統一**: ADR 0014 ヘアライン裁定が示した通り、画面家系での値分岐は意図的な
  較正であり得る。家系トークン分離で顕在化させ、真の微差のみ正規化する。
