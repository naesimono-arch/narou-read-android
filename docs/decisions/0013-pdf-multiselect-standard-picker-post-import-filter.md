# 0013. PDF 複数選択は標準ピッカー＋取込段フィルタ（独自ピッカー不採用）

- 状態: 採用（2026-07-11・`feat/pdf-import-improve`）
- 関連: 実装 `viewmodel/PdfImportSelection.kt`・`BookshelfViewModel.addBooks`／現況は STATUS §1

## 背景（要求と制約）

ユーザー要望は2つ:
1. **PDF を複数同時に選択**して一括取込したい。
2. Download には「いろいろな PDF」が混在して**どれがなろうPDFか分からない**ので、**なろうPDFだけを（ソートして）選びたい**。

ここに Android の壁がある。**OS 標準のファイルピッカー（SAF＝Storage Access Framework／`ActivityResultContracts.Open*Documents`）は、アプリから渡せるのが MIME タイプ（`application/pdf`）だけ**で、
**ファイル名・中身での絞り込みも、並べ替え順の固定も、アプリからは制御できない**（DocumentsUI の並べ替えメニューはユーザーが手で操作するものであり、既定も指定不可）。
つまり「なろうPDFだけを、ソートして選ぶ」を**選択画面で**実現するには、アプリが独自のファイル一覧UIを持つしかない。

なお、なろう公式縦書きPDF は DL 時のファイル名が `<NCODE>.pdf`（例 `N2959KI.pdf`＝`N`＋数字4桁以上＋英字1〜2）＝**1作品1ファイル・巻番号なし**。これは実機 Download の実データでも裏付けた（`N0743GY.pdf`〜`N9271IY.pdf` が多数）。

## 決定

**標準ピッカーで複数選択（`OpenDocument`→`OpenMultipleDocuments`）し、なろう形式かどうかの判定は「取込段」で行う。**

- 選択後、各 URI の表示名（ContentResolver の `DISPLAY_NAME`）を解決し、`^n\d{4,}[a-z]{1,2}\.pdf$` で Nコード名かを仕分ける。
- **全てなろう形式なら無摩擦で取込む**（case 1＝主フロー）。
- **非なろう形式が混在するときだけ確認ダイアログ**（`なろう形式のみ`／`すべて取り込む`／`キャンセル`）を出す。
- **非なろう形式を黙って捨てる経路は作らない**（ユーザー要望「無確認拒否はしない」）＝必ず確認を挟み、`すべて取り込む` で改名済みの正当PDFも救済する。
- 取込順は本棚が `addedAt DESC`（`BookDao.getAllBooks`）＝逐次処理で後に投入した本ほど新しいことを利用し、自然順で先頭の巻を最後に投入して巻順（1→N が上→下）に見せる。

判定・投入順ロジックは Android 非依存の純関数（`viewmodel/PdfImportSelection.kt`）に集約し JVM 単体テストで担保する（[ADR 0009] の方針＝テスト可能な純ロジック分離と同型）。

## 却下した代替案

- **案A: 独自のアプリ内選択画面**（SAF ツリー権限でフォルダを取得→そのフォルダ内 PDF を一覧→Nコード名だけに絞り込み＋自然順ソート→複数チェックで取込）。
  「なろうだけ表示＋ソート」を**選択時点で**満たす唯一の方法だが、**新画面・SAF ツリー権限・一覧UI・サムネイル・状態管理**が要る大きな追加で、要求（複数選択＋取り違え防止）に対して過剰。デバイス全体の PDF 走査は非メディアファイルのため `MANAGE_EXTERNAL_STORAGE`（全ファイルアクセス＝Play ポリシー上も重い）を要し、これも避けたい。ユーザーも「標準ピッカー＋取込段判別」を選択。
- **案B': 非なろう形式を無確認で自動スキップ**。摩擦は最小だが、**改名済みの正当ななろうPDF を黙って落とす**恐れがあり、ユーザー要望「無確認拒否はしない」に反する。確認ダイアログ＋`すべて取り込む` で救済する現方式を採用。

## 帰結

- ✅ 選択画面は OS 標準のまま（実装小・保守容易・権限追加なし）。複数選択は `OpenMultipleDocuments` で成立。
- ✅ なろう形式でない PDF は必ず確認を挟むため取り違え・変換失敗の事故を減らせる。かつ救済口があるので取りこぼしは不可逆にならない。
- ⚠️ **「選択画面での」なろう絞り込み・ソートは提供できない**（SAF 制約）。それが必要になったら案A（独自ピッカー）を別途検討する。
- ⚠️ Nコード名判定は strict（precision 優先）＝改名済みPDF はダイアログ経由になる。命名規約が変わった/緩めたい場合は `isNarouPdfFileName` の正規表現を調整する。
