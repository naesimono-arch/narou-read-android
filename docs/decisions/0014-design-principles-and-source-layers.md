# 0014. デザイン原則5箇条＋禁止則表の正式化と、デザイン正本の層構造宣言

- ステータス: Accepted
- 日付: 2026-07-12
- 出典: UX/Design 知識ベース（`C:\Users\qingj\Desktop\project\UX\Design` 7篇・本プロジェクトを対象に書かれた意匠の決め方 KB）。原則ドラフト＝KB 01 §4／禁止則表＝KB 04 §2／層構造＝KB 02／トークン現実解＝KB 03 §2 をほぼそのまま昇格。
- 上位関係: ADR 0005（視覚言語D）が「何を選んだか」、本 ADR が「その選択を貫く判断基準」。以後の意匠裁定は本 ADR の原則番号との衝突として記述する。

## Context（背景）

視覚言語D（ADR 0005）の正本は HTML モックだが、モック（姿）が**思想（なぜ）と語彙（値）の正本まで兼任**しており、ドリフトが実測レベルで開始していた（ヘアライン2値の無記録混在・`Color.kt` 冒頭コメントと実値の食い違い・UI 直書き3件・「モック完全準拠＞可読性」といった即席判断のコード埋め込み）。原則が文書として存在しないため、青磁コントラストや⋮アフォーダンスのような裁定を「原則との衝突」として書けず、都度の空中戦になっていた。

## Decision（決定）

### A. 正本の層構造（役割で分ける。1成果物に兼任させない）

| 層 | 正本 | 役割 |
|---|---|---|
| ①原則（why） | **本 ADR** | 裁定の上位審級。レビュー・ADR が引用する |
| ②値（what） | `theme/Color.kt`・`Typography.kt`・`Motion.kt` のトークン | 機械可読な単一値。モック CSS 変数とは一致検査スクリプトで同期を検証 |
| ③姿（look） | `docs/design-candidates/` の HTML モック | ②を使って組んだ視覚の参照実装（golden reference・受け入れ基準） |
| ④コード（render） | Compose 実装 | ③の翻訳。スクリーンショットテストで③との乖離を検出 |

tokens.json＋Style Dictionary による生成自動化は**現段階では過剰**（ソロ開発の現実解＝正本宣言＋一致検査。KB 03 §2）。導入判断は drift が検査で抑えきれなくなったときに再訪する。

### B. デザイン原則（5箇条。各1文＋捨てるものの明示）

1. **本文が主役、UIは黒衣** — 読書画面で本文以外の常時表示要素は最小。〔捨てるもの: 機能の見つけやすさ〕
2. **余白は要素である** — 余白を削って要素を足す変更はデフォルトで否。〔捨てるもの: 一覧性・密度〕
3. **色は意味である** — 藍=主アクセント/構造、青磁=副次。装飾目的の新色は追加しない。〔捨てるもの: 華やかさ〕
4. **一画面一強調** — 視覚的主張は画面ごとに1つ。〔捨てるもの: 並列アピール〕
5. **静謐は機能である** — 動き・演出はフィードバックのためだけに。〔捨てるもの: 楽しさの演出〕

原則の品質基準（KB 01 §1）: 具体的／トレードオフを刻む／逆張り可能／1文で言える。テスト法は「その原則の逆を掲げるプロダクトを想像できるか」。

### C. 禁止則表（雰囲気語→判定可能なルール。KB 04 §2）

| 雰囲気語 | 守れるルール（レビューで機械的に指摘できる形） |
|---|---|
| 余白主導 | 余白は離散スケール（4/8/16/24/40dp）のみ。任意値禁止。要素追加のために既存余白を縮める変更は原則否 |
| 静かなエディトリアル | 1画面の視覚的強調は1つ。強調手段は「藍」か「明朝の大きさ」のどちらか（両方同時は過剰） |
| ヘアライン | 区切り線は1px/最細のみ・色はヘアライントークンのみ。太線・二重線・影による区切りは使わない |
| 色は3色 | 素地・墨・藍＋補助の青磁で閉じる。装飾目的の新色追加は**本 ADR の改訂を要する** |
| 明朝は題字と本文 | 明朝＝コンテンツの声（題字・本文・章見出し）、ゴシック＝道具の声（ラベル・ボタン・メタ情報）。逆転禁止 |
| 静謐 | motion はフィードバック（状態変化の伝達）のみ。装飾アニメ・自動ループは無し。duration/easing はトークンスロットが正本（値は実機調整で更新してよい） |

### D. 可読性の優先順位（原則3の但し書き）

**アクセシビリティ最低線（意味を運ぶ文字は WCAG 4.5:1）＞美学**。「静かに沈める」は装飾・補助情報にのみ許される技法で、意味を運ぶ文字には適用しない（KB 04 §4・05 §2）。かつての「モック完全準拠＞可読性」（`Color.kt` 青磁コメントの即席判断）はこの順位で上書きする。

## 適用裁定の記録（2026-07-12・本 ADR を審級とした初回裁定）

- **ヘアライン2値**: 使用箇所の全数監査で「線か枠か」の役割ではなく**正本モックの画面家系**で値が分かれていたと判明。発見系6画面＝線も枠も `--line #ECEAE4`（→ `outlineVariant` を #ECEAE4 へ是正）／本棚系（目録・栞）＝区切り線もトラックも `--hl`/`--track` `#E4E2DB`（→ `ShelfHairlineLight`＋`LocalShelfColors` へ分離）／読書系＝reading-D の2値分離（バー線 #ECEAE4／ブロック枠 #E4E2DB）を `ReadingColors.divider`/`blockBorder` が既に忠実実装＝無変更。2トークンで両立し「混在」をトークン名で顕在化。
- **青磁「未読」ラベル**: 未読はカード上で唯一の未読表示＝意味を運ぶ文字。原則D により沈め不可 → 色相・彩度を保った濃青磁 `UnreadSeiji #50685C`（ライト素地 5.79:1・カード 5.30:1・セピア素地 4.92:1・セピアカード 4.52:1＝secondary をライトと共有するセピアでも 4.5 を満たす最小暗化）へ。青磁 `#9CB3A8` 自体は装飾・面・署名用途（Web由来カードの縦ルール・続きありドット等）で温存。ダークは既存 `SecondaryDark` が暗面 7:1 超のため変更不要。
- **発見系の情報メタ（順位番号・連載状態・読了目安・詳細の最終更新メタ・結果サブタイトル・発見ホーム未選択タブ）**（2026-07-12 追加裁定）: いずれもカード上で意味を運ぶ文字＝原則D により沈め不可 → 色相・彩度を保った暗化 `InfoText`（Light `#5C606D` 素地 6.01:1・カード 5.50:1／Sepia `#6C6148` 素地 4.97:1・カード 4.57:1／Dark は既存 `#8A929B` が暗面で合格のため同値の役割分離）へ。UnreadSeiji（未読ラベル）と同型の「意味を運ぶ補助テキストは 4.5:1 を満たす最小暗化」裁定。未選択タブは Material 標準の `onSurfaceVariant` を採らず本 ADR（原則D）を上位審級とした。
- **空本棚イラスト `#D7C6BF`**: 旧「紙と墨」暖色の取り残し＝原則3（装飾目的の palette 外色）に衝突 → テーマ追従（outlineVariant 系）へ置換。
- **motion 層**: 禁止則「静謐」の通りスロットを `Motion.kt` として正本化。値は実機調整のまま（ADR 0005-B の後詰め層に正本ゼロという穴の最小手当て）。

## Alternatives（採用しなかった案と理由）

- **tokens.json＋Style Dictionary で全自動生成**: 2プラットフォーム（HTML モック/Compose）・ソロ開発の規模では導入・保守コストが drift 検出の価値を上回る。一致検査スクリプト（`tools/check_design_tokens.py`）で同等の検出力を先に確保（KB 03 §2）。
- **原則を CLAUDE.md へ直書き**: CLAUDE.md は作業規約の場で、意匠の why の正本は ADR 体系（`docs/decisions/`）が担う役割分担を維持。CLAUDE.md からは参照のみ。
- **原則をもっと増やす／網羅する**: 原則は5±2が上限（KB 01）。数を増やすと審級として機能しない。欠落が見つかったら追加ではなくまず既存5箇条への吸収を検討する。
