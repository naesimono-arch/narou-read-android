# 0031. agy 委譲の復活設計＝三層委譲と、委譲ゲートの「機械強制」からの撤退

- 状態: **Accepted（2026-08-09）**
- 関連: memory `feedback-avoid-agy-low-trust`（禁止の経緯）／`docs/backlog-frozen.md`（凍結項目の解凍条件）／
  ADR 0030（機械と判断の線引きの先行例）／ADR 0006（事実照合を機械で止める路線）／CLAUDE.md 委譲節

## 経緯

2026-07-24 に agy（Antigravity/Gemini）を使用禁止、07-26 にプラグインごと無効化した
（`enabledPlugins` を `false`＝実体は残置）。復活の可否と設計を決めるにあたり、
**209 メインセッション（サブエージェントのログを含め 867 ファイル・1.5GB）を実測**し、
上流プラグインの28コミット分の差分を精読した。
計測スクリプトの要点＝`usage.output_tokens` を assistant ターンごとに積み、Write/Edit を含むターンを「生成ターン」として層別する。
**サブのログは `<session-id>/subagents/*.jsonl` に別置き**なので、直下の `*.jsonl` だけを見ると
サブ側（総消費の過半）を丸ごと取りこぼす——最初の測定で実際に踏んだ。

## 判断材料

### 1. 委譲の実績は Claude サブへ一極集中していた（2026-08-09 実測）

全 867 ファイル横断の `subagent_type` 出現数（メイン209本＋サブ全ログ）:

| 委譲先 | 起動記録 |
|---|---|
| general-purpose | 396 |
| Explore | 102 |
| device-verify / Plan / model-probe / claude-code-guide | 21 |
| **antigravity-delegate（agy）** | **2** |

- `agy-delegate.sh` の実行痕跡があるのは7セッション（実質 07-07〜07-12 の4本＋無効化作業）。
- `~/.antigravity-jobs/` は**空**＝ジョブ実行の完走記録ゼロ・`health.json` 無し。
- 一方でポリシー注入（~450トークン）は**209本中170セッションに入り続けた**＝投資はほぼ毎回・実行はほぼゼロ。

### 2. 使われなかった理由は「信頼度が低い」だけではない

1. **入口の二重化と規律の非対称** — Claude サブは `inject_subagent_briefing.py` が起動時に規律を機械注入する。
   agy はブリーフを手書きする分だけ監督の負荷が高く、同じ仕事なら常に Claude サブが安い。
2. **検証負荷が監督に乗る** — 「削除行込み diff 全量レビュー」は agy 前提のルールで、Claude サブでは不要と
   明文化済み（memory 追記 2026-07-17）。**agy を選んだ瞬間に監督のコンテキストを食う規律が復活する**構造だった。
3. **委譲がハングする**（下記3）。
4. 信頼度（偽GREEN・較正値クラスの見落とし＝memory `agy-mechanical-batch-calibrated-values`）。

### 3. ハングの真因は上流が特定し、根治済み（issue #37 / `33932f5`）

> agy の stdio MCP 子プロセスが wrapper の stdout を継承して agy より長生きするため、
> `OUT="$(agy ...)"` が EOF を永久に見ない。timeout guard も効かない（agy は殺せるが MCP 子が
> pipe の書き込み端を握り続ける）。

`~/.gemini/config/mcp_config.json` に stdio MCP サーバーがあると**毎回ハングする**という機序。
`docs/backlog-frozen.md` の「同期実行が保証されない（委譲5件中3件で再発）」は
"バックグラウンド起動のまま" と推定していたが、真因はこれ。上流は stdout を temp file 経由にして修正済み＝
**解凍条件がこちらの作業なしに満たされた**。

### 4. ゲートの実効性（本 ADR の主論点）

| ゲート | 実装日 | 判定 |
|---|---|---|
| **上限（強制委譲＝inline を deny）** | 2026-06-29 | **実効性なし**。委譲成功に繋がった発火はゼロ（そもそも委譲が2回）。確認できる発火は**正当な作業をブロックした1件**＝プラグイン無効化の直接原因。加えて `#agy-inline-ok` を Claude 自身が付けられる＝**自己 override 可能なゲートは規律として機能しない** |
| **下限（break-even 未満を止める）** | 2026-06-29 | 条件付き有効。ただし `agent_type` で self-scope するため、三層の2層目（general-purpose）が Bash で叩く経路には**効かない**＝穴 |
| **サーキットブレーカー**（hard cap 時に inline 許可） | 2026-07-02 | 有効。ただし未実証（`health.json` 生成なし）。「hard cap が起きた」という**事実の照合**＝機械が強い領域 |
| **plan 中 `--yolo` 拒否** | 2026-07-06 | 発想は有効だが**実装に穴**。上流 `d0fc12b`「`--yolo` is not the only headless write grant」＝`permissions.allow write_file(<dir>)` でも headless write が通る（agy 1.1.9 で検証済み）。ローカル実装は `--yolo` しか見ていない |

### 5. 上流も独立に同じ結論へ到達していた（0.17.0 `nudge-delegation.sh`）

> this supplies judgment MATERIAL — the DECISION stays with Claude. It never forces a delegation.

`UserPromptSubmit` で**計画に入る前**に材料を渡す方式。deny より早い段階で効き、迂回する必要がなく、誤爆しない。

### 6. 節約効果の実測——「何を移すか」で桁が2つ変わる（2026-08-09・agy ゼロコスト前提）

ユーザー指示により **agy 側はゼロコストと見なす**（別財布）。よって節約＝Claude 側消費の減少量だけを見ればよい。

| side | out | cache_read | cache_write | プレースホルダ単価換算 |
|---|---|---|---|---|
| main | 44.3M | 5,027.8M | 172.2M | ≒ $4,702 |
| **sub** | 22.8M | 5,131.5M | 350.0M | **≒ $5,324（総計の53.1%）** |
| 総計 | 67.1M | 10,159.3M | 522.2M | ≒ $10,026 |

- **コストの主体は生成ではなく `cache_read`**（10.16B トークン＝金額換算の約85%）。出力は 67.1M しかない。
- 生成ターンは出力の **20.3%**（13.6M）。層別では 2k 文字以上の塊が 985 ターン・5.9M（生成の43%）。
- したがって削減幅は「何を移すか」で桁が変わる:
  - **生成だけを agy へ** → 13.6M × 単価 ≒ 総計の **約3%**（ほぼ誤差）
  - **サブの仕事ごと agy へ** → 最大 **53%**
- ただし後者は「2層目も agy にする」ことを意味し、設計・品質保証を信頼度の低い側へ渡すことになる＝禁止の理由そのものへ逆戻りする。
  **現実的な中間解は「読み取り・調査の委譲」**——サブの `cache_read` 5.13B が消費の中心であり、read-only なら偽GREEN のリスクが構造的に無い。
  Phase 1 を読み取り専用から始める設計は、信頼度の観点だけでなく**コスト効率の観点でも最大の当たり**だった。

> ⚠️ 単価は `prices.json` のプレースホルダ（Opus 5 の実単価ではない）＝**相対比較にのみ使える**。
> また定額プランでは金額でなく「消費枠」として読むこと。

## 決定

### 決定1: 委譲の可否を機械で強制しない（上限ゲートを廃止する）

ADR 0030 と合わせると、機械に任せる範囲の線引きはこう整理できる。

- **事実の照合（事後・客観）＝機械が強い**: 実行捏造検知（0006）・hard cap・plan モード判定・golden 比較
- **判断の代行（事前・文脈依存）＝機械が弱い**: 委譲すべきか否か。強制すれば迂回されるか、正当な作業を壊す

0030 が「注入は読まれることに賭ける＝弱い」と言い、本 ADR が「deny は迂回・誤爆する」と言うのは矛盾ではない。
**機械に任せるのは事実の照合まで**という同じ線の、両側から見た姿である。

### 決定2: 三層委譲を既定形とする

```
main（オーケストレーション・委譲判断・最終ゲート）
  └── Claude サブ（設計／品質保証）
        └── agy（実実行＝生成）
```

- **2-a. 設計サブと品質保証サブを分ける。** agy の実測逸脱2種（不変値の全数列挙漏れ・較正値クラスの見落とし）は
  agy のミスというより**仕様書の不備**として現れ、仕様を書いた本人には構造的に見えない。
- **2-b. agy はフォアグラウンド同期・長 timeout で呼ぶ。** サブは追跡子ゼロで停止すると駐機して自走再開されない
  （`docs/knowledge/subagent-idle-stop-parks-forever.md`）。ここへ #37 のハングが重なると復旧は監督の手動再開のみ。
- **2-c. digest だけ持ち帰る。** 生出力の貼り戻し・agy が触ったファイルの再読み込みは禁止（コンテキスト再膨張＝節約の消失）。
- **2-d. 「削除行込み diff 全量レビュー」の担い手を2層目へ移す。** 監督は最終ゲートのみを持つ。
  これが理由2（検証負荷が監督に乗る）への構造的な回答であり、三層構造を採る最大の実利。

### 決定3: 上流 0.22.0 へ「乗り換える」（rebase しない）

ローカルは自作ブランチ `feat/delegation-break-even-gate` に独自6コミットを持ち、上流は28コミット先行（0.15.1→0.22.0）。
**競合予測**: ローカルが触った16ファイル中10を上流も変更している
（`scripts/agy-delegate.sh` 9回・`skills/antigravity/SKILL.md` 15回・`tests/run-tests.sh` 14回・`.claude-plugin/plugin.json` 15回）。

一方、残すべき独自機能は**新規ファイル**（`scripts/agy-break-even.py`・サーキットブレーカー）＝競合ゼロで再適用できる。
上限ゲート（`hooks/force-delegate-gate.py`）は決定1で廃止＝移植そのものが不要になる。
→ **master へ乗り換え、残す機能だけを再適用**。競合は `hooks/hooks.json` と `prices.json` の2点に限定される。

> ⚠️ **2026-08-11 実測でこの競合予測は外れた**（cherry-pick を実際に当てて測った）。
> 独自3コミット（`b14a034`・`f9e885b`・`6499b00`）は**いずれも競合**し、共通の競合先は
> `hooks/validate-delegate-bash.sh`——master 側がここを121行へ書き換えており、
> **その中身が下記セキュリティ修正そのもの**なので、feat 側を土台にする選択肢は無い。
> また「残す機能は新規ファイル」も不正確で、feat にしか無い新規ファイルは `scripts/agy-break-even.py` だけ。
> **サーキットブレーカー（`3d2edd9`）は `scripts/agy-delegate.sh`・`agy-job.sh`・`prices.json` への改変**であり、
> master がその `agy-delegate.sh` を9回変更済み＝機械移植は成立しない。
> 正しい移植は「**master 版を土台に、独自機能を手で足す**」の一方向のみ。

**セキュリティ上の前提**: `fa36262`（0.19.0）が `validate-delegate-bash.sh` の command-injection バイパスを修正している
（wrapper 名を部分一致で見ていたため `... # agy-delegate` で任意コマンドが通った）。
ローカル版はこの穴を抱えたままなので、**再有効化の前に追従が必須**。

### 決定4: 復活は読み取り専用から段階的に

| Phase | 内容 |
|---|---|
| 0 | 上流へ乗り換え（セキュリティ前提）・残す機能の再適用 |
| 1 | 有効化し、**読み取り専用（調査・クロスモデル検証）**から開始。書かせない＝偽GREEN・自己環境改変のリスクが構造的にゼロで、かつ判断材料6のとおり**コスト効率でも最大の当たり**（サブの `cache_read` が消費の中心） |
| 2 | 三層の配線（`inject_subagent_briefing.py` に agy 規律＝同期実行・digest・較正値クラス除外を追加） |
| 3 | 効果測定。**agy 側は測らない**（ゼロコスト前提）＝測るのは Claude 側の減少だけ。過去209セッションが対照群になるので、プラグインの `scripts/measure-session.py`（Claude 側 exact）と **`tools/measure_delegatable_tokens.py`**（本 ADR の実測に使った集計＝生成ターン層別＋side 別 `cache_read`）で前後比較する |

## 却下

- **全面 rebase して現状維持** — 競合10ファイル。かつ上限ゲートが生き残り、無効化の原因を再び持ち込む。
- **上流をそのまま採用（独自を全破棄）** — サーキットブレーカーと下限ゲートを失う。
  どちらも「事実の照合」側＝決定1の線引きで機械が強いとした領域にあり、捨てる理由がない。
- **agy を Claude サブの汎用代替として復活** — 602 対 2 という実績差は入口の設計差（規律注入の有無・検証負荷の非対称）から
  生まれている。同じ配線で戻せば同じ結末になる。
- **用途を絞らず再有効化して様子を見る** — 注入コスト（~450トークン × 全セッション）だけを払う状態に戻る。

## 帰結

- **CLAUDE.md 委譲節は三層前提へ書き換えが要る。** 特に「削除行込み diff 全量レビュー」の担い手が
  監督→2層目に変わる点と、「生成＝agy・判断＝Claude」の二分が三層に細分される点。
- `docs/backlog-frozen.md` の「同期実行が保証されない」は #37 根治により**解凍候補**。
  同ファイルの「委譲主張の E2 突合（opt-in）」は真陽性サンプル皆無で保留中だったが、Phase 1 以降でサンプルが出れば再検討する。
- `prices.json` の単価はプレースホルダ（`_gemini_flash_lo_comment` に「要 VERIFY」と明記）。
  Phase 3 の実測が済むまで、コスト効果は**推定値である**と明示したまま扱う。
- **Phase 1 の digest 契約は `docs/patterns/agy-readonly-digest-contract.md` が正本**（2026-08-11 策定）。
  行番号なしの主張は無効・自由列挙は 40KB 未満に限る・捏造1件で digest 全体を破棄、の3点が骨。
  いずれも 2026-08-10 の Read 精度実測（111KB の自由列挙で適合率82%／名指し確認は正答）から逆算している。
