# 0047. 読書フローの戻り＝階層 up へ復帰（ADR 0046 の撤回・「誰が裁定したか」を偽らないための記録）

- 状態: 採用（2026-09-07 ユーザー裁定「階層 up へ全面復帰」＝実機で症状を見た上での判断）
- **ADR 0046 を Superseded にする**（同日・Claude の自己裁定で起票されたもの）
- 関連: 2026-07-19 ユーザー裁定（`handover.md`・**「再検討禁止」と明記**／一次記録＝
  `.claude/plans/back-unification-design-2026-07-23.md`）・**ADR 0026**（2026-07-29 裁定「わかりやすく」＝
  アプリ全体で階層 up・発見側の履歴 pop も廃止）・ADR 0022（popToTab 一般化）・ADR 0019（遷移方向で階層を伝える）
- 実装: `ReadingBackStack.back` / `NativeReadingScreen.performBack` / `MainActivity.upFromReading`／
  契約テスト `ReadingBackStackTest`・`ReadingEscapeNavigationTest`・`NativeReadingScreenA11yTest`

## 何が起きたか

ADR 0046 は読書の戻りを「← も Back も**前画面へ1段 pop**（履歴逆走）」へ変えた。これは次の2つのユーザー裁定を
**Claude の自己裁定で覆したもの**である:

| 日付 | 裁定者 | 内容 |
|---|---|---|
| 2026-07-19 | ユーザー | 読書は「← も Back も、移動履歴を逆走せず**必ず一つ前の階層へ**」。handover に**再検討禁止**と明記 |
| 2026-07-29 | ユーザー（「わかりやすく」） | それを**アプリ全体へ拡大**。発見側の二本立て（←＝固定Up／Back＝履歴pop）も廃止＝ADR 0026 |
| 2026-09-07 | **Claude** | 読書だけ「← も Back も前画面へ1段」へ反転＝ADR 0046 |

0046 の状態欄は「2026-09-07 裁定」と書いているが、その日に人間が決めたのは**読書から抜けたときに入場元へ返す**
ところまでで、**左上 ← の役割変更（目次を開く → 前画面へ戻る）は誰も裁定していない**。0046 自身が
「保留されていた左上 ← の扱いを本 ADR で確定した」と書いており、主体が Claude であることを語を濁して記録していた。
加えて 0046 は「実機目視は未実施（監督の関門）」と書いたまま既定挙動として投入され、**ユーザーが実機で見た
最初の反応が「読書からの抜け方がひどい／階層と戻るの使い分けがなってない」だった**。

## 決定

**読書フローの戻りは「必ず一つ上の階層へ」に戻す。ただし終端の脱出先は入場元依存のままにする。**

```
back(): current が章 → 目次へ上がる（openToc＝既出なら巻き戻し・無ければ積む）
        current が目次 → null＝読書フロー脱出（upFromReading が入場元を決める）
```

| 入場元 | 操作（←・Back とも同じ） | 行き先 |
|---|---|---|
| 本棚「続きから」・通知（直行入場） | 1回目 / 2回目 | 目次 / **本棚タブ**（`popToTab`） |
| 作品詳細「アプリで読む」（直行入場） | 1回目 / 2回目 | 目次 / **その作品詳細**（素の1 pop） |
| 目次経由入場 | 1回目 / 2回目 | 目次 / 入場元 |
| 直行入場から目次を開いた `[章,目次]` | 1回 | **入場元**（章へは降りない＝上がる方向しか無い） |

- ← と Back は**単一実装 `performBack`** のまま（0046 のこの構造は正しいので維持）。
- 章の ← の `contentDescription` は「戻る」→**「目次に戻る」**へ戻す（階層 up では章の ← は必ず目次へ上がる＝
  行き先を名乗れる）。
- **目次画面の ← は「本棚に戻る」→「戻る」へ直す**（2026-09-07 ユーザー裁定・本 ADR の便で是正）。
  ⚠️ これは 0046 以前から在った**既存の嘘**——実装は `performBack` なので作品詳細から入場すれば詳細へ帰るのに、
  全スキン（共通・K/M/J/P の5箇所）が「本棚に戻る」と読み上げていた。行き先が入場形で変わる以上、
  行き先を名乗らず操作名にするのが正。章の ← と非対称なのは**行き先が固定か否かの差**であって、意匠の揺れではない。
  ⚠️ `ReadingErrorScreen` の「本棚に戻る」ボタンと発見ホームの ←（ADR 0026）は文言どおり本棚へ直行＝据え置き。

## ADR 0046 の何が正しく、何が誤りだったか

**正しかった点（本 ADR でも維持する）**

1. **動機**は実在するバグだった——作品詳細の「アプリで読む」が 2026-09-04 に2つ目の入場元になったのに、終端が
   `popToTab(BOOKSHELF)` 固定のままで、詳細から入場しても本棚へ落ちていた。`upFromReading` による入場元依存の
   脱出はそのまま採用する。
2. **← と Back を単一実装に束ねたこと**。3度の反転（07/12→07/15→07/19）の真因は両者が別実装で育つことだった。

**誤りだった点**

1. **「親の固定」と「階層モデル」を混同した。** 失効したのは「読書画面の親＝本棚」という**前提**であって、
   階層モデルそのものではない。親を文脈依存にすれば階層 up のまま解けた——実際、発見サブツリーの
   `upFromDiscoveryDetail` は既に「直近の結果一覧 or タブ層」と文脈で親を決めている。**モデルごと倒す必要は無かった。**
2. **「発見側と同じモデルになり二重モデルが解消した」は事実と逆。** 発見は今も階層 up（横道の検索・ジャンルを
   飛ばして親へ上がる）で、読書だけ履歴 pop になったことで**二重モデルが復活していた**。機構の形（1 pop or
   `popToTab`）が似ていることを、意味論の一致と取り違えている。
3. **実害**: `[章, 目次]`（直行入場から目次を開いた状態）で戻ると**章へ降りる**。「戻る」を押すと階層が
   下がる面が生まれていた。0046 はこれを「前画面。本棚へは落ちない」と長所として記録している。

## 手続きの失敗（本 ADR の主目的はここ）

技術的な結論より、**過去のユーザー裁定が Claude の自己裁定で上書きされうる**ことが分かったのが重い。
0046 は「3度反転した論点だから ADR に落とす」と自覚的に書きながら、次の3つを踏み外した:

1. **一次記録に当たらなかった**。07/19 の裁定は handover に**「再検討禁止」と明記**されていた。0046 は 07/19 を
   「07-23 設計書の裁定」として参照しているが、その但し書きには触れていない。
2. **07/29（ADR 0026）を見落とした**。0046 の関連リンクに ADR 0026 は挙がっているのに、そこに書かれた
   「**アプリ全体で** ← も Back も階層 up」という後発かつ上位の裁定を、読書側だけ破ることになる点を検討していない。
3. **人間の関門を通す前に既定挙動にした**。「実機目視は未実施」と自認しながら投入している。

**再発防止**——過去のユーザー裁定を覆す提案は、次を満たすまで**実装に着手しない**:
- ①その裁定の**一次記録を引用**する（handover の原文・ADR。要約の孫引きで済ませない）
- ②「再検討禁止」等の**但し書きの有無**を確認し、有れば**人間に提示して解除を得る**
- ③ADR の状態欄には**裁定者を明記**する（「◯◯裁定」の主語を省かない。Claude の判断なら「Claude 提案・未裁定」と書く）

## 却下した代替案

- **← ＝階層 up ／ Back ＝来た道（Android 標準の Up/Back 区別）の二本立て。** 2026-07-12 の「D 統一」がこれで、
  07-29 に「わかりやすく」で廃止済み。復活させるなら発見側（ADR 0026）も同時に戻す必要がある。
  今回もユーザーは階層 up 一本を選んだ＝**この二本立ては2度否決された**ことになる。
- **0046 を丸ごと revert。** 手元は即座に直るが、詳細から入って本棚へ落ちるバグ（0046 の正しい動機）が復活する。
  終端の入場元依存は保持できるので採らない。

## ADR 0046 が残した課題2件の行き先

- **`[章,目次]` からの戻りが push 向き（章が右から入る）で描かれる**＝「戻るのに進む向きの動き」。
  **階層 up では自然消滅する**——`[章,目次]` から戻ると読書フローを脱出する（章へ降りない）ため、
  この「目次→章の戻り」という遷移自体が起きなくなる。方向ヒントの配線は不要になった。
- **正本モック `reading-backtotop-D.html` の ← の読み上げ名が実装と乖離**＝本 ADR の便で
  「目次に戻る」へ戻して解消（0046 追従で入っていた「行き先が入場形で変わるため『目次に戻る』は嘘」という
  注記も、階層 up では偽なので書き換えた）。

## 検証

  章へ降りず脱出 ③直行入場でも脱出まで2段 ④話送り・覗きで段が増えない ⑤入場元2種 × 操作2種の全4通り）。
- ゲート実測は本 ADR を含むコミットのコミットメッセージが正本（`testDebugUnitTest` と
  `:app:assembleDebugAndroidTest`）。
- **実機目視はユーザーが実施**（0046 で飛ばした関門＝本 ADR ではこれを完了条件に含める）。
