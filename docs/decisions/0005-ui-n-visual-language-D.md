# 0005. UI-n の視覚言語に D「和モダン・余白」を採用（＋白紙設計のスコープと Why-not）

## Context（背景）

`UI-n` は既存 UI の見た目を保守チューニングするのではなく、**思想設計の段階から白紙で作り直す**ための破壊可能ブランチとして立てた（前版=保守チューニング指示書からの方針転換）。見た目（静的視覚）の正本を Claude Design（HTML デザインシステム）で立て、それを Claude Code が Compose へ翻訳する分業ワークフローを採った。

フェーズ0で「美学は指定せず与件だけ渡して複数案を出させる」方針のもと、本棚を A〜J の10案までモック化し、横並びで人間が目視選定した（2026-06-26）。その選定結果と、白紙設計に**含めない**領域の線引き、スキン機能の扱いを、恒久的な設計判断として本 ADR に固定する。

## Decision（決定）

### A. デフォルト視覚言語 ＝ D「和モダン・余白」

寒色の白×藍 `#1C3D5A` のヘアライン×青磁 `#9CB3A8`、余白主導の静かなエディトリアル。本文＝明朝／ラベル＝ゴシック。書影＝静かな縦グラデ＋縦の藍ルール（実画像を捏造しない）。3読書テーマ（ライト／セピア／ダーク）へ展開する。

**なぜ D**: 「ユーザーが長時間落ち着いて読む」用途に最も素直で、奇をてらわず可読・静謐。3読書テーマへ展開しやすい寒色基調。斬新案（H 栞と小口／I 読書の旅路／J ポータルデッキ）は魅力的だが、日常的に使う本命の土台としては D を採った。

### B. 白紙設計のスコープ（見た目のみ。機能は対象外）

白紙にするのは配色哲学・タイポ階層・余白/構図・コンポーネントの設計言語・画面構造のレイアウトのみ。操作感・組版の質感・アニメーション・没入クロームの挙動は今回のスコープ外（HTML→Compose で最も劣化する層＝実機フィードバックで後詰め）。

### C. スキン着せ替え（A〜J 選択）は当面実装しない

D をデフォルトとし、作成した A〜J 全案は「UIスキン」資産として claude.ai/design に保持する。ただし**ユーザー指示（2026-06-27）により、スキン着せ替え機能はまだ実装しない／main は現状 D のみ**。選択 UI・切替粒度（アプリ全体スキン or 画面ごと）の設計は、機能着手時まで延期する（進捗・再開点は `handover.md` A2 が正本）。

## Consequences（結果と制約）

- D は Compose へ実装済み（上記 関連コミット）。色は必ず `Color.kt`/`Theme.kt` 経由・直書き禁止、明朝は `Typography.kt` の `MinchoFamily` 経由という**トークン構造は維持**する（白紙設計はトークンの中身を変える作業で、トークン経由という構造は不変）。
- 残るのは任意の微調整（スライダー目盛り等）とスキン機能の将来送りのみ＝`handover.md` A2。
- A〜J のモック署名要素の索引はアーカイブ `.claude/plans/UI-n_DESIGN_PLAN-archived-2026-07-02.md` §6.1 に保全（スキン機能着手時の一次情報）。

## Alternatives（採用しなかった案と理由）

- **横書きルビ組版を白紙設計の対象に含める**: `ui/compose/RubyText.kt`＋`RubyLayoutHelper.kt` は AnnotatedString＋Canvas 重ね描きで禁則処理込みの組版エンジン。**移植リスクが大きく、かつ「機能」であって「見た目」ではない**ため対象外とした。PDF処理パイプライン・DB・Service 層も同理由で対象外。
- **斬新案（H/I/J）をデフォルトに**: 世界観は魅力的だが長時間読書の本命の土台には向かないと判断（→ D 採用）。C・F も最終候補に残したが、A〜J 全案はスキン資産として保持する形で決着。
- **スキン着せ替えを即実装**: 選択 UI・切替粒度・スキン×読書テーマの関係設計が必要でスコープが膨らむため、ユーザー判断で将来送り（上記 C）。
