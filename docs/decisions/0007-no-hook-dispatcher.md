# 0007. コミット系フックは個別プロセス構成を維持する（単一ディスパッチャ不採用・共有は定義モジュールのみ）

- ステータス: Accepted
- 日付: 2026-07-07
- 関連実装: `.claude/hooks/hooks_common.py`（共有定義）/ 各コミット系フック / `.claude/hooks/test_hooks.py`（identity テスト）
- 関連コミット: `e4ff7f7`（共有モジュール化）, `6031eba`（stdout 不達の横展開修正）

## Context（背景）

メタ監修レビューで「Bash 1回につき PreToolUse/PostToolUse の Python プロセスが**直列**で複数本走りレイテンシを足すため、単一ディスパッチャ（1つの python が stdin を読み、コマンド種別で各チェック関数へルーティング）へ統合すべき。COMMIT_CMD_RE の複製問題も consolidation で消える」と提案された（実配線は Bash 1回で Pre 6本＋Post 3本＝9本）。

事実確認（公式 hooks-guide・2026-07-07）の結果、提案の前提が公式仕様と異なった:

- **同一イベントにマッチした複数フックは並列実行**。レイテンシは「本数×単価」ではなく「最遅フック＋プロセス spawn」で決まる。
- 出力のマージはホスト側が行う: PreToolUse の permission decision は**最も制限的な回答が優先**（deny > defer > ask > allow）。`additionalContext` は**全フック分が連結**されてモデルへ渡る。1フックの deny は兄弟フックの実行・副作用を止めない。
- **タイムアウトはフック単位**（command 型の既定 600 秒・フックごとに個別設定可）。
- 公式はディスパッチャ統合を推奨しておらず、むしろ**個別フック＋ `if` フィールド**（v2.1.85+・ツール名/引数で起動前フィルタ）の方向を示す。
- 実測（WSL/ext4・2026-07-07）: PreToolUse 6本並列で **38ms**（単発 28ms）＝非コミットコマンドの早期 return 経路では体感ゼロ。

一方、レビューが指摘した **`COMMIT_CMD_RE`/`COMMIT_GENERATING_RE` の6フック複製は実在する問題**だった（旧設計＝意図的複製＋ `test_hooks.py` の pattern 一致テストで乖離検知）。

## Decision（決定）

1. **フックは1機能=1プロセスの個別構成を維持**し、単一ディスパッチャへ統合しない。
2. 複製問題は**共有定義モジュール `hooks_common.py`** への抽出で解消する（検知正規表現2種＋stdin 読取・UTF-8 張替えのボイラープレート）。
3. `test_hooks.py` は「複製の pattern 一致テスト」から「**identity テスト**」（各フックを exec して回収した正規表現オブジェクトが hooks_common のものと `is` で同一）へ置換し、ローカル再定義の混入を構造的に検出する。

## Consequences（結果と制約）

- 検知正規表現の変更は `hooks_common.py` の1箇所で済む（guard↔consume の検知整合も構造的に担保）。
- 1フックのクラッシュ・例外が他のガードを道連れにしない（プロセス隔離維持）。フック単位の timeout・`/hooks` メニューでの個別デバッグも維持。
- 新制約: フック単体ファイルだけを他ブランチへコピーすると hooks_common が無く ImportError でフックごと落ちる（git 上は常に同居するため通常運用では起きない）。
- ADR 0004 の既知課題 (a)（セッション内ブランチ跨ぎの file-not-found）は本件では解決しない別課題のまま。旧ブランチが 2026-07-06 の統合で全削除され発生条件が薄いため据え置き。

## Alternatives（採用しなかった案と理由）

- **単一ディスパッチャ統合**: 前提（直列実行）が公式仕様と異なりレイテンシ利得がほぼ無い。1バグで全ガード（ブランチ保護・テストゲート・センチネル消費）が同時沈黙する SPOF を新設し、このプロジェクトが最も警戒するサイレント失敗クラス（task_diary #26/#28 と同系）を太らせる。deny/additionalContext/exit code のマージをディスパッチャ内で自前再実装する必要も生じ、ホスト側のマージ仕様と二重化する。不採用。
- **現状維持（意図的複製＋一致テスト）**: 乖離は検知できるが「6箇所更新→更新漏れ→テスト失敗→再更新」の往復コストが変更のたびに発生する。定義の単一化で構造ごと解消できるため置換。
- **`if` フィールドによる起動前フィルタ**: 並列＋早期 return で実測 38ms のため現状は不要。フック本数が増えて spawn コストが顕在化したら再検討する（その場合も統合ではなくフィルタが先）。
