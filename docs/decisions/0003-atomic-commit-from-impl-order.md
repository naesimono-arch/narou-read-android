# 0003. Atomic Commit は実装順序から設計する

> 旧 `task_diary.md` §20（設計判断・運用メモ）

**Status**: 運用ルールとして採用

## 判断

複数コミットに分けることを事前に決めていた場合は、**コミット単位に合わせた実装順序**で進める。
（例: まず ③④ のファイルのみ変更してコミット → 次に ⑦ のファイルを変更してコミット）

## 理由

後から `git add -p` で分割しようとすると、異なる変更が同一ハンクになって分割不能になることがある。コミット境界を実装の順序に先取りで反映させておけば、ハンク分割に依存せず素直に Atomic Commit できる。
