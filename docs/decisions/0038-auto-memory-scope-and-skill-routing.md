# 0038. auto-memory の役割を「環境の事実」へ縮小し、行動規範は skill へ一本化する

- 状態: **Accepted（2026-08-25）**
- 関連: ADR 0017（台帳の役割分離）／ADR 0028（待ちの種類で二分）／ADR 0030（「読ませる」でなく機械で止める路線）／
  `docs/knowledge/tooling-no-grep-glob-tools.md`（**書かれた作法が実行系に存在しない**という同型の失敗）

## 経緯

ユーザー指摘「最近 memory にあるのに忘れる、というのが起きた」。
棚卸し（陳腐化・圧縮・不要の整理）の前に、まず**なぜ忘れるのか**を実測した。
結論から言うと**量の問題ではなく到達経路の問題**で、圧縮は効かない。

## 判断材料（2026-08-25 実測・当時 memory 46 件 / 71,412 字）

1. **自動注入されるのは索引 `MEMORY.md`（4,729 字）だけ**。個別ファイル（66,683 字＝**93%**）は載らない。
2. **memory を検索・読み出す専用ツールは存在しない**（ToolSearch で全滅）＝開く手段は Read/cat のみ。
   にもかかわらず索引の冒頭は「詳細は各ファイルを **recall で読む**」と書いていた＝
   **実行系に無い手順を指す空手形**（Grep/Glob ツール不在と同型）。
3. **46 件中 21 件は索引以外のどこからも名指しされていない**（skill・CLAUDE.md・docs を全数 grep）
   ＝到達経路が索引の 1 行しかない。
4. **索引の 1 行が「結論」を書くので開かれない**。しかも索引は本文と乖離しうる——
   `wsl-debug-keystore-share-for-install` は本文冒頭が「⚠️ **この手順をそのまま実行してはいけない**」
   （ユーザー名移行で Windows/WSL の鍵が md5 不一致）なのに、**索引の 1 行は当のコピー手順を推奨し続けていた**。
   常時載るのは索引だけなので、**索引の腐りはそのまま事故になる**。
5. **CLAUDE.md と memory が矛盾すると、全文が載る CLAUDE.md が勝つ**。実例＝CLAUDE.md「`git commit` 前に
   承認を得る」vs memory「2026-07-23 コミットは都度 OK」。**新しい裁定（memory 側）が死んでいた**。
6. **skill は既に memory の内容を大量にコピーしていた**（`/build` の非ASCIIパス節・`/orchestration` §5 の
   中断閾値など）＝二重管理が進行中で、これ自体が乖離の温床だった。

## 決定

1. **行動を変える規範は skill 側に置く**。skill は description による**自動起動を持つ唯一の層**で、
   CLAUDE.md の必須ゲートが起動を強制している。memory にはトリガー機構が無い。
2. **auto-memory に残すのは「環境の事実」と「一次情報の所在」**（ブランチ不変であることは従来どおり前提）。
3. **索引の各行は「結論」でなく『開く合図』を書く**——skill の description と同じ設計にする。
   結論を書くと「読んだ＝知った」で本文に到達しない。
4. **受け皿が既に全内容を持っているものは削除する**（二重管理を残さない＝乖離の芽を断つ）。

## Why-not

- **索引の書式だけ直す**: 21 件の到達経路が索引の 1 行のままで、合図を書いても**該当場面で索引を読み返す
  保証がない**。skill は場面で自動起動する＝経路の質が違う。
- **memory を分野別 skill へ分割**: description 予算と保守税。`claude-bestpractice/personal-ops-evolution.md`
  で既に不採用済み（単一 skill ＋内部ルーティング表で同じ遅延読込が成る）。
- **SessionStart hook で関連 memory を注入**: 常設コストが乗る（台帳だけで Read の 34% という実測＝
  `docs/knowledge/context-cost-breakdown-2026-08-10.md` に逆行）。加えて ADR 0030 の
  「注入は**読まれること**に賭ける」弱点をそのまま引き継ぐ。
- **索引に本文を全部載せる**: 常時注入が 71,412 字へ膨らむ。上限を字数で縛る台帳運用（CLAUDE.md）と矛盾する。

## 帰結

- memory **46 → 19 件**（71,412 → 39,653 字）・索引 4,729 → 3,371 字。移設先＝`/visual-language`（UI の恒久裁定）・
  `/device-verify`（実機着手前の関門・破壊フロー禁忌・release R8 手順）・`/orchestration`（機械バッチの較正・
  resume のモデル継承・重いジョブ直列化・モデル解決順）・CLAUDE.md（コミット規約の矛盾解消）。
- 削除で切れる参照は ADR・patterns・task_diary・androidTest コメント・memory 内リンクを移設先へ張り替え、
  **リンク切れゼロを機械確認**した（索引と実体の双方向突合も同時に実施）。
- ⚠️ **memory は git 管理外＝削除しても履歴から戻せない**。棚卸しでは削除前に scratchpad へ tar で
  バックアップを取ること（今回実施）。CLAUDE.md の「git 管理下の削除は復元可能」はここには当てはまらない。
- **新規に memory を書くときの判定＝「これは行動を変える規範か、環境の事実か」**。
  前者なら memory ではなく該当 skill の本文へ書く。
