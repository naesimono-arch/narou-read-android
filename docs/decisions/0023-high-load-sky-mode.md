# 0023: 高負荷スカイモード（美しさ特化・負荷許容）と実機先行探索の例外

- 日付: 2026-07-19
- 状態: 承認（ユーザー裁定・リッチ化ラウンド）
- 関連: 0005（HTMLモック正本・§B実機後詰め層）・0014（正本の層構造）・0022（§3 モーション裁定）

## 決定

1. **「高負荷モード」をプロダクト概念として導入する**: 描画の美しさに特化し、ある程度の描画負荷を許容するモード。
   展開方針（2026-07-19 ユーザー裁定で追記）: **星図Mで軽く作成→その知見を和モダンDへ→以降、各UI・各画面へ順次展開**
   （深追いせず段階的に。事前準備は実機時の AGSL 可否確認と jank% ベースライン採取のみ）。実装は debug トグルから始め、
   製品トグルの置き場所・既定値（OFF想定）・reduce-motion との優先関係は試作の実機評価後に確定する。
2. **この領域では「HTMLモックが正本」原則の例外を認める（ユーザー裁定）**:
   高負荷スカイの探索対象（加算合成・シェーダー・多深度視差・微細階調）は HTML では再現できず
   ADR 0005 §B の「実機後詰め層」に該当するため、**Compose 側の debug トグル試作→実機で直すループを正本探索とする**。
   HTML はコンセプトボード（静的な構図・色・思想一行の確認用。描画品質は追い込まない）まで・省略も可。
   確定した意匠の記録先（正本モックへの反映 or 本ADRへの追記）は確定時に決める。黙って原則を崩さない＝本ADRが根拠。
3. **新規モーションの裁定手順の差し替え（この領域限定）**: ADR 0022 §3 の「モックに先に入れて裁定」は、
   高負荷スカイでは「**実機トグルで先に見せて裁定**」に置き換わる。裁定の主体がユーザーである点は不変。
4. **限度のゲートは残す**: 高負荷といえど jank% 実測（gfxinfo）を試作評価のゲートに含める
   （体感もっさりの握りつぶし禁止＝memory `feedback-perf-jank-is-real-signal` と同根）。閾値は試作時に基準機で採取して定める。

## 背景（Why）

リッチ化ラウンドで天の川3案（構造/色彩/解像）を全合成してもなお「立体感が足りない・表面的・重心がない」
というユーザー所感。プラネタリウム級の美しさの追求には加算合成・オフスクリーン事前描画・多深度視差・
AGSL 等 Compose でしか試せない技法が必要で、HTML モックで追い込むと二重作業かつ翻訳劣化で判断を誤る。

## Why not（不採用の選択肢）

- **HTML モックで高負荷表現まで追い込む**: canvas 2D は加算合成の実際の見え・シェーダー・OLED バンディングを
  再現できない＝モック上の合否が実機の合否を予測しない。
- **通常モードの空をそのまま重くする**: 性能規律（DeepSkyM 基準）と美しさ追求が同じ土俵で衝突し続ける。
  モード分離により通常モードの規律は不変のまま探索できる。
