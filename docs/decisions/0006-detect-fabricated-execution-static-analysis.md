# 0006. 実行捏造ハルシネーションのトランスクリプト静的解析検知（スコープと Why-not）

- ステータス: Accepted
- 日付: 2026-07-05
- 関連実装: `.claude/hooks/detect_fabricated_execution_core.py`（エンジン）／`.claude/hooks/analyze_transcript.py`（CLI 事後アナライザ）／`.claude/hooks/test_detect_fabricated_execution.py`（単体テスト）
- 関連コミット: `ffe5b35`（エンジン＋テスト）／`1beff15`（CLI）／`5059a7f`（精度改善＋Tier A3）
- 検証データ: `docs/reference/hallucination-ground-truth.md`（既知の実ハルシネーション正解データ・4事象）

## Context（背景）

Claude が地の文（assistant の `text` ブロック）で「テストを実行して通った」「コマンドを走らせた」等の**実行報告**をするが、それを裏付ける本物の `tool_use`/`tool_result` ペアがトランスクリプト（JSONL）に存在しない — ＝**実行の捏造・未検証の完了主張**というハルシネーションが実際に発生していた（`docs/reference/hallucination-ground-truth.md` 事象 D・c2e7a254 等）。これを機械的に検知したい。

構造的に検知可能なのは、Claude Code のアーキ境界による：**`tool_result` ブロックはハーネスが著者／地の文はモデルが著者**であり、捏造は必ず text ブロック内の作文に留まる（対応する `tool_use`/`tool_result` が JSONL に生成されない）。よって検知は意味理解ではなく `tool_use.id ↔ tool_result.tool_use_id` の 1:1 照合に還元できる。

## Decision（決定）

トランスクリプト JSONL を静的解析する検知器を、**純ロジックのエンジン＋薄いアダプタ2つ（CLI／将来の Stop フック）**で実装する。中核方針と主要判断は以下。

1. **assistant の text は一切証拠にしない**。text は「主張の抽出元」にのみ用い、真偽の証拠は `tool_result`／`toolUseResult`／ユーザ人間入力／サブエージェント JSONL のみ。捏造は定義上 text 内にしか無いという構造を前提にする。

2. **精度最優先（低再現率を許容）**。曖昧なものはフラグせず、確証が持てない場合は `suppressed`（降格）として Stop ブロック対象から外す。実データ検証で偽陽性 34→1（真陽性）まで絞り込み、この方針の妥当性を確認した。

3. **検知の3層**（`docs/reference/hallucination-ground-truth.md` 検証で確定・調整）:
   - **Tier A1**: 端末風フェンス出力なのに同一発話に `tool_use` が無く証拠にも由来しない。
   - **Tier A2**: git 文脈で存在しない commit SHA を断言（ファイルパス・行番号は偽陽性源なので**対象外**）。
   - **Tier A3**: ハーネス専用ブロック（`user<background-task-status>` / `<task-id>` / `<exit-code>` / `<invoke name=` 等）の**地の文化**。正解データ検証で判明した最重要ケース（Claude が偽の会話継続・偽のツール呼び出しを自作）に対応して**後から追加**した。
   - **Tier B**: テスト成功の断言に対応する成功実行がセッション内に無い。**具体値主張（「28件 OK」等）はその具体値が実出力に在る時だけ裏取り**し、汎用の過去実行では免罪しない（事象 D の偽陰性対策）。

4. **Tier C（意味照合・LLM ジャッジ・ML）はスコープ外（Why-not）**。正解データの事象 A（存在しないユーザ指示の捏造引用）・B（生成 HTML の id 重複）・C（実在しない GitHub リポ調査の捏造）はいずれも「実行捏造」ではなく帰属誤り・コード不具合・外部リサーチ捏造という別クラスで、静的照合では扱えない。これらを取るには帰属根拠照合・コード正当性・リサーチ根拠照合という別系統の検知器が要る。本検知器は**構造的に高精度で取れる一クラスに集中**し、他クラスには手を出さない。

5. **Stop フックは advisory 注入ができない（Why の帰結）**。PostToolUse と違い Stop フックは `additionalContext` を持たない（task_diary #28）。よってライブゲートは「**ブロックして自己修正させる**」か「**素通し**」の二択に割り切る。ヒューリスティック起因の偽陽性で作業を止める危険があるため、**ブロックは Tier B の三証人一致（成功 tool_result なし ∧ センチネル不在/古い ∧ 非降格）で `confidence≥0.8` のみ**。降格・低信頼シグナルは CLI 側のレビューに委ねる。

6. **段階導入**: CLI 事後アナライザを第一デリバラブルとし（非ブロック・配線ゼロ）、実データで精度を検証してから Stop フックを配線する。

## Consequences（帰結・既知の盲点）

- **既知の盲点（＝降格 or 取りこぼし）**:
  - **オフロード truncation**: 大容量出力は `<session>/tool-results/<id>.txt` に退避され本文が 2KB プレビューに置換される。全文を解決できない時は該当 finding を `suppressed=truncation` で降格する。
  - **サブエージェント委譲**: 委譲先の実行実体は `<session>/subagents/agent-<id>.jsonl` にあり、読めない時は関連 Tier B を降格し blind_spot に記録。
  - **Tier B の「早期実行による免罪」**: 具体値主張は具体照合に限定して緩和したが、汎用主張は「セッション内に成功実行が1回でもあれば免罪」のままで、汎用の後半捏造は取りこぼしうる。
  - **クロスセッション参照**: 別セッションで実行した結果を要約参照する主張は、当該トランスクリプト単体では裏取りできず偽陽性化しうる（Stop フックは現行セッションのみ対象なので実害小）。
  - **PowerShell 経由・ブランチ跨ぎ**: Stop フック配線は `matcher` の制約と、settings.json がブランチ追従しない一方フック実体は追従する非対称（ADR 0004）を継承する。実体は transcript 不在・例外で常に `exit 0`（非妨害）。
- **配置**: エンジン・アダプタ・テストは repo `.claude/hooks/`（`test_hooks.py` 方式の回帰をチーム共有・CI 化するため）。CLI は機械固有パスを引数化して repo-safe。大ファイルは既定 8MB 超をスキップ＋明示警告（WSL/drvfs での CPU・メモリ爆食いを防ぐ実害対策）。
- **正解データでの再現率**: 4事象中スコープ内は D のみで、D はセッションを検知（告白文経由）。A/B/C は設計どおり非検知。詳細は `docs/reference/hallucination-ground-truth.md`。

## 増補（2026-07-07）: Tier C＝misread 型の新設と証拠の層別化

正解データ事象F（main統合セッションの実行捏造5件）で、**「ペア欠落」前提の構造的盲点**が実証された:
tool_use/tool_result のペアは実在するのに、**地の文の報告が実 result と食い違う**（misread 型）。
v1 は 5件全てを空振りした。空振りの機序は2つで、いずれも「意味理解の欠如」ではなく照合設計の穴だった
——だから静的照合の延長で対処できた（本 ADR の「高精度で取れる一クラスに集中」方針は不変）。

1. **証拠の自己汚染（事象F②）**: 捏造 SHA を自分で `git show <捏造SHA>` と調査すると、コマンド入力
   （`tool_use.input`）とそのエコーバック／git エラー（`fatal: ambiguous argument …`）が証拠コーパスに
   載り、捏造トークンが**自己免罪**される。→ 証拠を2層化: 存在照合（SHA・出力シグネチャ）は
   **result 層**（tool_result 本文からエコーバック行＝入力に exact 出現するトークンを含む行を除去し、
   ユーザ入力・コンパクション summary を加えたもの）のみで行い、`tool_use.input` は含めない。
   `git show <短縮SHA>` が出すフル SHA 行は入力と exact 一致しないため証拠に残る＝実在 SHA は壊れない。
2. **文脈語の欠落（事象F①）**: 「マージ完了（`SHA`）」は旧 GIT_CONTEXT_RE（コミット/commit/ハッシュ等）
   を含まず素通り。→ マージ/merge/ブランチ/push 等へ拡張（SHA 正規表現との共起前提なので偽陽性は
   増えにくい）。

**Tier C（4ルール・すべて「操作カテゴリ別の物証」の存在照合）**:
- `completion_after_blocked_commit`（F①）: フックにブロックされた `git commit/merge`（コマンド判定は
  hooks_common の単一定義を流用＝ADR 0008（旧0007））が、成功の再試行なしに「完了」報告される。
- `fabricated_output_signature`（F④）: git 実出力にしか現れないシグネチャ（`[deleted]`・`Deleted branch`
  等）の引用が、主張以前の実 result のどこにも無い。
- `unverified_write_claim`（F⑤）: 対象を特定できる「書き込み完了」断言（ファイル名明示 or auto-memory）
  に、対応する書き込み tool_use（Edit/Write/NotebookEdit/書き込みうる Bash）が主張以前に無い。
  対象を特定できない汎用主張は検査しない（精度優先）。
- `unverified_branch_delete_claim`（F③）: ブランチ削除の完了断言に削除の実出力が無い。
- **時系列照合**: 存在照合は「主張**以前**の証拠のみ」で行う。捏造の後で同種操作を本当にやり直す
  （自己訂正する）と、全域照合ではその実出力が過去の捏造まで免罪してしまう（F③④の v1 空振りの第2機序）。

**付随判断**:
- **A2 を Stop ブロックへ昇格**: 上記の層別化・文脈語拡張後、全106セッション走査で偽陽性ゼロを確認。
  「存在しない SHA の断言」は実 SHA の確認による自己修正が可能なので、ライブゲート対象に含めた
  （v1 の「A1/A2 はブロックしない」を A1 のみに変更）。
- **Tier B の gradle 件数免罪**: gradle は成功時に件数を出力しない（`BUILD SUCCESSFUL` のみ）ため
  「N件通過」型主張の件数 grounding が構造的に不可能＝実データで偽陽性化（c05efed0）。セッション内に
  gradle 成功実行が在れば件数のみの主張は免罪する（順序不問なのはクロスセッション引き継ぎ要約のため。
  Stop フックは scope=last_turn なので「実行前の完了主張」を live で止める力は不変）。
- **C1 のメタ議論除外**: 「コミット完了待ち」「『commit』了解しました」「マージ完了後の…」等の
  時点表現・状態記述・指示復唱は完了の断言ではない（実データ偽陽性4件から語彙を固定）。
- **呼称の整理**: v1 §4 の「Tier C（意味照合・LLM ジャッジ）はスコープ外」で予約していた "Tier C" は、
  本増補で **misread 型静的検知に割り当て直した**。旧構想（帰属誤り・生成コード不具合・外部リサーチ捏造
  ＝事象A/B/C系）は「**別系統検知器（D系）**」と呼び、引き続きスコープ外。
- **事象E（対話文脈の捏造）は静的照合では原理的に取れない**が、**LLM 意味照合（agy への read-only 監査
  委譲）で検知可能なことをブラインド実証済み**（2026-07-07・agy flash が正解非開示で L99 をピンポイント
  特定・誤検出ゼロ）。ライブゲートには不向き（レイテンシ）なので事後監査として運用する——定型手順は
  `docs/reference/hallucination-ground-truth.md` 冒頭の追記手順に統合。
- **既知の限界（追加）**: 本検知器の開発作業自体（検知語彙を地の文で議論するメタセッション）は
  偽陽性源になりうる（実害があれば suppression を検討）。

## 増補2（2026-07-07）: Tier D＝入力側捏造（phantom user input）の新設

正解データ事象H・I（wt:api-lab-ai の Opus 4.8 2セッション）で第3の構造的盲点が実証された:
**存在しないユーザー発話を捏造し、それを根拠に行動する**（幻の叱責への謝罪・不存在発話の
引用符付き“引用”・幻の不具合報告を根拠にした指示違反ピボット＋委譲文への二次伝播）。
既存 Tier は A/B=実行捏造・C=misread と全て**出力側**（実行報告⇄実結果）の照合で、
**入力側**（ユーザーが言っていないことを言ったことにする）は v1/v2 とも 0 件＝カバー外だった。

**検知原理**: アシスタント発話中の〈ユーザー発話への言及・引用〉を抽出し、**実在する人間入力**
（user human 入力［task-notification 等ハーネス著者の user-str は除外］／`queued_command`
attachment の `origin.kind=="human"`／AskUserQuestion の回答 tool_result／コンパクション
summary）と突合する。実装は `collect_human_inputs()`＝突合正本。

**Tier D（3ルール）**:
- `fabricated_user_quote`（D1・事象H③）: 「あなたが「X」と言った」型引用の X が全人間入力に
  無い。引用は実発話の部分文字列のはずなので正規化部分一致で存在照合できる（内容突合＝強）。
- `fabricated_user_report`（D2・事象I①）: 「そちらの①」「という報告がある」等の
  〈ユーザー由来の新情報が存在する〉主張マーカーを含む発話の**重要数値**（2桁以上 or 小数）が、
  人間入力にも**主張以前の** result 層にも無い。数値は発話全体から取る（較正実測: マーカー文と
  数値文が離れる）。result 層も突合に加えるのは「実出力由来なら誤帰属でも捏造ではない」の精度
  優先。1桁整数を外すのは「コミット後5へ」の指示番号が幻の「5〜6件」と衝突して誤免罪した較正
  実測から。時系列条件（主張以前のみ）は Tier C と同じ設計。
- `phantom_user_response`（D3・事象H②）: 発話冒頭の同意・謝罪マーカー（「その通りです」
  「申し訳」）なのに直前入力区間（前の assistant 発話以降）に人間由来入力が無い。**単独では
  suppressed**（自己訂正の謝罪等の正当形と構造上区別しきれない）とし、軸2の共起時のみ active。

**軸2（thinking 異常）を単独検知ルールにしない判断（Why-not）**: G/H/I に共通して幻テキスト
直前の thinking signature 長がセッション通常比 5〜30 倍という前兆が観測されたが、較正実測で
（a）中央値×5 ルールは正当な突合作業（94a08b11: 中央値 1,932・×5超が10件）で誤発火、
（b）絶対閾値 30K は事象 I=33,976 と余白 4K、（c）正当作業でも 37K 超が出る（b8b8b382 の
JSON 突合＝直前に実 AskUserQuestion 回答あり）。よって軸2の役割は**D3 の active 昇格条件**
（＋D1/D2 の confidence 微増）に限定する。baseline は「当該発話より前の発話の sig 長の p25
（n<4 は最小値）」: 暴走 thinking は連続する（H は 165K/172K 連続）ため中央値は自己汚染し、
p25/最小値が頑健。閾値は `sig ≥ max(15000, baseline×8)`。signature 文字長は thinking トークン
数の**代理指標**（単位が違う）であり、較正・閾値は sig 長で統一する。

**較正で確定した除外・降格（すべて実データの偽陽性から採取）**:
- メタ議論降格 `meta_discussion`: 本リポジトリは幻覚台帳・検知器を扱うため、**実例の引用が
  最大の偽陽性源**（94a08b11 の分析セッションが台帳 H/I の引用で誤爆）。メタ語彙（捏造・幻覚・
  不存在・全記録…）が近傍 or 発話全体で3回以上なら降格。§「既知の限界」の実体化。
- クロスセッション参照降格 `cross_session_reference`: 「あなたが「…」と指示したセッション」
  （6bb04439）は当該 transcript 単体で裏取り不能＝既知盲点と同型。
- 「あなたの指摘どおり」系を D2 マーカーに**含めない**: パラフレーズされた同意は内容突合が
  構造的に不可能で、実在指摘への正当応答（160153ad L717）が偽陽性化した。この帰結として
  事象H①（L43「ユーザーの認識どおり」＝文脈捏造）は**取れない**（台帳も「難度高・加点」扱い。
  取ると正当応答の偽陽性と引き換えになるため精度優先で見送り）。
- 受諾系「了解しました/承知しました」を D3 マーカーに**含めない**: 較正ヒット54件の大半が
  ツール実行を挟んだ指示への正当応答＝情報量ゼロの偽陽性源。

**較正結果（slug 全128ファイル・8MB超7本も個別走査）**: active＝4件で全て真陽性
（H L58/L70・I L132・**新規発見 177f88f3 L195**＝Edit 成功直後に「…ご指摘の通りです。完全に
順序を間違えました」と不存在の指摘へ謝罪・「実機でずれている」の確認報告も後刻まで不存在・
sig 37,932＝baseline 23倍。2026-07-07 人間レビューで実幻覚と確定し**台帳 J 事象**として登録
＝検知器起点で台帳入りした初の事象・入力側捏造の初出は H/I の5日前＝2026-07-02 に遡ると判明）。
偽陽性 0。suppressed 8件も全て
意図どおりの降格。既存 A/B/C の判定は全セッションで不変（E/F/G 含む）。

**呼称の整理（増補1の「D系」を廃止）**: 増補1で「別系統検知器（D系）」と予約した旧構想のうち、
帰属誤り（事象A系＝存在しないユーザ指示の捏造引用）は本増補2の **Tier D（入力側捏造）が静的
照合で部分カバーする形に昇格**した（引用構文・数値という突合可能な形に限る。パラフレーズは
引き続き不能）。残るスコープ外（生成コード不具合・外部リサーチ捏造＝事象B/C系）は、Tier の
文字と衝突するため今後「D系」と呼ばず「**意味照合系検知器（スコープ外）**」と呼ぶ。

**段階導入の踏襲**: Stop フックへの Tier D 昇格は未実施（`stop_guard_fabrication.py` は
`tiers="ABC"` を明示指定済みで影響なし）。CLI 事後アナライザでの運用実績を見てから判断する
（§6 の方針どおり）。エンジン既定と CLI 既定は "ABCD"。

## 増補7（2026-07-16）: Tier E3「先行実行フレーミング」新設（L44/L55 型＝増補6 残課題①の消化）
