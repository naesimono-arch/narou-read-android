# 監督ゲートが Gradle のキャッシュで空回りする＝テストを1件も走らせずに緑が返る

★★★ / 2026-08-25 / サブの直後に監督が同じテストを回しても `FROM-CACHE` で数秒の緑が返るだけ＝「独立に確かめた」ことにならない。

## 症状

`/orchestration` の規約「**自己申告 GREEN は信じず、ゲートは監督が自分で再実行する**」に従って
サブの直後に同じテストを回すと、こうなる:

| 起動列 | 所要 | Gradle の出力 |
|---|---|---|
| `bash tools/gwlock.sh testDebugUnitTest` | 2秒 | `> Task :app:testDebugUnitTest UP-TO-DATE` |
| `bash tools/gwlock.sh cleanTestDebugUnitTest testDebugUnitTest` | 5秒 | `> Task :app:testDebugUnitTest FROM-CACHE` |
| 同上 ＋ `--no-build-cache` | **2分13秒** | 実走 |

**どれも BUILD SUCCESSFUL で、結果 XML は新しい mtime で置かれ「1569 tests / failures 0」を表示する**。
上2つはテストを**1件も走らせていない**のに、成果物の見た目は実走と区別がつかない。
`clean` を足しても効かない——`clean` が消すのは出力であって、キャッシュエントリではないため。

## 真因

Gradle のビルドキャッシュは**タスク入力のハッシュ**で管理される。サブが直前に同じコミット・同じ
クラスパスで回していれば入力ハッシュは一致し、監督の実行はキャッシュヒットして
**保存済みの出力（結果 XML を含む）を展開するだけ**になる。展開された XML は新しく書かれるので
mtime も件数も「今走った」ように見え、実走との差は `FROM-CACHE` / `UP-TO-DATE` のタスク行にしか出ない。

⚠️ **公平のために書く: これは Gradle の不具合ではない**。入力が同じなら出力も同じ、という前提は
正しく、コードが変われば必ずキャッシュミスして実走する＝**値としては常に正しい**。
問題は「**正しいか**」ではなく「**独立に確かめたことになるか**」で、後者だけが崩れている。

## なぜ問題か（規約が空回りする）

監督ゲートの目的は値の正しさではなく**独立検証**——サブの申告を信じずに自分の手で確かめること。
ところがキャッシュヒットした実行は、サブが得た結果をそのまま読み直しているだけで、
**検証の主体がサブのままである**。二重チェックのつもりが、同じ1回の実行を2回読んでいる。

とくに **flaky なテストでは1回目の緑がキャッシュされ続ける**＝
「監督も回して緑だった」という記録が、実際には「たまたま緑だった1回」の使い回しになる。
偽 GREEN クラス（`gradle-env-var-not-task-input-stale-results.md`・memory
`bash-pipe-masks-exit-code-false-green`）と同じく、**緑だったことではなく何が実際に走ったかを見る**必要がある。

## 対処

**監督ゲートは `--no-build-cache` を付けて回す**（所要は約2分＝独立検証の対価として妥当）:

```bash
bash tools/gwlock.sh cleanTestDebugUnitTest testDebugUnitTest --no-build-cache
```

- サブの自己検証や実装中の反復では**付けない**（キャッシュは速度のために働かせる）。
  付けるのは**監督が最終ゲートとして回す1回だけ**＝そこだけが独立検証を要求している。
- 付け忘れても気づけるよう、**タスク行（`FROM-CACHE` / `UP-TO-DATE` の有無）を必ず読む**。
  所要時間でも判別できる（2秒〜5秒で返ったなら走っていない）。
