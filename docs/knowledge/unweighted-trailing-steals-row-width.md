# 行の trailing が「幅の制約」を持たないと、fontScale 2.0 で行名だけが潰れる（非加重子の幅先取り）

**重要度 ★★★／golden 監査 2026-08-06 で類型化・2026-08-17 に新事例／一次情報＝`.claude/plans/golden-and-docs-audit-2026-08-06.md` 第1部**

1行要約: `Row` の中で **trailing（値・チップ・ゲージ）が幅の制約（`weight` / `widthIn(max)` / 段組み）を持たない**と、
Compose は非加重子に**必要幅を先に配り**、残りだけが title 側へ回る＝**大きいフォントスケールで行名の方が `...` に潰れる**。

## 型

- 非加重の子は「自分が欲しい幅」を先取りする。`weight(1f)` を持つ title は**余りを受け取るだけ**。
- fontScale が上がると trailing の要求幅も比例して伸びるので、**潰れるのは常に title 側**＝
  「何の行か分からないが値だけ読める」という、情報の優先順位が逆転した見えになる。
- **等倍（1.0）では健全に見える**ため、1.0 だけを見ていると発見できない。

## 事例

| 場所 | 状態 |
|---|---|
| 目次の再開チップ・話数ラベル・現在地バー | **是正済み**（この型の初出・golden 監査の根因群） |
| P の目次 HUD＝進捗ゲージ＋「CLEAR N%」が幅を先取りし `.mid` に約 **55dp** しか残らない | **凍結**（P の版面裁定待ち＝`docs/backlog-frozen.md`「カートリッジP の目次 HUD の幅配分」が正本） |
| 設定のテーマ行（`ui/skins/k/SettingsScreenK.kt` の `KSettingsRow`）＝trailing「システムに従う」が行幅をほぼ占め、title「**テーマ**」が `...` の3点に潰れて何の行か読めない | **是正済み**（2026-08-17 に `followingSystem=true` の 2.0 を撮って判明し同日に案Bで是正＝`SettingsScreenK.kt` の `KSettingsValue` に `K_ROW_TEXT_BUDGET` 由来の `widthIn(max)` を掛け、行名の幅を先に予約する） |

## 直し方の型

効くのは **幅の制約だけ**＝`weight` / `widthIn(max)` / 段を分ける、のいずれか。

⚠️ **`maxLines` は効かない**（2026-08-17 に訂正。旧記述「`weight` か `maxLines` を与えて上限を切る」は誤り）。
`maxLines` は**行数の上限であって幅の上限ではない**——非加重の子は依然として「全文が要る幅」を先取りするので、
`maxLines = 1` を足しても 1px も変わらない。実証＝`KSettingsRow` の title には
`weight(1f)` と `maxLines = 1` と `TextOverflow.Ellipsis` が**既に付いているのに潰れている**
（`ui/skins/k/SettingsScreenK.kt:421-425`）。`Ellipsis` は潰れた結果を丸めているだけで、原因は trailing 側にある。
「title に `weight(1f)` を付ける」だけでも効かない（余りを受け取る側の宣言でしかないため）。

⚠️ **「同型だから意匠裁定は不要」も誤り**（同日訂正）。幅を切る以上、**何を失うかの選択が必ず生じる**——
行名を守る（値を省略）／値を守る（行高を増やして段を分ける）／語彙を短くする（1.0 の見えが変わる）は
どれも別の意匠判断で、機械的に決まらない。案の比較＝`docs/design-candidates/skins/candidates/settings-K-row-width-candidates.html`。
なお**アイコン化は万能ではない**——目次の再開チップでは成立したが（状態が1種で凡例が要らなかった）、
P の HUD ではゲージ 108.5dp が dp 固定のため文字を削っても先取り幅の主成分が残り、失敗が実証済み。

## ⚠️ モックの「Nsp × M字」を Compose へ翻訳するときの罠（2026-08-17 に踏んだ）

**`(N.sp * M).toDp()` と書くのは誤り**。API 34 の sp→dp 変換は**非線形**で、fontScale 2.0 の実測では
**64sp → 68.1dp**（16sp → 28dp の4倍＝112dp の、わずか6割にしかならない）。
まとめて換算すると幅が足りず、行名が1字しか残らない。

**正しい翻訳＝1字を換算してから字数倍する**（`16.sp.toDp() * 4`）。
モックが「bodyLarge 4字ぶん」と規定しているとき、守るべきは**字数ぶんの幅**であって sp の合計値ではない。

⚠️ この誤りは**番人テストがあったから止まった**（「行名の可視文字が 0 文字 expected:&lt;3&gt; but was:&lt;0&gt;」で赤）。
golden だけだと「潰れた絵」が新しい正解として記録されて終わる＝この型には**レイアウト値の断言が要る**。

## 検知の穴

golden は**壊れた絵のまま記録される**（＝`golden-record-bakes-in-regressions.md` と同根）。
記録済みのものは走査(a) の赤として出るが、**赤が出る＝直っていない印**であって allowlist で消してはいけない。
直したら**再記録して赤を落とす**のが手順。
