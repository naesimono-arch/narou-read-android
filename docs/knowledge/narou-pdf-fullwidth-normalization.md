# なろうPDFはWeb原文の半角英数字・!?を全角化して出力する（単幅特殊字は素通し）

★★★ 2026-07-17 — Web本文で半角の略号・記号も、PDF取込経路では全角で届く＝縦中横の半角判定は実運用ではほぼ発火しない

**事実（9作品・約1,070万字の抽出JSONで確認）**: 半角 `[0-9][A-Za-z][!?]` の run は全作品で0件。
Web原文に半角が実在する作品（N3957FQ の AW/MW/SIM、N9463BR の m(_ _)m 等をユーザーがWeb側で確認済み）でも、
PDF抽出後は ＡＷ/ＭＷ/ＳＩＭ/ｍ（＿＿）ｍ と全角になっている。

**機序の推定**: なろうのPDF生成（縦書き版面）が半角→全角正規化していると推定。抽出器（PDFBox）起因は
否定的——旧3作品では `'`（U+0027）×16・`~`×6 の生ASCIIが素通しで残っており、抽出器が一律変換していれば残らない。
ただし生成側の直接確認（PDF内グリフの照合）はしていないため「推定」と明記。

**素通しされる単幅特殊字（作者ごとに出没＝全角化の一般則は無い）**:
- ギリシャ文字 α β γ Δ（N3957FQ に629回・他3作品は0）
- ローマ数字 Ⅳ U+2163 等（N9463BR/集中出現）
- 縦書き用引用符 〝U+301D 〞U+301E（N8809BK のみ593回。閉じは 〟U+301F でなく 〞U+301E が実体）
- 波ダッシュの異体割れ: **本文=〜U+301C・タイトル=～U+FF5E** と出所で割れる（本文に U+FF5E は0件）

**含意**:
- 縦中横の半角判定（2〜3字run）は実運用のPDF経路ではほぼ発火しない＝担保は合成テストのまま正しい。
  実装は将来の非PDF経路（Web本文の直接組版）に備えて保持する。
- 文字分類は「全角化されている前提」に寄りかからず**コードポイント単位**で持つ（U+2015/U+301C/U+FF5E/
  U+301D-E/ギリシャ/ローマ数字を個別に扱う）。回帰固定＝`EdgecaseCorpusTest`・実データ＝`edgecase_corpus.txt`。
