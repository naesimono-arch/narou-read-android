# Claude Code のフック配線はセッション起動時固定——実体だけ消すと全 Bash がブロックされる

★★ Important（2026-07-12 実測・テスト強制3点フック撤去時）

**症状**: settings.json に配線された PreToolUse(Bash) フックの実体 `.py` を `git rm` した直後から、**すべての Bash ツール呼び出しが失敗**する（`python: can't open file ...: [Errno 2]` が PreToolUse エラーとして返る）。

**真因**: settings.json のフック配線は**セッション起動時に読み込まれて固定**される（settings.json を編集しても現セッションには反映されない）。実体ファイルが無いと `python` が **exit code 2** で落ち、PreToolUse の exit 2 は「ツール呼び出しのブロック」を意味する仕様のため、対象 matcher（Bash）の全呼び出しが道連れになる。PostToolUse 側は非ブロックだが毎回エラー通知が出る。

**対処（撤去の正しい手順）**:
1. `git rm` した**同じターン内で、同パスに no-op スタブ**（`import sys; sys.exit(0)`）を Write で置く——Bash がブロックされていても Write/Edit ツールは matcher 違いで生きているため復旧できる。
2. settings.json から配線を撤去（次セッション向け）。
3. スタブは git 追跡外のまま残し、**次セッションで削除**する（配線が無いので呼ばれない）。

**補足**: フックの「配線」は起動時固定だが、フック**ファイルの中身**は呼び出しのたびに読まれる＝既存フックの文言・ロジック修正は即時反映される（本件と同日、remind_task_diary.py の文言変更が同一セッション内で反映されるのを実測）。「改名・削除は再起動まで危険／中身の編集は安全」と覚える。
