# Read も委譲する運用は、コンテキストの「量」でなく「中身」を変える（実測 2026-08-26）

★★★ / 2026-08-26 実測（nuru プロジェクトを自然実験として観測し、当該セッションに照合済み）

**1行要約**: 調査 Read までサブへ出しても、main の**コンテキスト成長率はほとんど下がらない**
（Read の tool_result は1ターン増分の1割程度しか占めないため）。効果は量ではなく**中身**に出る——
本体にファイル本文が載らず、判断材料だけが載る。⚠️ 副作用として**本体が常設ルールを読まなくなる**。

## 観測した自然実験

nuru プロジェクトは 2026-08-24 のユーザー指示「read なども委譲して、サブエージェントの管理のみに務めて」を境に、
Read まで委譲する運用へ振っている。novel-reader（編集起点の Read は main が持つ）を対照群として比較した。
集計＝`tools/measure_delegation_effect_by_project.py`。

### 運用は確かに変わっている（nuru・8/17 を境に前後）

| | Read字/ターン | Agent/100ターン | Agent字/ターン |
|---|---|---|---|
| 前 | 355 | 1.5 | 19 |
| 後 | 182 | 8.8 | 96 |

セッション単位で見ると変化点は 8/23（それ以前は Agent 0〜1回のセッションが多く、8/23 以降は 18〜36回）。

### ところが成長率は下がらない

ターン位置を揃えた平均コンテキスト長（nuru 前 → 後）: 1–25 帯 74.8k → 63.0k（-16%）／
51–100 帯 162.9k → **178.7k（+10%）**／101–200 帯 243.5k → **267.5k（+10%）**。
対照群の novel-reader も同期間に Read を減らしている（221 → 91 字/ターン）が、やはり後半帯はむしろ増えている。

⚠️ nuru 後群は 7本 1,147 ターンと小さく、仕事の性質の違いと分離できていない。

## なぜ量が減らないか（構造）

コンテキストは1ターンあたり **1,000〜1,500 トークン**（文字換算で 2,000〜4,000 字）伸びる
（`context-cost-superlinear-in-session-length.md` の傾き実測）。対して Read の tool_result は
**355 字/ターン → その 1 割程度**。全部外へ出しても成長率は数 % しか動かない。
さらに委譲を増やせば、**委譲仕様（Agent の tool_use 引数・中央値 2,227 字）とサブの報告文が main 側に載る**
——読まない分を書く分が相殺する。

## では何が効果か（nuru セッション本人の証言）

> 軽くなったのはトークン総量というより本体の注意の質。本体がファイル本文を保持しない＝要点報告だけで
> 1ループ（偵察→監査3レンズ→修正波→締め）を完走できた。

**委譲は「成長を止める」のではなく「成長の中身を判断材料だけにする」運用**——これが実感されている効果であり、
成長率が下がらないという実測と矛盾しない。量で効果を測ろうとすると「効いていない」と誤読する。

## ⚠️ 副作用: 本体が常設ルールを読まなくなる

nuru では 2026-08-25 に**本体が正典（AGENTS.md）を読まないまま必守ルールを1件適用し忘れた**。
対処として「🔴 常設ルールだけは本体が冒頭に自分で読む」例外を追加している。
**「全部委譲」には、委譲してはいけないものを名指しで除外する例外規定が要る**。

## 付随して分かったこと

- **「重いタスクだから1委譲が大きい」は実測では成立しない**。sub 1本あたり nuru 90.3ターン/145,169字 に対し
  novel-reader 99.8ターン/120,559字＝ほぼ同等（委譲仕様の長さも 2,227 対 2,192 字）。
  nuru 側の見立ても「意図的に大きくはしていない。分割軸はファイル集合の相互排他と監査レンズ別（並列3本）。
  『死ぬほど大きい』は監査波の発注文（制約列挙が長い）の印象では」。**発注文の長さと仕事量は別**。
- **委譲運用のルールが正典に書かれているとは限らない**。nuru の CLAUDE.md は 580 字のポインタ、正典の AGENTS.md にも
  委譲・Read の運用ルールはほぼ無く、実体は Claude の永続メモリ側（orchestrator-mode-thin-context ほか）にあった。
  他プロジェクトの運用を調べるとき、リポジトリ内の md だけを見ると**運用が見えない**。
