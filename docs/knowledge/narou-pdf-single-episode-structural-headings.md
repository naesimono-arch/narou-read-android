# なろう縦書きPDF: 単話でも前書き/後書きには Bold 見出しが付く

**開く合図**: PDF 抽出で「章見出しの有無」「単話かどうか」を判定するコードを書く／読むとき。
`ChapterProcessor.splitIntoChapters` の単話判定を触るとき。

## 事実（2026-09-04 実測）

なろうの縦書きPDF 生成器は、**前書き・後書きブロックにも本文サイズの Bold 見出しを打つ**。
見出しの文字列は〈話タイトル〉＋末尾マーカーの形で組まれるが、**単話（短編＝話タイトルが存在しない作品）
では話タイトル部が空になり、裸の「（前書き）」「（後書き）」だけが出る**。

| 実測した PDF | 種別 | 出た Bold 見出し | 本文側の見出し |
|---|---|---|---|
| N0089HK | 短編・後書きあり | 「（後書き）」1件 | **0件** |
| N7668GF | 短編・前書き＋後書き | 「（前書き）」「（後書き）」2件 | **0件** |
| N5368ML（golden 第4本） | 短編・前書き後書きなし | 0件 | 0件 |

**本文ブロックには見出しが付かない**（話タイトルが空なので生成器が何も描かない）。
つまり単話の PDF は「前書き/後書きの見出しだけが在り、本文の見出しは無い」という非対称な形になる。

ページ構成そのものは連載と同じ: `0`=表紙（作品タイトル20pt Bold＋著者12pt＋`HinaProject Inc.`）／
`1`=注意事項＋あらすじ前半／`2`=あらすじ後半／`3` 以降=本文／最終=クレジット。
`TextProcessor.addPage` の「先頭3ページと最終ページを除外」はこの形に合っている。

## なぜ効くか（踏んだ罠）

1. **「単話＝【題名】マーカーが0件」は誤り**。マーカーは 1〜2 件出るので、総数で単話を判定すると外れる。
   実害＝後書き付き単話の全文が嘘見出し「作品情報・プロローグ」の章に入る／前書き付き単話は
   `processForewordAfterword` の畳み込み先（次の通常章）が最後まで現れず**章数0＝本文全損**。
   対処は `ChapterProcessor.isRealChapterHeading`（構造マーカーを除いた【題名】の有無で判定）。
2. **前書きと本文の境界は復元できない**（下の計測を参照）。現状は「前書き見出しを章の区切りにしない」
   ＝枠は付かないが内容と順序は落とさない、で妥協している。

## ⚠️ 「ページ境界を通せば前書き枠を戻せる」は**計測で否定済み**（2026-09-04）

ブロック（前書き／本文／後書き）が**ページ揃え**なのは確か（N2959KI で厳密に裏が取れる＝
131章＋102マーカーブロック＋表紙＋注意事項＝235 が Bold を含むページ数と一致＝**見出しは必ず1ページに1つ**）。
だから「境界はどこかのページ継ぎ目」までは言える。**しかしどの継ぎ目かは決まらない。**

単話の本文ブロックは**見出しを持たない**（話タイトルが空なので生成器が何も描かない）。
版面にも手掛かりが無い——見出し無しのブロック開始ページ（N7668GF p4）は最右列 x0=741.3 から始まり、
ただの継続ページと**完全に同一**（見出しページだけは見出しが右端を占め本文が数列左から始まる）。

唯一残る幾何量が「継ぎ目の空き列数」（`TextProcessor.crossPageBlankCount`）だが、
全10本＋単話2本で分布を採ると**既知のブロック境界と継続ページが重なる**:

| | 空き列数の範囲 |
|---|---|
| 既知のブロック境界（次ページに見出しあり） | **4〜35**（低い側にも厚い山。N2959KI は 4:3件・5:2件…） |
| 継続ページ（見出しなし） | 主に 0〜1 だが**長い裾**（N6169DZ は 2:86件…15:11件…最大 38） |

∴ しきい値では分離できない。単話だけに限れば手元3本は clean（N5368ML 最大2・N7668GF は境界20・他は≤2）だが、
**3本の標本から不変条件を引くのは、このバグを生んだ過ちそのもの**なので採らない。

同じ欠落は**目に見える副作用**も生む: 単話の前書きページは版面が余るため、継ぎ目の空き列が
そのまま空行として復元され、**本文冒頭に空行が約20行入る**（N7668GF 実測）。既存の抑止は
「現ページに見出しがあるとき」しか効かず、見出しの無いブロック開始ページを守れない。
前書き枠の復元とこの空行抑止は**同じ1つの信号（このページは新しいブロックの先頭か）**を必要とする。

## golden corpus

第5本 **N7668GF（単話・前書き＋後書き）** を追加済み（2026-09-04）。第4本 N5368ML と型が重ならない
（あちらは前書きも後書きも無い単話）。これで「単話 × 構造マーカー見出し」の枝が `body_sha256`
完全一致で固定され、章数0（本文全損）と嘘見出しの再発は機械で落ちる。

## 標本の穴に注意（この知見が生まれた本当の理由）

`ChapterProcessor.structuralMarkerOf` の KDoc は golden corpus 4本の Bold 見出し1444件を全数実測し
「すべて〈話タイトル〉＋末尾マーカー・裸のマーカーは0件」と結論していた。**この標本には前書き/後書きを
持つ単話が1本も含まれていなかった**（4本のうち単話は N5368ML だけで、それが前書き後書きなし）。
実測に基づく結論でも、**標本が偏っていれば前提ごと外れる**。
コーパス統計から不変条件を引くときは「その形の作品が標本に居るか」を先に数えること。

## 一次情報の採り方

PDF は アプリと同じ ADR 0011 のフローで取れる（`ncode.syosetu.com/<ncode>/` の `div.c-under-nav` の
POST フォーム → `pdfdl.syosetu.com/pdfout/checkpdfapi/ncode/<ncode>/` へ `token` と `out=json` を
POST してポーリング → `downloadend` ページ → PDF 実体）。⚠️ `out=json` を欠くと `Forbidden` が返る。
取得した作品PDFは**リポジトリへ入れない**（golden へ足すかは著作物を増やす判断＝別途裁定）。
