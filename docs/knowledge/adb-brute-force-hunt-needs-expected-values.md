# 再現不能バグの adb 総当たりハントは「期待値を記録しない撮り方」では判定不能に終わる

**出典**: 2026-08-05、「本文読書中の章遷移で描画が上部にジャンプする」（実機ユーザー報告・**報告者自身も再現できていない**）を
機械で捕まえようとしたラウンド。adb で〈スキン×縦書き/横書き×スワイプ送り/ボタン送り×章種別〉を総当たりし、
章を送る前後の a/b スクリーンショット対を撮った。結果は**判定不能**＝陽性も陰性も主張できないまま終わった。

## 何が足りなかったか（3つ）

1. **操作が実行できたことを検証していなかった**
   `hunt-K-h-btn-*` / `hunt-K-v-btn-back-*` の a/b が**バイト同一**だった＝座標タップが章送りボタンに当たっておらず、
   ボタン送り系は**丸ごと未試行**のまま「試した」ことになっていた。
   → 次回は uiautomator の **resource-id 指定**で押し、試行ごとに「押下前後で画面が変わった」ことを確認してから次へ進む。

2. **判定の基準値を撮る前に記録していなかった**
   スクリーンショットだけ残っても、「飛んだ」を判定する基準（＝送る**前**のスクロール位置）が無い。
   目視で「上のほうが写っている」と言えても、それが異常か正常かを後から決められない。
   → 各試行で `dumpsys` か a11y ノードから**スクロール量を数値で控えてから**送る。

3. **軸の消化状況を記録していなかった**
   実際に回せたのはスキン K/D・横書き（K/D）・縦書き（K）だけで、**没入 ON/OFF は軸ごと未消化**だったことが
   事後の点検で判明した。走らせている最中は「全部回した」つもりでいた。
   → 軸の直積を先に表として書き出し、試行のたびに消し込む。消し込めない軸は「未試行」として報告に残す。

## より根本的な教訓

**報告者自身が再現できていない不具合に対しては、機械の総当たりより「遭遇した瞬間の条件採取」のほうが本筋**。
総当たりを回すのであれば、上の3点（操作の実行検証・基準値の事前記録・軸の消化記録）が揃ってはじめて
**「陰性」を主張できる**——揃っていない総当たりは、コストだけ払って何も確定させない。
