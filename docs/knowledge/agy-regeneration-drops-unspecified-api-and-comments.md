# agy に「再生成」を委譲すると、仕様に名指しされていない public API とコメントが消える

★★★ / 2026-08-11 / 「完全な仕様はこのファイル」と書くと、そこに現れない public 宣言と「なぜ」コメントは**落として正しい**と読まれる。

## 症状

`domain/ReimportPlan.kt`（322行）の再生成を agy へ委譲したところ、返ってきたのは 235行。
差分は **230行削除・158行追加**で、消えたものの内訳が偏っていた。

| 消えたもの | 実測 |
|---|---|
| コメント | 削除230行のうち **167行（73%）** |
| `sealed interface` のサブクラス | `AutoPdf` / `AutoWeb` / `AutoCachePdf` / `PickPdfPermissionLost` / `PickPdfNoRecord` の5種 |
| トップレベル関数 | `sourceFileNameHint` / `shouldShowReimportSweep` / `shouldConsumeSweepBanner` / `pruneReimportSeenIds` / `reimportStatusLabel` / `countMissingContentTargets` ほか |

コンパイルは通る形で返ってくるため、**呼び出し側を見に行かなければ欠落に気づけない**。

## 真因

agy の逸脱ではなく、**ブリーフどおりの動作**だった。委譲時に「完全な仕様はこのテストファイル」と書いたため、
テストが参照しない public API とコメントは「仕様の外」＝再生成の対象外として扱われた。

人間は「テストは仕様の一部」と読むが、**「完全な」と書かれた指名は網羅の宣言として読まれる**。
`git` 上の元ファイルは参照してよい材料だと（こちらは）思っていたが、
「完全な仕様はここ」は**他を見るなという指示に等しい**。

## 対処

再生成を頼むときは、仕様の指名とは別に**不変条件**を渡す。

- 既存の public シグネチャは全数保持（削ってよいものがあるなら名指しで列挙する）
- コメントは保持（「なぜ」コメントは仕様書に書かれないので、指名した仕様からは必ず落ちる）
- そもそも**再生成でなく差分適用**で頼めるなら、そちらは構造的にこのクラスの欠落が出ない

検証側は、**削除行込みの diff 全量レビュー**でしか捕まらない（ADR 0031 決定2-d でこれを2層目の職務としたのは、
まさにこの型のためである）。テストは通る・コンパイルも通るので、ゲートは赤くならない。

## なぜそうなるか

生成モデルにとって「仕様」は**出力の完全性を判定する基準**であり、参照可能な材料の一部ではない。
基準に現れないものは、保持する根拠がない＝落とすのが最適解になる。
同じ理由で、正解を `git` に残したまま「復元せよ」と頼むと `git reset` が返ってくる——
**タスクとして最適だから**であり、これも逸脱ではない（同日の別試行で実測）。

関連: ADR 0031（三層委譲・決定2-a「仕様の不備は書いた本人に構造的に見えない」）
