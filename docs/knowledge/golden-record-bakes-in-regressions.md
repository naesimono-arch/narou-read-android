# `recordRoborazziDebug` は退行を「新しい正解」として黙って焼き込む

## 何が起きるか

見た目を変えたときは `recordRoborazziDebug` で golden を再記録してから `verifyRoborazziDebug` に掛ける、
という手順を踏む。ここに構造的な穴がある——**record は「今の描画」を無条件に正解として書き出す**ので、
その描画が壊れていても record は成功し、続く verify も当然のように緑になる。

つまり **golden が守るのは「前回の record 以降の変化」だけ**であり、record を打った瞬間に
それ以前の回帰は帳消しになる。ゲートを何本並べても、この1点だけは機械が検出できない。

## 実例（2026-07-31）

ランキング期間の横スワイプが重い（Janky 11.89%・`draw/record` 100.6ms 一点集中）ので、隣接ページを
先行実体化する `beyondViewportPageCount = 1` を入れた。結果:

- `testDebugUnitTest` **緑**（1151件）／`recordRoborazziDebug` **BUILD SUCCESSFUL**
- `:app:assembleDebugAndroidTest` **緑**／`:app:lintDebug` **緑**／`check_design_tokens.py` **exit 0**

**全ゲートが緑のまま、ランキング一覧が丸ごと消えて空白になる退行が確定していた。**
（`HorizontalPager` の交差軸サイズは測定したページの**最大高**で決まるため、10行の現在ページの下に
未訪問ページの骨30行ぶんの空白が生まれていた。詳細＝`pager-resident-pages-break-wrap-height.md`）

## だから何をするか

**record を打ったら、差分の量に説明を要求する。** 「意図した変更だから record した」で終わらせない。

- `git status --short <screenshots>` で**枚数**を数え、事前に予想した枚数と突き合わせる。
  予想より多い／説明のつかない1枚がある、は赤信号。
- 説明できない差分は**画素で測る**。差分率と外接矩形、必要なら縦方向の帯プロファイル。
  Pillow は `uv run --with pillow python3 …` で入れずに使える。
- **「文字だけ変えたはずなのに区切り線・罫線まで差分に出る」はレイアウト高が動いた強いシグナル**。
  文字の変化なら線は動かない。この非対称性は判定に使える。
- 差分率が高い（数%規模）のに変更が局所のはずなら、**非背景画素の総量**を新旧で比べる。
  減っていれば「何かが消えた」＝退行の可能性が高い（実例では 100,783 → 70,662 で −30%）。

## 一般化

**自動生成される「正解」を持つ検査は、正解の生成手順そのものが検査の外にある。**
golden・スナップショット・承認テストはいずれも同型で、「更新操作」が無検査の抜け道になる。
守れるのは人間の側の運用規律だけなので、規律を明文化しておく（このファイルがそれ）。
