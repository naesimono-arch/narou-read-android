# スキン起案は「コンセプト行で数打ち→当たりだけモック化」の二段分離（2026-07-25 A/B実験）

## 実験の形

新スキンテーマ提案を Fable 5 と Opus 4.8/5 に同一ブリーフで委託
（headless `claude -p --model`・3案×2ラウンド＝計12案・人間ブラインド目視で裁定）。
R1 はADR 0014（静謐・余白＝既定UIの規範）接地・R2 は M/P/J モック（装置化スキンの実例）接地＋紙もの禁止＋相互距離の強制。

## 結果

- 合格 2/12。R1=製図室（Fable）・R2=カプセル売場（Opus 5）＝**モデル勝敗 1-1・モック生成のモデル依存は決定打でない**。
- 没10案は**全てコンセプト段階の却下**（純喫茶・湯屋・回転寿司…）で、実行品質（HTML の作り込み）による却下はゼロ。

## 知見

1. **モック費用の大半が無情報だった**: 却下はテーマ名を聞いた時点で可能＝フルHTMLを作る前に殺せた。
   → 起案は二段分離する: ①コンセプト1行×10〜20案をテキストで出す（ほぼタダ）→ ユーザーが丸を付ける →
   ②丸の付いた案だけモック化。「全部作って見せる」（memory feedback-build-dont-ask-iterate）は
   **コンセプト確定後の意匠詰め**で効く手であり、世界観の当てずっぽうには適用しない。
2. **ブリーフの接地先が生成空間を支配する**: ADR 0014 を必読にした R1 は両モデルとも「静かな紙もの」
   （両者が独立に純喫茶を提案＝同一アトラクタ）へ収束。M/P/J 接地の R2 は装置化系へ移動。
   規範ファイルの錨は意図して選ぶ。無誘導の多様性は出ない＝「3案は互いにジャンル級で離す」等を明記する。
3. **headless 委譲の作法**: `claude -p --model <id>` はサブエージェントの env opus 固定
   （memory claude-code-subagent-model-control）を迂回できる。Opus は headless でも書込確認を求めて
   成果物ゼロで終わりうる＝**書込先を作業ツリー内＋「事前承認済み・確認不要」をブリーフに明記**する
   （Fable は同条件で書ける場所を自力確保した＝旧A/B「停止線」差の再現）。
