# 1シェルに連結した `input` は先行ジェスチャが落ちる（偽の再現・偽の反証を両方作る）

**いつ開くか**: 実機で「操作Aの直後に操作B」を adb で撃ち、**Aが効いていない／Bが効いていない**ように見えたとき。
特に「タップが無反応」「スワイプが効かない」を再現しようとしているとき。

## 事実

`adb shell "input swipe …; input tap …"` のように**1回の shell に2つのジェスチャを連結すると、
どちらか一方（多くは先行側）がアプリに届かない**。2026-09-05 に PGEM10 で実測。

同じことは `input tap; input tap` でも起きる（先行タップが丸ごと落ちる）。`&` でのバックグラウンド
起動（`input tap … & input tap …`）でも落ちた。

**分けて撃てば両方届く**——`adb shell input swipe …` と `adb shell input tap …` を**別々の adb 起動**
にすると、2つとも確実にアプリへ入る（アプリ側のログで受信を確認済み）。

```bash
# ✗ 一方が消える（何が消えるかは走ごとに変わる）
adb shell "input swipe 1150 1760 250 1760 100; input tap 136 759"

# ○ 両方届く。間隔は adb 起動ぶん（実測 ~0.2-0.4s）空くが、フリングの尾には十分間に合う
adb shell input swipe 1150 1760 250 1760 100
adb shell input tap 136 759
```

## なぜ危険か — 症状が「アプリの不具合」に化ける

落ちるのが**先行のスワイプ**なら「スワイプが効かない」、**後続のタップ**なら「タップが無反応」に見える。
どちらもアプリ側の実在の症状と見分けがつかない。しかも落ちる側は走ごとに変わるので、

- **偽の再現**: 3回連続で「タップ無反応」を観測 → 不具合として報告 → 実体は後続タップが届いていないだけ
- **偽の反証**: 別の回に 12/12 で「正常」 → 「再現しない」と結論 → 実体は先行スワイプが届かず競合が起きていないだけ

の**両方**が起きる。2026-09-05 の期間タブ調査では実際に両方を踏み、「3/3 再現」と「0/13 再現せず」という
矛盾した結果を出した（最終的な真因は別に実在したが、**そこへ至る観測はすべて無効**だった）。

## 判定の作法

**「画面が変わらなかった」を証拠にしない。ジェスチャがアプリに届いたことを別の手段で確かめる。**

1. **アプリ側の一時ログで受信を見る**のが最も確実（`adb logcat -c` → 操作 → `adb logcat -d -s <TAG>`）。
   届いていないなら**ログ行が1本も出ない**ので、(a) 届いていない と (b) 届いたが状態が動かない が一発で割れる。
2. ログを入れられないときは、**ジェスチャを1つずつ撃って各々の効果を個別に確認**してから連結を組む。
3. 座標は毎回 `uiautomator dump` の bounds で取り直す（スクロール位置で動くため。固定 y の使い回しは
   別の偽陽性源＝ダミーの領域を叩いて「無反応」に見える）。

⚠️ **`input swipe` は当たりどころで無反応になる**のも併発する（2026-09-05 実測: 同じ行の中でも
y=1650/1180/2000 では送りが走り、y=1555 では一度も走らなかった）。スワイプが効かないときは
連結を疑うのと同時に、`uiautomator dump` で実在の行の中心 y を取り直すこと。
