# 加算合成（BlendMode.Plus）ベースのレイヤでは「暗く描く」が構造的に不可能

- 日付: 2026-07-19（高負荷スカイ試作ラウンド・ADR 0023）
- 現場: `HighLoadSkyM.kt` の BH「真の黒」要望と暗黒シルエット雲

## 事実

光の重なりを表現するために層全体を `BlendMode.Plus` で合成すると、そのレイヤは**地色より暗い画素を作れない**
（加算は各チャネルを増やす方向にしか働かない＝黒 (0,0,0) を Plus しても無変化）。
「真っ黒な孔」「暗黒雲」のような**負の要素**は加算レイヤ内では原理的に描けない。

## 使い分け（実証済みの2解）

1. **生成段階で抜く**: 粒子系なら「そこに粒を置かない」（BH の孔＝レンズ写像で粒が入らない領域・
   暗黒レーン＝配置確率の欠乏）。負荷ゼロ・焼き込みと相性が良いが、地のグラデーションまでは消せない。
2. **SrcOver の別レイヤで遮蔽**: 発光しない黒を通常合成で上から重ねる（暗黒シルエット雲）。
   加算レイヤ群より上の合成順に置く。「暗い側の表現」はこちらでしか成立しない。

## なぜ残すか

視覚表現の追い込み中は「もっと暗く/黒く」の裁定が繰り返し出る。加算レイヤに対してこの要望が来たら
較正では解決できず**合成方式の選択**の問題になる、と最初に切り分けるための知見。
