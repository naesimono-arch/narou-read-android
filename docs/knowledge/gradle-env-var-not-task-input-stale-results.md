# Gradle は環境変数を test タスクの入力と見ない＝古い結果を読む偽 GREEN

★★ / 2026-08-17 / 環境変数で対象を切り替えるテストは `--rerun` を付けないと、前回の対象の結果が残ったまま BUILD SUCCESSFUL になる。

## 症状

環境変数で処理対象を選ぶテスト（例: `EXTRACT_PROFILE=<fixture>` で計測対象の PDF を切り替える
`ExtractPhaseProfileTest`）で、変数の値だけを変えて実行すると:

- `> Task :app:testDebugUnitTest UP-TO-DATE`
- `BUILD SUCCESSFUL`
- しかし `test-results/*.xml` の中身は**前回の対象のまま**

結果 XML を読んで「新しい対象の実測が出た」と誤読しかける（実際に踏んだ＝中編の計測値を大 PDF の
計測値として報告する寸前だった）。

## 真因

Gradle の up-to-date 判定はタスクの宣言済み入力（ソース・クラスパス・プロパティ等）で行われ、
**環境変数は入力に含まれない**。ソースもクラスパスも変えずに環境変数だけ変えた実行は
「前回と同一の入力」と判定され、タスクごとスキップされる。スキップされた以上、結果 XML は
前回の走行のものがそのまま残る（消えないので「無い」ことにも気づけない）。

## 対処

- 環境変数で挙動が変わるテストは **`--rerun` を必ず付ける**（当該タスクだけ強制再実行）。
- 付け忘れても気づけるよう、**出力の先頭に対象名と実行時刻を必ず出す**。
  `ImportBudget` が `benchmarkData.json` の `lastModified` で残骸 JSON を弾いているのと同じ発想を、
  出力側の自己申告で行う。読む側は対象名と時刻を毎回確認すること。
- システムプロパティ（`-D`）に替えても解決しない。転送設定を書けば入力にはできるが、
  ビルドスクリプトを計測都合で変更することになる。

## なぜそうなるか

up-to-date チェックは「宣言された入力が同じなら出力も同じ」という前提で成り立つ。
環境変数はビルドスクリプトが明示的に `environment` として宣言しない限りその前提の外にあり、
Gradle から見れば**存在しない**。よってこれは Gradle の不具合ではなく、
「宣言していない入力で挙動を変えた」側の設計上の帰結。
同種の罠は `| tail` による exit code の握り潰し（memory `bash-pipe-masks-exit-code-false-green`）と同じ
**偽 GREEN クラス**で、いずれも「緑だったこと」ではなく「何が実際に走ったか」を出力本文で確認して防ぐ。
