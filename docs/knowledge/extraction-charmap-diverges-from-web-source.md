# 抽出の字種写像は web 原文と食い違う（オラクルが死んだ pdfminer のまま）

★★ / 2026-09-02 調査（独立再実装実験 S2b の裁定材料。**裁定は人間・未了**）

**1行要約**: なろう公式PDFの抽出結果は、照合できた字種**6種すべて**で web 原文と 食い違い、
第二実装（`~/naro-pdf-engine/`）は6種すべてで一致した。原因は1箇所ではなく**2系統**あり、
「正規化を撤去すれば直る」わけではない。

## 何が食い違うか（第二実装＝web 原文一致、現行＝不一致）

| 字種 | web 原文 | 現行の出力 | 規模 |
|---|---|---|---|
| 波ダッシュ | 作品により `～`FF5E と `〜`301C の**両方が実在** | 一律 301C | 全作品・**作品題3本**が不一致 |
| 二重引用符 | `〝`301D … `〟`301F | `〞`301E | 591 件 |
| 縦書き括弧 | `［`FF3B / `］`FF3D | `﹇`FE47 / `﹈`FE48 | 3 作品 |
| ダッシュ | `—`2014 | U+0336 結合長打消線 | 41 run |
| 矢印 | `↑`2191 | 回転後の別矢印 | 12 件 |
| マイナス | 半角 `-`（PDF生成器が全角化） | `−`2212 | 1,600 件超 |

⚠️ **PDF は 301C と FF5E を区別して保持している**（作品ごとに撃ち分けが観測された）＝
現行の FF5E→301C は情報の破壊であって復元ではない。

## 出所は2系統（ここを取り違えると直らない）

1. **意図的な正規化** `pdf/PdfExtractor.kt` の `normalizeGlyphUnicode`。**中身は4写像だけ**:
   FF5E→301C ／ FF0D→2212 ／ 2191→2190（↑→←）／ 2193→2192（↓→→）。
   同ファイル冒頭のコメントが動機を明記している——**追従先は pdfminer**（「golden から離れる写像は入れない」
   「短中編 body_sha256 が現状 pdfminer と完全一致」）。⚠️ **Python 経路は撤去済みで、この追従先はもう存在しない**
   （`docs/knowledge/legacy-python-artifacts.md`）。オラクルとして残っているのは web 原文だけ。
2. **正規化ではない経路**: `﹇`FE47・`﹈`FE48・U+0336 は **Kotlin ソースのどこにも現れない**（全文検索で0件）。
   ＝明示的な写像ではなく ToUnicode CMap 側の復号結果がそのまま出ている。真因の特定は未了。

## 波及先（撤去するなら道連れになるもの）

- `typeset/CharClass.kt:41-42` のコメントが「閉じの実体は `〟`U+301F でなく `〞`U+301E」と**断定**しているが、
  これは上表のとおり web 原文と逆。同じ誤オラクル由来と見てよい。`PUNCT_REPOSITION_CHARS` の収録字と
  `ROTATE_CHARS`・`VertFeatureCoverage` が `−`2212 前提で `－`FF0D 未収載、という追随も同根。
- `JvmGoldenRegressionTest` の golden は旧 Python 出力の複製＝写像を直せば**全面再採取が要る**。

## 未確認（埋めていない）

- 矢印は、コードの写像（↑→←・↓→→）と観測（web ↑ に対し現行 →）が直接はつながらない。
  CMap 側が既に ↓ を返し、そこへ回転が乗って → になった、という二段重ねが疑われるが**未確定**。
- `N6169DZ` は PDF の話番号と web の話番号がずれるため、同作の高番号話は未照合。

## 裁定の論点（人間）

「pdfminer をオラクルにする」前提は撤去してよいか。撤去するなら golden 再採取と `CharClass` の同時改訂が必須。
⚠️ 放置の実害として、U+0336（結合長打消線）は**独立字ではない**ので実機表示が壊れる側に入る。
