# 抽出の字種が web 原文と食い違う（真因は写像表ではなく**字を取ってくる層**）

★★ / 2026-09-02 調査 → 2026-09-03 裁定（ADR 0041）と実装で真因確定＝**解決済み**。
以後この文書は「同じ取り違えを繰り返さないための型」として残す（着地の詳細は ADR 0041 の「着地」節）。

**1行要約**: なろう公式PDFの抽出は web 原文と食い違っていたが、原因は**写像表が間違っていた**ことではなく、
**字を ToUnicode CMap の逆引きから取っていた**こと。明示的な写像が関与していたのは食い違い 7 系統のうち
**2 つだけ**で、残りは表のどこにも書かれていない。**写像を足しても引いても直らない**——
直ったのは、字をフォントの**符号化そのもの**（文字コード）から決める層へ切り替えたとき。

## ⚠️ 先に読み方の注意: 下の表は網羅ではなかった

2026-09-02 時点で作った表は「照合できた 6 種」であって、**存在するものの全部ではない**。
実装時に全グリフを二重復号して数えたら **8 種（7 系統）**あり、7 つ目の
`‾`203E→`￣`FFE3（上線。N3957FQ に 2 件）は**表に載っていなかった**。
表に無いことは「存在しない」ことの証拠にならない。疑いが出たら表を眺めず、後述の数え方を回すこと。
——今回踏んだのはまさにこの形で、「6 種すべてを直す」と決めて着手したが、実際には 7 系統あった。

|---|---|---|---|
| 波ダッシュ | 作品により `～`FF5E と `〜`301C の**両方が実在** | 一律 301C | 全作品・**作品題3本**が不一致 |

## 真因＝参照する層が違った（ここがこの知見の値打ち）

食い違い 7 系統の出所は 2 つに割れる。

1. **明示的な写像（2 系統だけ）** — `pdf/PdfExtractor.kt` の `normalizeGlyphUnicode`。
   中身は FF5E→301C ／ FF0D→2212 ／ 2191→2190 ／ 2193→2192。
   動機は当時のコメントが明記していて**追従先は pdfminer**（「golden から離れる写像は入れない」）。
   ⚠️ **Python 経路は撤去済みで、この追従先はもう存在しない**（`legacy-python-artifacts.md`）＝
   合わせている相手が死んだオラクル。オラクルとして残っているのは web 原文だけ。
2. **写像ではない残り（5 系統）** — `﹇`FE47・`﹈`FE48・U+0336・`〞`301E・`‾`203E は
   **Kotlin ソースのどこにも現れない**（全文検索で 0 件）。これらは **ToUnicode CMap の逆引きが返していた**。
   ToUnicode は「縦組みグリフ(CID)→Unicode」の表で、縦組み専用の**表示形**（FE47/FE48）や、
   CID を共有する**別字**（301E）や、そもそも**独立字ですらないもの**（U+0336 結合長打消線）へ写る。

⚠️ **ここを取り違えると、表を足しても直らない**。「FE47→FF3B を写像表に足す」式の対処は
症状を 1 行ずつ潰す作業で、載せ漏れた 203E のような系統は**残り続ける**（実際、6 系統の表で着手して
7 つ目を取りこぼしかけた）。

**直した層と、それが成立する理由**: なろうの縦書き PDF が使う CMap は `…-UniJIS-UTF16-V/H` 系＝
**文字コードが UTF-16 符号単位そのもの**（CMap 名の UTF16 がその契約）。つまりコンテンツストリームの
バイト列には**作者が書いた字がそのまま入っており**、CID もグリフも経由しない。
だから「ToUnicode で CID から Unicode を逆引きする」のは、**復元できる情報を一度捨てて推測し直す**操作にあたる。
字はコードから決めればよく、そうすると 5 系統が**個別対処ゼロで同時に**原文どおりになる。
実装は `PdfExtractor.GlyphDecoder`（コード優先・**フォント名に UTF16 を含むときだけ**適用・
それ以外は ToUnicode へフォールバック）。

⚠️ **層を切り替える条件を必ず確かめること**: Identity-H など「コード＝グリフ番号」の符号化で同じことをすると、
読めない字を**別の読める字に化けさせる**＝ToUnicode より悪い壊れ方をする。前提が確認できないフォントは触らない。

**副産物**: ToUnicode の穴（U+FFFD 化。実測 N6169DZ 本文 32 件）への特別扱いが**不要になった**。
穴が空いているのは逆引き表の側だけで、コードには字が入っているため——
これも「層を戻せば個別対処が消える」ことの一例。

## 数え方: 網羅を主張したいなら全グリフを二重復号して差分を数える

表を眺めて系統を拾うのは**網羅を主張できない**（今回それで 1 系統落ちた）。代わりにこれを回す:

1. `PDFTextStripper` を継承したストリッパを 1 本用意し、`processTextPosition` で**同じグリフを 2 通りに復号**する
   ——旧経路（`text.unicode` ＋当時の正規化）と新経路（`GlyphDecoder`）。
2. 両者が違うグリフだけ `"U+XXXX -> U+YYYY"` をキーに **HashMap でカウント**する
   （複数コードポイントになる場合に備え、キーは `+` 連結で全コードポイントを出す＝
   **1:1 でない変化＝字数が増減する変化**をここで検出できる）。
3. sample_pdfs 全 10 本に対して回し、件数降順で出す。出た種類がその時点の**全系統**。

実測は 30 秒程度で終わる（N6169DZ 8,668 ページ込み）。1 回の実行で
「何系統あるか」「各何件か」「字数が変わるか」の 3 つが同時に確定するので、
同種の疑い（生成器の更新・PDFBox の更新・別サイトの PDF）が出たら最初にこれを回すこと。

**恒久ゲート側の作法**: 期待値の表には**出現数 0 の字も載せる**。
`pdf_oracle/*.oracle.json` の `s2b_charmap_counts` は 21 コードポイントを 0 件込みで持つ＝
「出るはずのない字が出た（撤去漏れ）」と「出るはずの字が消えた（過剰写像）」を**1 本の等式で両向きに**見張る。
片側だけの表はどちらかを必ず見逃す。

## 取り違えの型: 死んだオラクルの出力を「実体」と誤認する（301E/301F の件）

`typeset/CharClass.kt` のコメントは、縦書き用引用符について
「閉じの実体は `〟`U+301F でなく `〞`U+301E」と**断定**していた。これは**逆**である。
web 原文の閉じは `〟`U+301F で、301E は ToUnicode 逆引きが返していた値にすぎない。

この断定は嘘をつくつもりで書かれたのではなく、**実データ（N8809BK で 593 回出現）を観測して書かれている**。
観測したのは本物の PDF であり、回数も正しい。誤ったのは**何を観測したかの解釈**で、
「自分の抽出パイプラインの出力」を「PDF に入っている実体」と読んでしまった。
パイプラインが変換を挟んでいる限り、出力は実体ではなく**実装の像**である。

⚠️ **再発の条件**は「出力しか見ていない」こと 1 つ。防ぎ方は 2 つ:
- コード内で字の**実体**を断定するときは、根拠を**パイプラインの外**（web 原文・PDF のバイト列・第二実装）に置く。
  「実データで N 回観測した」は根拠にならない——それは像を N 回見ただけ。
- 断定を書くなら、**何と照合したか**を同じ行に書く。今回の訂正後のコメントはそうしてある。

同根の追随として `ROTATE_CHARS`・`VertFeatureCoverage` が `−`2212 前提で `－`FF0D 未収載だった
（2212 は写像の産物で、原文に出るのは FF0D）。**誤オラクルは 1 箇所では終わらず、下流の判定表へ伝播する**
＝直すときは「その字を前提にしている表」を全部たどること。

## 決着（2026-09-03）

- 裁定＝**ADR 0041**（字種写像は全面撤去し web 原文一致へ）。実装・ゲート・golden 再採取も同 ADR の「着地」節。
- 恒久ゲート＝`WebAnchoredOracleTest` の S2b（追跡 4 本 × 21 コードポイントの全数一致）。
- かつて「未確認」としていた矢印の二段重ね（コードの写像 ↑→← と観測 web ↑ / 現行 → がつながらない）は
  **解決**: CMap 逆引きが既に別の矢印を返し、そこへ写像が乗る二段重ねだった＝
  上表の `→`2192→`↑`2191・`←`2190→`↓`2193 がその実測。
- 未照合のまま残るもの: `N6169DZ` は PDF の話番号と web の話番号がずれるため、同作の高番号話は web と直接照合していない
  （第二実装との全数一致では担保されている）。
