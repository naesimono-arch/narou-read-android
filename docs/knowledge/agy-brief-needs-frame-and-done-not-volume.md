# agy に要るのは厚い仕様でなく「枠と完了条件」——量を増やしても網羅は上がらない

★★★ / 2026-08-11 / 同一タスクをブリーフの具体度だけ変えて実測（2×4 格子）。95文字でも網羅は上限に張り付き、
607文字で変わったのは**緑と範囲遵守**だった。

## 測り方

対象＝`domain/ShelfItems.kt` の未テスト3関数（`recencyKeyOf`／`webRecencyKeyOf`／`importedNcodeKeys`）。
採点は**変異テスト**——本番コードに7つのバグを仕込み、生成されたテストが赤で捕まえるかを数える
（表面的な網羅率ではなく実効カバレッジ。採点基準は投入前に固定＝ハーネスは `tools/agy-probe/`）。

| | ブリーフ | 緑 | 変異 | 範囲 |
|---|---|---|---|---|
| ベースライン（既存テストのみ） | — | — | **5/7** | — |
| agy L0（ゴールのみ） | 95字 | ✗ 赤いまま提出 | 新規寄与 2/2 | **逸脱**（指示外の関数を壊した） |
| Claude Sonnet L0（同一ブリーフ） | 95字 | ✓ | 新規寄与 2/2 | 逸脱なし |
| agy L2（＋不変条件＋検証コマンド） | 607字 | ✓ | **単独 7/7** | 逸脱なし |

⚠️ **ベースラインを先に測らないと 7/7 は読めない**: 既存テストが `mergeShelfItems` 経由で5つを巻き添えで殺すため、
L0 の「7/7」の新規寄与は実際には2つだった。**変異は「既存テストが殺せないもの」から設計する**こと。

## 分かったこと

1. **網羅はブリーフの量に比例しない。** 95文字の一行でも、既存テストが取りこぼしていた境界（`lastReadAt` の
   0 境界・web 側の value 選択）を両方埋めた。`trim`+大文字正規化も tier 優先の比較も自力で洗い出す。
2. **完了条件は明示しないと満たされない。** L0（「緑にしろ」なし）は**自分でテストを回さず、赤いまま提出した**。
   L2（「緑になるまで自分で回すこと」あり）は緑にして返した。同じモデル・同じ対象で、差はこの一行だけ。
3. **枠も明示しないと守られない。** L0 では指示していない `filterBooksByQuery` にまで手を伸ばし、
   実装を読まずに期待値を書いて壊した（「オーバーロード」が `"OverLoad"` に当たると仮定。実装は素の
   `lowercase().contains`）。`src/main` 不触・既存改変なしと書いた L2 では逸脱ゼロ。
4. **Claude(Sonnet) との差は「緑」だけだった。** 同一の95文字で網羅は同点。Claude は言われずともゲートを回した。

## 処方

委譲ブリーフに要るのは仕様の分量ではなく、次の4点（合計 600字程度で足りる）。

- **対象**（どのファイルのどの関数か）
- **枠**＝触ってよい範囲と触ってはいけない範囲（`src/main` 不触・既存改変禁止など）
- **完了条件**＝検証コマンドと「緑になるまで自分で回せ」
- **配置先の規約**（既存のどのファイルに倣うか）

⚠️ 逆に「完全な仕様」を書き下すのは有害ですらある——**動詞に忠実な分、仕様に無いものを落とす**
（→ [[agy-regeneration-drops-unspecified-api-and-comments]]）。症状を一言でいえば
**枠の中では最大化するが、枠と完了条件そのものは検算しない**。
これは CLAUDE.md にある Opus の性質（書かれた基準への追従が最強・書かれていない基準の自己設定が弱点）と同型で、
処方も同じ＝**完了定義を外から与える**。

⚠️ **厚いブリーフは実行時間を延ばす**（読むべき仕様が増える）。L2 は読み込みだけで2分を超え、
`agy -p` を素の foreground で叩くと呼び出し元のシェルが切れた瞬間に SIGTERM で死ぬ。
`setsid nohup … &` で切り離すこと（handover の「2分で表示が切れてもタスクは走り続ける」は不正確だった）。

関連: ADR 0031 判断材料2（「ブリーフを書く監督の負荷ゆえ同じ仕事なら常に Claude サブが安い」＝
この実測はその前提を覆す）／`docs/patterns/agy-readonly-digest-contract.md`
