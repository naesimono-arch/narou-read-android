# 独立再実装によるアンカリング検出 — 方法論と適用条件

★★★ 2026-08-30。**「矛盾ゼロで一貫して間違っているもの」は内部からは原理的に見えない**——
既存コードを見せず同じ要件だけから独立に書かせ、後から意味突合すると、この盲点が外から見える。
抽出コアへの適用1回で欠陥6クラス＋テスト設計の構造欠陥＋中核前提への反証候補を検出した。

## 方法（再現手順）

1. **要件書を汚染側が起草し、人間が目視ゲート**。渡すのは外形的振る舞い・世界の事実・受け入れ基準・入力データのみ。
   検出アルゴリズム・閾値・ライブラリ名・出力形式・期待値は落とす（**ブリーフ自体が最大の汚染経路**）。
2. **クリーンセッションで独立実装**。CLAUDE.md・memory・会話履歴を持たない環境で
   「要件書を読め＋このフォルダ外は参照するな」だけ渡す。要件書だけのフォルダで新規セッションを起動すれば再現可能。
3. **意味突合**: 両実装の出力を共通モデルへ写像して機械比較。差分は〈欠陥／方針差（裁定未了）／機能差〉に三分する。
4. 留保: クリーンは「文脈の独立」であって「モデルの独立」ではない（学習由来の盲点は共有しうる）。

実験の経緯・所見・成果物所在の一次情報＝`.claude/plans/archive/indep-reimpl-experiment-2026-08-30.md`
（成果物: 要件書と入力=`~/indep-reimpl/`・第二実装=`~/naro-pdf-engine/`・突合報告=`~/indep-reimpl/diff-work/diff-report.md`。
扱いは awaiting-human の裁定待ち＝裁定前に消さない）。

## 実装より持ち帰る2原則（独立再実装なしでも適用可）

1. **オラクルは実装系譜の外に置く**。「自分の出力の写し」だけでなく、**祖先実装の複製も系譜内**
   （当リポジトリの golden は旧 Python 実装の出力複製＝交差オラクルだが、Python→Kotlin は移植系譜で
   欠陥を共有する。S1 半角スペース脱落等は golden が緑のまま存在し続けた）。
   真の期待値（web 原文）は常に実在したのに、系譜の中に居ると使う発想自体が出ない。
2. **固定前提＋実行時全数検証で「黙って壊れない」**。揺れへの自動適応（寸法自動検出）は実在しない揺れへの
   防御である可能性がある。固定前提を置き、逸脱したら警告する方が、静かな誤適応より安全。

## フル形態 vs 軽量版の分岐（横展開の適用条件）

フル形態（クリーンセッション独立再実装＋意味突合）が割に合う条件は**全部盛り**が必要:
決定的変換／系譜の外に真のオラクルが実在／差分が正誤になる（趣味差にならない）／JVM 等で軽く実行可能／数千行級。
UI・意匠は差分が趣味の違いになるので不成立。収穫の核は一回性の構造的知見で、繰り返すと逓減する。

条件が欠けるときの軽量版:
- **公開規範が既に文書で存在する** → 独立再実装は不要、規範と直接突合する（例: 縦書き組版
  ＝`vertical-typeset-external-oracle-gap.md`）。
- **規模が小さい**（〜数百行）→ クリーンセッション儀式は不要、独立サブに仕様文だけ渡して再実装→出力突合
  （例: `tools/measure_*.py`。オラクル無し領域では独立実装同士の一致が唯一の裏取り。
  「69%→再測4.3%」の前科がこの領域にある＝`context-cost-breakdown-2026-08-10.md`）。
- **期待値を人手で起こしている** → 実装非依存の独立カウント手段を揃えるだけで足りる
  （例: scrape fixture の章数照合。カクヨム 593 は grep で独立裏取り可・暁 66 には手段が無い）。
