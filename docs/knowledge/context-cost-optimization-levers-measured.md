# コスト最適化のレバーと、その効きの実測（2026-08-26）

★★★ / 2026-08-26 実測（main 167 セッション / 25,005 ターン / 5,551M トークン）

**1行要約**: `cache_read` が支配的なのは**構造**で、無くせない（各ターンが全長を読み直す）。
動かせるのは「**何ターン × どれだけの長さ**」だけ。総額 ≈ **n·F + (n²/2)·avg_inc** に分解して測ると、
効きは **切る（46pt）＞ ターン数を減らす（20%減で 33pt）＞ 増分を減らす（30%減で 24pt）＞ 固定費（30%減で 6pt）**。

## 分解

```
累積 cache_read ≈ Σ_t ctx(t) = n·F + Σ_t Σ_{i<t} inc(i) ≈ n·F + (n²/2)·avg_inc
```

| 項 | 実測 | 割合 |
|---|---|---|
| 固定費 n·F（常設注入＝システム＋CLAUDE.md＋memory） | 1,125M（F = **45.0k/ターン**） | **20.3%** |
| 可変（累積増分） | 4,426M（avg_inc = **2,629 トークン/ターン**） | **79.7%** |

## 打ち手ごとの効き（この母数での試算）

| 打ち手 | 効き | 当たる項 |
|---|---|---|
| **100 ターンで切る** | **-46pt**（総量 54%） | 2次項を n²/m へ |
| ターン数を 20% 減らす | **-33pt** | n·F と 2次項の両方 |
| 増分を 30% 減らす | -24pt | 2次項のみ |
| 固定費 F を 30% 削る | -6pt | n·F のみ |

**固定費の削減は効きが小さい**（45.0k を 30% 削っても 6pt）。ここに労力を割く前に、切る・減らすが先。

## 委譲の損益分岐 — 1回 ≒ main の 1.4 ターン

委譲 1 回が main に載せるのは **委譲仕様（中央値 2,227 字 ≒ 2,581 トークン）＋ 返却 digest（1,052 字 ≒ 1,219 トークン）
＝ 約 3,800 トークン**。1ターンの増分が 2,629 トークンなので、**委譲 1 回は main 約 1.4 ターン分のコスト**。

したがって:
- **1〜2 ターンで済む調査を委譲しても収支は取れない**（仕様を書く方が高い）。
- **多ターンの調査を 1 回に畳むときだけ得**。畳んだターン数が 2 を超えた分が利益になる。
- 「Read を委譲すれば軽くなる」は量の話としては誤り＝`read-delegation-changes-context-quality-not-size.md`。
  委譲の値打ちは**畳んだターン数**と**中身の質**で測る。

## 効かないと確定した打ち手

- **応答本文を短くする**（4.3%・二重に確定）
- **生成だけを外部モデルへ**（約3%＝ADR 0031 判断材料6）
- **Read 委譲を「量」の削減として期待する**（1ターン増分の1割程度で、委譲仕様と相殺する）
