# LazyColumn: reload の Loading で行を全置換するとスクロール位置が先頭へクランプされる

**症状**: 発見ホームでスクロール後に期間タブ（週間/月間等）を切り替えると位置がトップへ強制リセット
（キャッシュ無し時のみ顕在。2026-07-19 ユーザー報告・全スキン D/C/M/J/P で同型を確認）。

**機序**: reload のたび state が `Loading` を経由し、ランキング行群が status 行1件へ**全置換**される
→ 総コンテンツ高が崩壊→ LazyListState が可視アンカーitemを見失い先頭側へクランプ→ Content 復帰後も戻らない。
タブ切替そのものではなく **「Loading による一時的な全置換」が真因**（キャッシュがあると Loading を挟まないため
再現しない＝再現条件が「キャッシュ無し」になる理由）。

**対処パターン（stale-while-revalidate）**: 直近の `Content` を `lastContent` に控え（`LaunchedEffect(state)`）、
再取得 Loading 中は直近ランキング骨格（同 key）を出し続けてアンカーを保持。VM/データ層は非改変。
Empty/Error は真に畳む。回帰テスト＝「初回 Loading は status 表示」「再取得中は直近保持（全置換しない）」の対。

## 再発（2026-07-29・K のランキング Pager 化）と、stale-while-revalidate の限界

K の「さがす」ランキングを全6期間の横スワイプ Pager 化（`RankingPagerK`／`RankingPageK`）した際、
**新しい経路で同じ機序を踏んだ**。ページャは外側 LazyColumn の 1 item に丸ごと収まるため、ページの高さが
崩れると item ごと縮み、上と同じクランプが起きる。

きっかけは「控えを期間別に分割した」こと。単一の `lastContent` を期間跨ぎで流用すると週間の行が月間ページに
載る誤誘導になるため分割は正しい判断だが、その代償として**一度も開いていない期間＝控えの無い「初訪ページ」**
が生まれ、そこを「読み込んでいます」1行で描いた＝高さが行数ぶん→1行へ崩壊した。

> **限界の一般化**: stale-while-revalidate は「**控えのある再訪**」しか救えない。控えを細かい単位
> （期間別・タブ別・クエリ別…）へ分けるほど初訪の面が増え、その面では原理的に効かない。
> 控えの粒度を細かくする変更は、必ず「控えが無い面をどう描くか」とセットで決めること。

**初訪の対処＝構造スケルトン**: 控えの無い面は status 1行に潰さず、**行数ぶんの構造骨**を描いて高さそのものを
保つ（`ui/discovery/RankingSkeleton.kt`＝案A 構造プレースホルダ。骨の語彙は `BookshelfSkeleton`／
`TransitionSkeletons` の写経・正本モック `docs/design-candidates/transition-skeleton-D.html`）。
骨の行数は取得件数（`DiscoveryQuery.limit`）から引く——ここが実データより少ないと結局高さが縮んで同じ穴に落ちる。
Empty/Error は従来どおり畳む（骨で覆うと「真に0件・失敗」を隠すため。高さ保持より正直さが上位）。

**Pager を持たないスキン（D/C・M・J・P）**: 単一控えを期間跨ぎで流用する形のままなので「初訪ページ」という
概念が無く、2回目以降の期間切替では常に骨格が出る＝この経路の穴は無い。残る同型は「初回ロードなのに
スクロール位置だけ復元されている」場合（process death 復帰など）で、トリガーが違うだけで機序は同じ。

## 何に守られているか（2026-07-29 に入れた2層）

knowledge も回帰テスト6件も**存在した上で**再発した。理由は「既存実装の退行は防げても、新しく書いた
コードが同じ罠を踏むのは防げない」から（K の Pager 化は新規コード＝テストの網の外）。そこで2層にした。

- **L1 不変条件テスト** `DiscoveryHomeInvariantTest`: 登録簿 `DiscoveryHomeRegistry` の**全実装**へ同じ性質を
  かける。①送った状態でキャッシュ無しの期間切替が起きても先頭へクランプしない（内部の LazyListState を
  読まず、末尾リンクと先頭セクションが合成されているかで観測）②Empty を覆い隠さない ③Error を覆い隠さない。
  ②③は①の対処が行き過ぎるのを禁じる対の条件なので必ず一緒に回す。
- **L2 取りこぼし検知メタテスト** `DiscoveryHomeInvariantCoverageTest`: ソースを走査して「罠を踏み得る形」
  （引数で `DiscoveryUiState`/`DiscoveryViewModel` を受ける ui/ の関数）を機械列挙し、登録簿と突合。
  未登録の新実装／実体を失った登録の**両方向**で落ちる。再発コミット 23ace39 に対して実測で赤くなることを
  確認済み（新設 `RankingPagerK`/`RankingPageK`/`RankingRowsK` が未登録・消えた `RankingStaleRows` が残骸）。

新しい発見ホーム実装・新しいスキンを書いたら `DiscoveryHomeRegistry` へ1行足す（足し忘れは L2 が止める）。
走査ロジックは `KotlinSourceScanner`（バグ型非依存）に分けてあるので、別のバグ型へ横展開するときは
「述語」と「登録簿」だけ書けばよい。

**未展開の同型**: 結果一覧(Result)系 4実装は同機序だが「新クエリは先頭表示が正」の解釈もあり要裁定
（L2 では `acknowledgedOutOfScope` に理由付きで登録＝除外の判断も記録に残している。handover 参照）。
