# hallucination — ハルシネーションの台帳登録（記録はフックで完結・検証は事後）

## 即時動作: 何もしない（2026-07-11 運用変更）

`/hallucination` が打たれた直後のターンでは、**分類・調査・検知器実行・台帳編集を一切開始しない**。
フックのキャプチャ完了注入を1行で確認し、直前の作業に戻る（作業中でなければ「記録済み。検証は事後に」とだけ返す）。

**なぜ**: ①証拠確保はフックが決定的に完了済み＝このターンにやることが残っていない
②幻覚直後の Claude の判断を信用しない設計原則（下記）は分類作業自体にも適用される
③その場で分類を始めると直前の作業が脱線する。スナップショットは不変なので検証は事後で劣化しない。

**唯一の例外＝証拠救済**: キャプチャ完了注入が見えない（フック未配線ブランチ・失敗報告あり等）場合のみ、
その場で手動スナップショットを取る（`cp <transcript> ~/.claude/hallucination-archive/`。ライブファイルは
追記で成長するため、これだけは事後に回すと証拠が劣化する）。transcript の特定はキュー行の `live=` or
フック失敗メッセージを正とし、mtime 最新で推測しない。

## 前提: キャプチャは既にフックが済ませている

ユーザーが `/hallucination [メモ]` と打った**瞬間**に、UserPromptSubmit フック
`record_hallucination.py` がモデル推論を介さず機械的に:

1. その時点のセッション JSONL を `~/.claude/hallucination-archive/<session>-<日時>.jsonl` へ**不変スナップショット**
2. 台帳 `docs/reference/hallucination-ground-truth.md` 末尾の「⏳ 未確定キュー」へ1行記載
3. スナップショットパスをコンテキストへ注入（このターンに `[/hallucination 自動キャプチャ完了]` が見えているはず）

**なぜこの分業か**: ハルシネーション直後のセッションでは Claude 自身が信用できない（台帳L＝完了報告の全面捏造の実例）。
証拠確保はハーネスが決定的に行い、Claude は分類・確定のみを担う。

## 事後検証モード（明示依頼時のみ）: 分類→確定→正式登録

ユーザーが「キューを消化して」「台帳に正式登録して」「ハルシネーションを記載して」等と
**事後に明示的に頼んだときだけ**、以下を実行する（/hallucination 直後のターンでは実行しない）。

1. **対象の把握**: 台帳の未確定キューから当該行（今の1件、または溜まっている過去分）を読む。
   ユーザーメモと直前の会話文脈から「どの発話・どの主張が幻覚か」を把握。曖昧なら AskUserQuestion。
2. **静的検知器**: `python3 .claude/hooks/analyze_transcript.py <スナップショット>`。
   **検知器が拾うのは実行捏造系だけ**——0件でも打ち切らない（台帳「追記手順」2）。
3. **一次情報で確定**: スナップショット JSONL を直読し、該当 assistant 発話の〈行番号・uuid・冒頭引用〉を確定。
   行番号は**スナップショット基準**（ライブファイルは追記でずれる）。
   E型（対話文脈の捏造）を疑う場合の agy read-only 意味監査は台帳「追記手順」3 の定型を使う。
   検知器・agy の指摘は主張にすぎない——**必ず直読突合してから**確定。
4. **正式登録**: 台帳へ既存フォーマットのセクションを追加し、キューの当該行を消す:
   - 事象IDは既存最大レターの次。並列レーン衝突防止に
     `grep -h "^## " docs/reference/hallucination-ground-truth.md ~/wt/*/docs/reference/hallucination-ground-truth.md` で全レーン確認してから採番。
   - セクション: `## <ID>. <一行要約>（確度: 高/中/低）`＋場所（**ライブパスとスナップショットパスの両方**）＋`| 行 | uuid |` 表＋`※` note（型分類・暴走 thinking 前兆の有無・検知器の検知/空振り）。
   - 冒頭ヘッダ「確認済み実幻覚セクション: N件（M事象）」と事象一覧説明を更新。
   - 検知器が空振りした型なら `handover.md` の検知器残タスク節へ検知穴を1行追記（重複なら不要）。
5. **締め**: 登録要約（事象ID・型・行/uuid・スナップショット）を提示。コミットは通常フロー（提示→人間承認・`docs:`）。

## 遡及モード

- `/hallucination` 後にユーザーが「過去のセッションも」と言った場合や、キューに古い未確定行が溜まっている場合は、各行の snapshot に対して上の 2〜4 を繰り返す。
- スナップショットが無い過去分は live パス（存在すれば）から今すぐスナップショットを取ってから作業する。
- 候補探しから頼まれたら: 直近 N 日の slug 内 JSONL を `analyze_transcript.py` で走査し、active finding のあるセッションを提示 → ユーザー確認の取れたものだけ登録（検知器の finding だけで確定登録しない）。

## 禁忌

- 台帳以外の場所に幻覚記録を作らない（正本一元化＝CLAUDE.md 規約）。
- キュー行の削除は正式セクションへの昇格と**同一編集**で行う（消すだけは禁止＝証拠ポインタの喪失）。
- ユーザー申告と一次情報が食い違ったら、確度を下げて登録するか差し戻す（記録の捏造をしない）。
