# UIラウンド: 密度圧縮・スワイプ化・気分パターン複数化・Webマーク再意匠（2026-07-24）

**対象ブランチ: `feat/ui-playground`**（コミットは worktree 内セッションから）

## 背景（ユーザー指示 2026-07-24・4点＋構造化1点）

1. Web作品マークが非常にダサい → 再意匠。**今後 UI 追加は必ずモック先行**（memory `feedback-mock-before-any-ui-addition` に固定済み）。
2. 本棚の表示圧縮: 横型（リスト型）の幅・行高を詰めて1画面あたりの作品数を増やす。書籍型は現状1列3冊。
3. 本棚⇄さがす⇄設定を横スワイプでシームレスに移動したい。
4. 「今日の気分」の選択肢セットを複数パターン化し、横スワイプで切替・日替わりで良さげなセットが出る仕組み。
5. 「確定している形」を固定化し、その枠の上で中身だけ入れ替え可能にするコード構造（変えるべき所だけ簡単に変えられる）。

## 接地の結果（Explore 棚卸し 2026-07-24・確認済み事実）

- **Webマークの現況**: `sourceSite`/`sourceUrl`（BookEntity）は **UI 層で未参照**＝取込済みWeb蔵書はPDF蔵書と見分け不能。
  マークが出るのは未取込 browse カード（`ShelfItem.Web`）のみ。K＝書影左上「Web」ピル（`skins/k/BookshelfK.kt:688-700`・
  モック `bookshelf-K.html` と一致）、D＝青磁「なろう・未取込」テキスト、J＝モックの Web 角バッジ未実装（乖離）、
  P/C＝バッジなし。
- **本棚2型**: 切替はスキン別 prefs キー（`BookshelfScreen.kt:278-306`）。グリッド＝D/共通 `Adaptive(124dp)`・
  K `Fixed(3)`・J `Fixed(2)`。リスト＝`ListBookCard`（`BookCard.kt:422`）は書影なし・左4dp色帯・上下 S16 padding・
  行高およそ72–88dp（≒8–10行/画面）。
- **タブ機構**: 恒常ボトムナビ（`KBottomNav`・NavHost 外・全スキン開放済み）＋ルート切替 crossfade
  （`MainActivity.kt:370-410`）。**HorizontalPager は不使用**。タブは独立バックスタックでなく
  `popUpTo+saveState/restoreState` の同格入替。
- **今日の気分**: `MoodPreset` enum 4件固定（SHORT_TRIP/BINGE/DIALOGUE/ILLUSTRATED）→ `toQuery()` で
  `DiscoveryQuery` へ変換。全スキン同一 entries を各意匠でレイアウト（K=`MoodSectionK` 2列）。
- **二層化の現況（ADR 0022）**: 枠＝MainActivity の Column（NavHost＋恒常ボトムナビ）・中身＝exhaustive `when(skin)`
  で画面丸ごと分岐。ユーザー要望5は **この枠をさらに明文化・拡張する話**＝新規機構の発明ではない。

## 確定事項（裁定つき）

### A. Web作品マーク再意匠【装飾＋データ課題】
- 裁定: 意匠課題（Kピルの主張が強すぎる）＋構造課題（取込済みWeb蔵書の識別が**そもそも無い**）の複合。
- 確定: モックで複数候補を作る。候補は「未取込 browse カード」の識別と「取込済みWeb蔵書」の識別（付けるか含め）の
  両方を扱う。骨格から別物の候補を並べる（memory `feedback-build-dont-ask-iterate`）。
- 制約: 初見3秒で意味が取れること・情報過密禁止（memory `feedback-skin-design-judgment-criteria`）。
  実装は K を第一意匠→他スキンへ翻訳（K形伝播と同型）。

### B. 本棚の密度（2026-07-24 ユーザー裁定で更新: 横型は小さく・書籍グリッドは大きく）
- **実機実測（2026-07-24・PGEM10）**: Override density 640（物理480）＝**実効360dp幅**。
  リスト現行＝題字明朝2行＋著者＋状態の縦積みで1行≈190dp＝**約3.5行/画面**。グリッド現行＝3列×2行＝
  **6冊/画面**。初版モックの「現行≒74px行・10行/画面」は机上値で実機と乖離（ユーザー指摘）→ 実機実測を
  基準に逆同期（恒久ルール「実機画面を原点」の適用）。
- 確定（リスト型・圧縮）: 基準=実機3.5行から圧縮。候補A=題字1行化＋メタ同行（≈7-8行）・候補B=さらに縦詰め
  （≈10行）。タップ標的48dp維持（UX05-C）。モックのビューポートは360px幅（実機実効幅と同値）。
- 確定（書籍グリッド・拡大）: ユーザー裁定「一画面6冊は小さすぎる→**一画面4冊に**」＝3列→**2列**へ拡大。
  4列候補は廃案。

### C. タブ横スワイプ【構造】
- 語彙追加の4問審査（UX18-C3）: ①毎セッション級頻度=YES ②既存文法から導出=YES（ボトムナビの空間配列
  〔本棚|さがす|設定〕に沿う moving-text＝標準 Pager 挙動） ③可視の等価経路=YES（ボトムナビ自体）
  ④OS予約語衝突=Pager は端の戻るジェスチャと共存する標準挙動（UX18-E「Pager 第一候補」）。**全問 YES＝追加可**。
- 確定: タブ3画面を `HorizontalPager` 化し、ボトムナビと双方向同期。crossfade はスライドに置換
  （スワイプ追従とタップ切替で運動言語を一致させる）。深い画面（読書・目次等）は従来どおり NavHost 遷移＝
  Pager はタブ層のみ。タブ状態保持（saveState 相当）は Pager のページ保持で担保。
- 注意: 本棚グリッドは縦スクロール＝垂直/水平のジェスチャ分離は Pager 標準で成立。リスト内の水平スワイプ語彙は
  現在空欄（UX18-C1）なので衝突なし。
- モックは静止1枚（スワイプ途中フレーム＝隣タブが覗く状態）で運動言語を確定。操作感の数値はモックで確定させず
  実機後詰め（ADR 0005 §B）。

### D. 気分パターン複数化【構造＋コンテンツ】
- 確定: `MoodPreset` 平板 enum → 「パターン（4件1組）×複数」へ拡張。気分セクションを横スワイプのページャ化
  （ページドット等の可視インジケータ必須＝可視代替義務 UX18-D）。初期表示ページは**日付シードで日替わり**。
- パターン案（モック用・クエリ対応は実装時に DiscoveryQuery の対応可否を確認し、不能なら候補を差し替える。
  近似で誤魔化さない）:
  - P1（現行）: ちょっとそこまで／どっぷり一気読み／会話劇を楽しむ／挿絵のある旅
  - P2（気分転換）: 泣ける・しんみり／スカッと爽快／ほのぼの日常／ハラハラ冒険（ジャンル・キーワード系）
  - P3（読み方で選ぶ）: 完結をまとめて／連載を追いかける／短編を数本／超長編にどっぷり（状態・長さ系）
- Room 変更なし（enum/定数のみ）。日替わりは端末日付から決定的に導出（乱数不使用＝再現可能）。

### F. Webマーク＝D改 採用＋書影輪郭は「線→影」へ【確定・2026-07-24 ユーザー裁定】
- (a)未取込＝**D改（破線フレームのみ・↓なし・紙地一段沈め）採用**。(b)取込済み＝識別なし確定。
- **書影の輪郭**: 現実装は黒っぽい輪郭線（border）だが、モックは影（box-shadow）。ユーザー裁定＝
  「影ではなく線になっている→影に修正」。Compose 実装で全スキンの書影 border を柔らかい影
  （elevation/shadow）へ置換する。ダークテーマでは影が沈みやすい＝視認が保てる影値を実機で詰める
  （モック＝構図の正・実機＝実データ検分の二段検分ルール）。
  ※旧フィードバック（2026-07-23 第1便「書影輪郭線」追加）はこの裁定で上書き。

### E. 枠組みの固定化（スロット化）【構造・ADR 0022 拡張】
- 裁定: 新機構の発明ではなく **ADR 0022 の「枠」を契約として明文化・強化**する話。
- 確定: 〈恒常枠＝ボトムナビ＋タブPager＋（C の実装で導入する）タブスロット〉を固定 API とし、
  タブの中身（本棚/さがす/設定）と気分セクション等の「面」は**スロットに差す Composable** として統一。
  スキン分岐（exhaustive when）はスロット内に限定＝枠には skin 分岐を持ち込まない。
  実装完了時に ADR 0022 へ追記（または新 ADR）。C・D がこの枠の最初の適用例。
