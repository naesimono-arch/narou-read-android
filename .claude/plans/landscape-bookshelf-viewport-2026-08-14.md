# 横向きの本棚で書影カードが1枚も収まらない — 実測と選択肢（裁定待ちの一次情報）

> 2026-07-30 に実機で発見。**構造の裁定が要るので直していない**。
> 裁定そのものは `awaiting-human.md` §3-1 が正本（ここは判断材料の置き場）。
> 2026-08-14 に台帳から退避（裁定材料の詳細まで台帳に置くとサイズ規約を割るため）。

## 実測（OPPO PGEM10・横向き）

| | 値 | 内訳 |
|---|---|---|
| 実効ビューポート | **~133〜141dp** | ボトムナビ 65dp ＋ ヘッダ ~68dp ＋ 状態チップ行 ~46dp ＋ システムバー |
| カード実高（5列） | **~206〜212dp** | セル幅 124.8dp → 書影 3:4 で 166.4dp ＋ キャプション |

＝**構造的に入らない**。さらに末尾までスクロールすると画面の 2/3 が空白になる。

## 調査済みの選択肢（効く順）

- **(a) ヘッダ＋状態チップ行（固定 ~114dp）をグリッドの span item へ移してスクロールで抜けさせる**
  → 実効 ~250dp となりカード1枚＋次行の頭が見える。**意匠改変が最小**で、
  K の「全画面に明示タイトル」とは両立する（スクロールで消えるだけ）。
- **(b) 横向きのみボトムナビを NavigationRail（左端縦置き）へ**
  → 65dp＋nav インセットが縦方向から消える。Material の canonical な compact-height 対応だが、
  **全画面に波及する構造裁定**になる。
- **(c) カード実高を下げる**（列数 5→7 で書影 80dp なら計算上は収まる）
  → ただし裁定「書影の肥大回避」の逆方向へ行き過ぎる。

## 真因ではないが関係するもの

`Insets.ScrollBottomForFab = 96dp` は真因ではない（`contentPadding` はビューポート高を食わない）。
ただし「1枚も入らない画面の末尾に 96dp の空白」は体感を悪くするので、向き応答化は副次的に有効。

## ⚠️ この破綻は golden に写らない

Robolectric の window insets は全て 0 で、`@Config(qualifiers)` にインセット修飾子が存在しないため。
合成インセットを流すことは可能だが、その値は端末ごとの推測値＝**推測を回帰の基準線に焼き込む**ことになるので採っていない。
**横向きの検証は実機が唯一の手段。**
